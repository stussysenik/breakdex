  You're actually thinking like a good programmer - MinimalTrimmerView seems like the logical place! But here's why AddMoveView is the correct target:

  Current View Hierarchy

  MainView (Tabs)
  └── AddMoveView (Workflow Coordinator)
      ├── SelectClip (Video Selection)
      ├── MinimalTrimmerView (Video Trimming)

  Why MinimalTrimmerView Can't Navigate

  1. MinimalTrimmerView's Job (SRP Violation if it navigates):
  // MinimalTrimmerView.swift - Line ~1890
  private func proceedToNaming() {
      // Creates TrimModification data
      await viewModel.updateTrimModification(modification)
      // ⚠️  COMMENT: "Navigation will be handled by the parent view observing the view model changes"
      // ✅ This is CORRECT - it's creating data, not navigation logic
  }

  2. AddMoveView is the Workflow Orchestrator:
  // AddMoveView.swift - Lines 32-94
  var body: some View {
      switch currentStep {  // THIS is the navigation engine
      case .trimming:
          MinimalTrimmerView(viewModel: viewModel)  // Shows trimmer
      case .naming:
          NameMoveView(viewModel: viewModel)       // Shows namer
      }
  }

  The Navigation Pattern Explained

  Child Views (MinimalTrimmerView, NameMoveView):
  - ✅ Create/update data in ViewModel
  - ✅ Emit state changes via @Published properties
  - ❌ NEVER handle navigation (violates SRP)

  Parent Coordinator (AddMoveView):
  - ✅ Observe ViewModel state changes
  - ✅ Handle navigation via switch currentStep
  - ✅ Maintain workflow orchestration

  Why Your Instinct Was Wrong (But Good!)

  You wanted to put navigation in MinimalTrimmerView because:
  Button("Submit") {
      // I want to navigate here!
  }

  But this creates tight coupling - MinimalTrimmerView would need to know:
  - What view comes next?
  - How to transition states?
  - What triggers navigation?

  The Clean Architecture Solution:
  // MinimalTrimmerView - Just emit state
  await viewModel.updateTrimModification(modification)

  // AddMoveView - Observe and navigate  
  .onChange(of: viewModel.currentTrimModification) { _, mod in
      if mod != nil { currentStep = .naming }
  }

  Real-World Analogy

  - MinimalTrimmerView: Doorbell button (just triggers signal)
  - AddMoveView: Home security system (decides what to do when bell rings)

  This follows MVVM separation of concerns - Views emit state, Coordinators handle navigation.
