Short answer: Recreate the AVPlayer when returning to Pre‑Trim (going from a rotated composition back to the plain asset) and force a brief item clear + seek, so the preview visually resets; keep the rotate pipeline unchanged so rotation still propagates to naming. [1][2]

## Root cause
- The Pre‑Trim view instantiates a non‑rotated player, but the player path sometimes reuses an existing AVPlayer and only replaces its item, which can leave a rotated composition frame cached on screen for a moment. [1][2]
- Because the rotated path builds an AVMutableVideoComposition, switching back to a bare asset via replaceCurrentItem doesn’t always flush render buffers immediately, producing the “rotation persists visually” effect. [1][2]

## Minimal fix
- On transitions to Pre‑Trim (rotationQuarterTurns == 0), perform a “hard reset”: pause, clear the current item, cancel prerolls, then create a new AVPlayer with a fresh AVPlayerItem and seek to zero before play. This guarantees a clean visual reset with negligible overhead. [1][2]

## Code changes
- In CustomVideoPlayerView add a small helper to apply items with an optional hard reset, and call it when quarterTurns becomes 0 or when switching off a composition. [2]
```swift
@State private var lastAppliedQuarterTurns = 0

@MainActor
private func apply(_ item: AVPlayerItem, hardReset: Bool) {
  switch playerState {
  case .playing(let existing):
    if hardReset {
      existing.pause()
      existing.replaceCurrentItem(with: nil)
      existing.cancelPendingPrerolls()
      let fresh = AVPlayer(playerItem: item)
      playerState = .playing(player: fresh)
    } else {
      existing.replaceCurrentItem(with: item)
    }
  default:
    playerState = .playing(player: AVPlayer(playerItem: item))
  }
  if case .playing(let p) = playerState {
    p.seek(to: .zero, toleranceBefore: .zero, toleranceAfter: .zero)
    p.play()
  }
}

.onAppear { lastAppliedQuarterTurns = rotationQuarterTurns }

.onChange(of: rotationQuarterTurns) { _, newTurns in
  Task { await rebuildWithRotation(newTurns) }
}

@MainActor
private func rebuildWithRotation(_ turns: Int) async {
  guard let asset else { return }
  do {
    if turns != 0 {
      let r = try await VideoTransformBuilder.build(asset: asset, quarterTurns: turns)
      let item = AVPlayerItem(asset: r.composition)
      item.videoComposition = r.videoComposition
      item.seekingWaitsForVideoCompositionRendering = true
      apply(item, hardReset: false) // composition → composition or asset → composition
    } else {
      let item = AVPlayerItem(asset: asset)
      apply(item, hardReset: true)  // composition → plain asset needs hard reset
    }
    lastAppliedQuarterTurns = turns
  } catch {
    playerState = .error(message: "Failed to process video: \(error.localizedDescription)")
  }
}
```
This keeps the “rotated” path fast (reuse player), but guarantees a clean reset when leaving rotation. [2]

## Hook into back navigation
- When the back button transitions to Pre‑Trim, ensure the view passes rotationQuarterTurns: 0 and triggers setup; the hard‑reset logic above handles the visual flush without changing navigation code. [1][2]
- If Pre‑Trim uses a new CustomVideoPlayerView(asset: asset, rotationQuarterTurns: 0), no further wiring is needed; the helper guarantees a fresh, unrotated preview. [1][2]

## Preserve rotation pipeline
- Keep the rotate button behavior in TrimmerView as is: update rotationQuarterTurns locally, emit onRotate, and mirror into TrimmerViewModel.rotationQuarterTurns so the value flows to NameMoveView state, preserving correct downstream rotation. [1][2]
- NameMoveView should continue to read the stored rotation or use 0 when rotation was baked at export, matching the documented flow, so functionality remains consistent after the back‑navigation fix. [1][2]
