# Agentic Spec-Kit: Modular Emoji Handle Trimmer

## 1. Intent & Context

Deliver a highly precise, tactile video trimmer that uses swappable, emoji-based handles, driven by a high-fidelity UIKit gesture layer.

- **Primary Goal:** Abstract the trimmer's "handle" into a modular component. This component will accept any SwiftUI `View` as its content, defaulting to a randomly selected emoji from a predefined set.
- **Core Logic:** All precision physics (frame-snapping, one-frame gap, no-lag seeking) and the UIKit gesture bridge must be preserved. The change is purely at the visual/compositional layer of the handles.
- **Aesthetic:** Minimalist, dark-themed, and playful. The emoji handles must be crisp, perfectly centered, and feel directly connected to the user's touch.

## 2. The Modular Handle Component (`HandleView`)

This is the new core component.

- **Generic Content:** The `HandleView` will be a generic SwiftUI `View` that accepts content via a `@ViewBuilder`.
  ```swift
  struct HandleView<Content: View>: View {
      let content: Content
      init(@ViewBuilder content: () -> Content) {
          self.content = content()
      }
      // Body will apply modifiers...
  }
  ```
- **Random Emoji Logic:** The parent view (`TrimControlPanelView`) will be responsible for state management. It will select and store the random emojis.
  ```swift
  // In the parent view
  private let handleEmojis = ["👟", "🔥", "🍃", "🌪️", "💃", "🪩"]
  @State private var startHandleEmoji: String
  @State private var endHandleEmoji: String

  // In the parent's .onAppear or init
  self._startHandleEmoji = State(initialValue: handleEmojis.randomElement()!)
  self._endHandleEmoji = State(initialValue: handleEmojis.randomElement()!)

  // Usage in parent's body
  HandleView { Text(startHandleEmoji) }
  HandleView { Text(endHandleEmoji) }
  ```
- **Hit Target & Size:** The `HandleView` will apply the necessary modifiers to its content to ensure a large, reliable touch target, regardless of the emoji's visual size.
  - `.font(.system(size: 24)) // Or whatever size looks best`
  - `.frame(width: 44, height: 44, alignment: .center)`
  - `.contentShape(Rectangle())`

## 3. Integration with UIKit (`UIViewRepresentable`)

The existing `PanGestureRecognizerBridge` (or a new one) will now host the `HandleView` instead of a simple shape.

- **Hosting SwiftUI in UIKit:** The bridge will use a `UIHostingController` to render the SwiftUI `HandleView`. This ensures that even though the gesture is handled by UIKit, the handle's appearance is defined declaratively in SwiftUI.
- **State Communication:** The bridge will continue to communicate drag state (translation, velocity, state) back to the SwiftUI `ViewModel` via a coordinator and bindings. The modularity is preserved because the bridge doesn't care *what* the handle looks like, only that it's a view it can attach a gesture to.

## 4. Tasks & Workflow

### Phase 1: Build the Modular `HandleView`

- **Task:** Create `HandleView.swift`.
- **Implementation:** Define the generic `HandleView` with a `@ViewBuilder` initializer. The body should apply the `.frame(width: 44, height: 44)` and `.contentShape(Rectangle())` modifiers to whatever content is passed in.

### Phase 2: Update the Parent View State

- **Task:** Modify `TrimControlPanelView` (or its `ViewModel`).
- **Implementation:** Add the `handleEmojis` array and the `@State` properties for `startHandleEmoji` and `endHandleEmoji`. Initialize them with a random element in the view's `init` or `.onAppear`.

### Phase 3: Integrate with the UIKit Bridge

- **Task:** Adapt the `UIViewRepresentable` bridge.
- **Implementation:** Modify the bridge to accept a `@ViewBuilder` for its content. Inside `makeUIView` or `updateUIView`, create a `UIHostingController` with the `HandleView` as its `rootView`. Add the pan gesture recognizer to this hosting controller's view.

### Phase 4: Assemble and Test

- **Task:** Replace the old handle implementation in `TrimControlPanelView` with the new modular system.
- **Implementation:**
  - Instantiate two handle components, passing in the random emoji `Text` views.
  - Ensure the gesture bridge correctly reports drag events for each handle independently.
  - Verify that the handle's visual center aligns perfectly with the timeline track's start and end points. The active (blue) track must be drawn from emoji-center to emoji-center.

## 5. Acceptance Criteria

- **AC1: Modularity:** The handle's appearance can be changed by passing a different SwiftUI `View` (e.g., `Image(systemName: "circle.fill")`) into the `HandleView` without breaking any gesture logic.
- **AC2: Emoji Rendering:** The selected emojis (👟, 🔥, etc.) render crisply and are centered correctly on the timeline boundaries.
- **AC3: Precision & Feel:** The drag interaction retains all the precision of the pure UIKit approach: no lag, frame-snapping, velocity scaling, and a guaranteed one-frame gap.
- **AC4: Hit Testing:** Drags can only be initiated on the handles' 44x44pt touch areas. The timeline track remains non-interactive.
- **AC5: Accessibility:** Each emoji handle has a clear, descriptive `accessibilityLabel` that is updated with its current time value.

This workflow provides a robust, professional, and extensible solution. It correctly leverages the strengths of both SwiftUI (for flexible, declarative UI composition) and UIKit (for high-fidelity, imperative gesture control), resulting in a final product that is both precise and uniquely designed.
