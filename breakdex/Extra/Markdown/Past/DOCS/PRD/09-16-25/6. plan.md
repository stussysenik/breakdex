### **Engineering Spec: Resolve `NSInvalidArgumentException` Crash in `PreTrimContainerView` Initialization**

### **1. Objective**

Refactor the initialization of `PreTrimContainerView` to use a valid, empty `AVPlayer` as a placeholder. This will prevent the fatal crash caused by the illegal instantiation of the abstract `AVAsset` class, allowing the view to appear and begin its intended video loading process.

### **2. Background**

The previous fix correctly addressed the state transition logic, but revealed a fatal initialization error. The `PreTrimContainerView.swift` file attempts to create a placeholder `AVPlayer` by passing it an `AVAsset()` instance. This is an illegal operation, as `AVAsset` is an abstract class that cannot be instantiated directly, resulting in an `NSInvalidArgumentException` that terminates the app.

This spec details the minimal, correct change to create a safe placeholder that satisfies the view's initialization requirements without causing a crash.

### **3. Required Code Changes**

**File to Modify**: `PreTrimContainerView.swift`

**Precise Instructions**:

1.  Navigate to the `init` method within the `PreTrimContainerView` struct.

2.  Locate the block where `self.playerViewModel` is initialized.

3.  Identify the line where the `AVPlayer` is created. It currently reads:

    ```swift
    // IDENTIFY THIS LINE
    player: AVPlayer(playerItem: AVPlayerItem(asset: AVAsset())), // Temporary asset, will be replaced during loading
    ```

4.  **Replace** the faulty `AVPlayer` instantiation with a call to the empty `AVPlayer()` initializer, which creates a valid placeholder object.

    ```swift
    // REPLACE WITH THIS LINE
    player: AVPlayer(), // Corrected: Use a valid, empty player as a placeholder
    ```

The final, corrected initialization block should look like this:

```swift
// The corrected code block
self.playerViewModel = UnifiedVideoPlayerViewModel(
    player: AVPlayer(), // Corrected: Use a valid, empty player as a placeholder
    mode: .preview,
    appContainer: appContainer
)
```

### **4. Reasoning**

Instantiating a player with `AVPlayer()` creates a valid, non-nil object that satisfies the `UnifiedVideoPlayerViewModel` initializer without requiring an `AVPlayerItem` or an `AVAsset`. This empty player serves as a safe, temporary placeholder. The view's existing logic in the `.onAppear` lifecycle event, which calls `startProgressiveLoading()`, will then correctly load the real video asset and configure this player instance with a valid `AVPlayerItem`. This change adheres to the KISS principle outlined in the project documentation.

### **5. Verification Criteria**

To confirm the fix is successful, the following conditions must be met:

1.  ✅ After selecting a video in the "Add Move" flow, the app must transition to the next screen **without crashing**.
2.  ✅ The `PreTrimContainerView` should initially display its `LoadingOverlayView`.
3.  ✅ After the video loading completes, the loading overlay must disappear, and the `PreTrimView` content (with the video player and action buttons) must become visible and fully functional.
4.  ✅ The console log must be completely free of the `NSInvalidArgumentException` related to `AVAsset`.
