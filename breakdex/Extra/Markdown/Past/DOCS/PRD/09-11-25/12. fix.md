## Solution for Move Model videoURL Property Issue

### Problem Analysis
The error "Value of type 'Move' has no member 'videoURL'" occurs because:
1. The `Move` Core Data model has a `videoReference` attribute (binary type) that stores the video URL as UTF-8 encoded data
2. The `VideoAssetLoader.loadFromMove(move:)` method tries to access `move.videoURL` which doesn't exist as a direct property
3. Other parts of the codebase use helper functions like `videoURL(for move: Move)` to convert the binary data to a URL

### Solution Implementation

#### 1. Update Move+CoreDataClass.swift
The `Move` class should be extended with a computed `videoURL` property that handles the conversion between the binary `videoReference` and a URL object:

```swift
@objc(Move)
public class Move: NSManagedObject, Identifiable {
    public var id: NSManagedObjectID { objectID }

    @NSManaged public var rotationQuarterTurns: Int16
    @NSManaged public var videoReference: Data?
    @NSManaged public var photosIdentifier: String?
    
    // Computed property to get the video URL from videoReference
    public var videoURL: URL? {
        get {
            guard let videoData = videoReference,
                  let path = String(data: videoData, encoding: .utf8),
                  !path.isEmpty else {
                return nil
            }
            return URL(fileURLWithPath: path)
        }
        set {
            if let url = newValue {
                videoReference = Data(url.path.utf8)
            } else {
                videoReference = nil
            }
        }
    }
    
    // Helper method to check if the move has a video
    public var hasVideo: Bool {
        return videoURL != nil
    }
    
    // Helper method to check if the video file exists
    public var videoFileExists: Bool {
        guard let url = videoURL else { return false }
        return FileManager.default.fileExists(atPath: url.path)
    }
}
```

#### 2. Update VideoAssetLoader.swift
The `loadFromMove` method should be enhanced to provide better error handling and logging:

```swift
private func loadFromMove(move: Move) async throws -> AVAsset {
    // Update last accessed date
    move.updateVideoLastAccessedDate()
    
    // Log the operation
    VideoLogger.log("Loading video from move", 
                   category: "ASSET_LOADING", 
                   correlationID: correlationID,
                   metadata: [
                       "moveID": move.id.uriRepresentation().absoluteString,
                       "hasVideo": move.hasVideo
                   ])
    
    // Check if the move has a video URL
    guard let videoURL = move.videoURL else {
        let error = VideoAssetLoaderError.assetNotFound
        VideoLogger.error("Move does not have a video URL", 
                         error: error, 
                         category: "ASSET_LOADING", 
                         correlationID: correlationID)
        throw error
    }
    
    // Check if the file exists at the URL
    guard FileManager.default.fileExists(atPath: videoURL.path) else {
        let error = VideoAssetLoaderError.assetNotFound
        VideoLogger.error("Video file does not exist at URL: \(videoURL.path)", 
                         error: error, 
                         category: "ASSET_LOADING", 
                         correlationID: correlationID)
        throw error
    }
    
    return AVURLAsset(url: videoURL)
}
```

### Benefits of This Solution

1. **Backward Compatibility**: The solution maintains compatibility with existing code that uses the `videoReference` attribute directly.

2. **Cleaner API**: The computed `videoURL` property provides a cleaner, more intuitive API for accessing the video URL.

3. **Type Safety**: The solution provides type safety by converting between binary data and URL objects in a controlled manner.

4. **Error Handling**: The enhanced error handling provides clearer error messages and better logging for debugging.

5. **Consistency**: The solution makes the API consistent across the codebase, eliminating the need for helper functions in multiple places.
