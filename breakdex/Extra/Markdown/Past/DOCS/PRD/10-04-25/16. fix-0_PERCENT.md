### **1. Overview (The "What" and "Why")**

#### **1.1. Goal** 🎯

This specification outlines the final fix for the loading UI being visually frozen at 0% with an elapsed time of "00:00". The primary goal is to **correctly activate the timers that drive the loading UI's animation and elapsed time display**, ensuring the interface provides immediate, real-time feedback to the user, reflecting the successful backend operations now confirmed by the logs.

#### **1.2. Persona & User Journey** 🏃

  * **Persona:** "The Athlete" expects a tool that is not only fast but also visibly responsive. A loading screen that appears but shows no activity erodes trust and suggests the app has hung.

  * **Problematic Journey:**

    1.  The user selects a video.
    2.  The loading overlay appears correctly.
    3.  The backend loading process starts and runs flawlessly, confirmed by logs.
    4.  However, the on-screen progress bar and elapsed time clock remain frozen at their initial "0%" and "00:00" values because their driving timer was never started.

  * **Ideal Journey:**

    1.  The user selects a video.
    2.  The loading overlay appears.
    3.  The elapsed time clock immediately begins counting, and the progress bar animates smoothly, providing confident feedback that the app is working.

#### **1.3. Desired Outcomes** ✨

  * **Real-Time UI Feedback:** The progress bar and elapsed time must start updating immediately upon entering the loading state.
  * **Elimination of the UI Stall:** The UI must no longer be frozen as depicted in the provided screenshot.
  * **Architectural Correctness:** The loading lifecycle must be correctly implemented, ensuring all necessary services, specifically the `TimerManagementService`, are started at the appropriate time.

#### **1.4. Non-Goals** ❌

  * **Changes to Progress Calculation:** The logic within `UnifiedProgressEngine` that calculates target progress is correct and will not be modified.
  * **Changes to State Transition Logic:** The state machine's completion logic is correct and will not be modified.

### **2. Functional Requirements (The "What")**

#### **2.1. Timer Activation on Load Start**

Upon entering the `.loadingVideo` state, the system **must** initiate the master load timer via `TimerManagementService`. This timer is the authoritative source for driving all time-based UI updates during the loading phase.

#### **2.2. Animated Progress Activation**

The visual progress bar **must** begin its smooth animation from 0% towards its target value. This is a direct consequence of an active run loop, which is driven by the master load timer.
