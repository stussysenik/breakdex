An analysis of the provided logs and source code reveals a critical race condition in the "Change Video" workflow. The issue stems from the `didSelectVideo` function initiating a destructive state reset *within the same asynchronous task* responsible for loading the new video. This concurrent teardown and setup of UI and state-related components leads to the loading task being terminated prematurely, causing the UI to stall indefinitely in the "Initializing" state.

The core problem is a non-commutative diagram of operations: the task that triggers a UI teardown (`trimming` state -\> `ready` state) is itself cancelled by that very teardown.

This implementation plan resolves the issue by enforcing a strict, sequential order of operations: **Reset First, Then Select.**

-----

## ✅ Implementation Plan Checklist

1.  **Decouple State Reset from Video Selection:** Modify the "Change Video" button's action in `FeatureRichTrimmerView` to first call the atomic reset function (`prepareForNewVideoSelection`) and *then* present the `PhotosPicker`. This ensures the application is in a clean, `.ready` state before the user even selects a new video.
2.  **Simplify `didSelectVideo`:** Remove the call to `resetForNewVideoSelection` from within `didSelectVideo`. This function will now be responsible only for the loading sequence, starting from a guaranteed clean state.
3.  **Verify Robustness of the Fallback Loading Path:** Ensure the `loadVideoViaDataTransfer` fallback in `VideoLoadingServiceResilient` is correctly invoked when a `PhotosPickerItem` lacks a local identifier, as observed in the logs. This path is critical for handling items not fully synced from iCloud.
4.  **Confirm File Size Display Integration:** The logic to fetch and display the video file size already exists. This plan ensures it is correctly integrated into the simplified, more robust loading sequence to meet user requirements for precise feedback.

## 1\. Root Cause Analysis (Categorical Model)

The failure occurs because the composition of morphisms (function calls) is not sequential and creates a side effect that terminates the operation.

  * **Objects:**

      * `A`: State `.trimming` (with active `TrimmerViewModel` and `PlayerViewModel`).
      * `B`: State `.ready` (clean state, ViewModels torn down).
      * `C`: State `.loadingVideo` (loading overlay visible).
      * `D`: A `PhotosPickerItem` selected by the user.
      * `E`: A `VideoLoadingResult`.

  * **Morphisms (The Flawed Path):**

    1.  `select(D)` -\> calls `didSelectVideo(D)`.
    2.  `didSelectVideo(D)` -\> creates `Task T1`.
    3.  `Task T1` -\> calls `prepareForNewVideoSelection()`.
    4.  `prepareForNewVideoSelection()` -\> transitions state `A` to `B`. This morphism has a side effect: it tears down the UI (`FeatureRichTrimmerView`) that initiated the action.
    5.  `Task T1` -\> calls `beginLoadingState()`, transitioning state `B` to `C`.
    6.  **FAILURE:** The UI teardown from step 4 causes SwiftUI to cancel `Task T1` before it can execute the final, critical morphism: `loadVideo(D)` -\> `E`.

  * **The Non-Commutative Diagram:** The path that includes tearing down the originating UI context while the initiating task is still running is flawed. The task's lifecycle is incorrectly tied to the view that is being destroyed.

-----

## 2\. Solution: Enforce Sequential, Decoupled Operations

The solution is to restructure the workflow into two distinct, atomic, and sequential phases, ensuring the state is fully reset *before* the selection and loading process begins.

// AFTER: Refactored implementation
@MainActor
public func didSelectVideo(_ item: PhotosPickerItem) {
    let identifier = item.itemIdentifier ?? "unknown"
    let correlationId = UUID().uuidString.prefix(8)
    let sessionStartTime = Date()

    logger.info("🎯 UNIFIED_LOADING_ENTRY: 🚀 VIDEO_SELECTION_START [\(correlationId)] - Processing video from clean state: \(identifier)")

    // 1. Cancel any previous loading task.
    videoLoadingTask?.cancel()
    logger.info("🎯 UNIFIED_LOADING_ENTRY: 🛑 Previous loading task cancelled to ensure clean start [\(correlationId)]")

    // 2. Create a new task for the loading operation.
    // The state is presumed to be .ready due to the new UI workflow.
    videoLoadingTask = Task { [weak self] in
        guard let self = self else {
            logger.warning("🎯 UNIFIED_LOADING_ENTRY: ⚠️ Self reference lost during task execution [\(correlationId)]")
            return
        }

        do {
            // STEP 1: Immediately and synchronously transition to .loadingVideo.
            // This is safe because the "Change Video" button already forced a reset to .ready.
            logger.info("🎯 UNIFIED_LOADING_ENTRY: 🔄 STEP 1 - Atomic state transition to .loadingVideo [\(correlationId)]")
            guard self.flowState.isReady else {
                logger.critical("🚨 CRITICAL STATE VIOLATION: didSelectVideo called from non-ready state: \(String(describing: self.flowState)). This indicates a failure in the reset-before-selection workflow.")
                await self.setError(message: "Cannot start loading from an invalid state.")
                return
            }
            
            let transitionSuccess = self.beginLoadingState(from: self.flowState, videoIdentifier: identifier, correlationId: String(correlationId))
            guard transitionSuccess else {
                logger.error("❌ UNIFIED_LOADING_ENTRY: ❌ STEP 1 failed - State transition rejected [\(correlationId)]")
                await self.setError(message: "Failed to initialize loading state.")
                return
            }
            logger.info("🎯 UNIFIED_LOADING_ENTRY: ✅ STEP 1 complete - Atomic state transition to .loadingVideo successful [\(correlationId)]")
            try Task.checkCancellation()

            // STEP 2: Perform all asynchronous loading work now that state is correctly set.
            logger.info("🎯 UNIFIED_LOADING_ENTRY: 🔄 STEP 2 - Starting async operations [\(correlationId)]")

            // Fetch file size for the loading UI.
            await self.fetchAndDisplayFileSize(from: item, correlationId: String(correlationId))
            try Task.checkCancellation()

            // Perform the actual video load.
            await self.loadVideoWithCancellation(from: item, correlationId: String(correlationId))

            let sessionDuration = Date().timeIntervalSince(sessionStartTime)
            logger.info("🎯 UNIFIED_LOADING_ENTRY: 🎉 SESSION_COMPLETE - Total duration: \(String(format: "%.3f", sessionDuration))s [\(correlationId)]")

        } catch is CancellationError {
            logger.info("🛑 UNIFIED_LOADING_ENTRY: 🛑 Video loading task was cancelled [\(correlationId)]")
            await self.performLoadingCancellationCleanup(correlationId: String(correlationId))
        } catch {
            logger.error("❌ UNIFIED_LOADING_ENTRY: ❌ Unexpected error during video selection: \(error.localizedDescription) [\(correlationId)]")
            await self.setError(message: "A problem occurred while selecting the video.", underlying: error.localizedDescription)
        }
    }
}
