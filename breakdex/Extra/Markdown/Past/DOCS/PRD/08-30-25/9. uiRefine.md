**Subject: Engineering Directives for Video Trimmer UI Refinement (iOS 18)**

Please implement the following updates to the video trimmer UI. The goal is a cleaner, more intuitive, and highly polished user experience that aligns with our app's design philosophy and Apple's HIG.

### 1. Implement a De-cluttered, Proportional Layout
The current UI is cluttered. We will adopt a cleaner layout that prioritizes the user's core task: trimming.

*   **Adopt a 40/60 Vertical Split:** The top 40% of the screen will be the `AVPlayer` preview. The bottom 60% will be a dedicated control panel.
*   **Remove Redundant Elements:** Delete the static, centered "Preview" image box and all associated timestamps and labels. The main video player and the new "magnifying loupe" (see below) will provide all necessary visual feedback.

### 2. Introduce a Precision "Magnifying Loupe"
To give users frame-accurate control, we will replace the static preview with a dynamic, interactive loupe.

*   **Contextual Appearance:** A circular "magnifying loupe" will appear directly above the timeline handle *only* when the user is actively dragging it.
*   **Live Preview:** The loupe will display a live, frame-accurate video preview that updates in real-time with the drag gesture.
*   **Haptic Feedback:** Trigger a light haptic tap when the loupe appears and disappears to make the interaction feel more tangible and responsive.

### 3. Eradicate UI Jitter with Isolated State Management
The flicker on handle release must be eliminated. This is a top priority for ensuring a smooth, professional feel.

*   **Isolate Drag States:** Do not use a single, global `isDragging` boolean. Implement two separate `@State` variables (e.g., `isDraggingStartHandle`, `isDraggingEndHandle`) to manage the state of each handle independently.
*   **Two Independent Loupes:** The UI should contain two `MagnifyingLoupeView` instances, each with its visibility tied to its respective drag state variable. This prevents the entire control panel from re-rendering when a single handle is released.
*   **Remove Redundant Seeks:** The final `player.seek()` call in the `.onEnded` block of the drag gesture is redundant and causes the jitter. Remove it.

### 4. Refine the Export Progress State
The current progress bar feels disconnected. We will implement a clean, modal progress state that aligns with Apple's design principles.

*   **Implement a Modal Overlay:** Upon tapping "Create Clip," fade out the entire trimming control panel and present a new, dedicated progress view on a semi-transparent modal overlay.
*   **Use a Circular Progress Indicator:** Display a circular `ProgressView` in the center of the screen. Show the percentage text inside the circle and a "Creating Clip..." label below it.
*   **Provide Clear Success Feedback:** When the export is complete, animate the progress ring transforming into a checkmark. After a brief delay, automatically dismiss the entire trimming screen.

### 5. Ensure Visual Cohesion and Polish
Finally, ensure all elements align with our app's branding and feel native to iOS 18.

*   **Fonts & Colors:** All text should use our app's custom font. The neon blue accent color must be applied consistently to all interactive elements: the timeline handles, loupe borders, and start/end timestamps.
*   **Button Styles:** Update the "Cancel" and "Create Clip" buttons to have less vertical padding, giving them a sleeker, more modern appearance.
*   **Animations:** Use modern SwiftUI techniques (`.animation(.spring(), value: ...)`). Apply animations locally to the loupes, not globally, to maintain performance.
