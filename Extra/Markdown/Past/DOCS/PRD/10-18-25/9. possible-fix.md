# Design: Fix ViewModel State Collision

## Context

The root cause of the 94% UI hang has been misdiagnosed. It is not a race condition *between* the Service and the ViewModel.

It is a UI update collision *within* the `AddMoveViewModel` itself.

The log `onChange(of: LoadingState) action tried to update multiple times per frame` is the key. This log originates from a View observing the `loadingState` property.

In `AddMoveViewModel.swift`, the `coordinatePlayerInitialization` function sets this property three times in a row without a frame break:

1.  `loadingState = .loading(progress: 0.95, ...)`
2.  `loadingState = .loading(progress: 0.99, ...)`
3.  `loadingState = .fullyReady(asset)`

This is the "multiple updates per frame" collision.

## Decision: Apply `await Task.yield()` to `AddMoveViewModel`

The `await Task.yield()` solution was correct in principle but was being applied to the wrong file.

We will now apply it to `AddMoveViewModel.swift`'s `coordinatePlayerInitialization` function.

```swift
// Proposed Implementation in AddMoveViewModel.swift

@MainActor
private func coordinatePlayerInitialization(asset: AVAsset) async {
    // ...
    // let playerReady = await videoPlayer.loadVideo(asset)
    // ...

    if playerReady {
        Logger.loadingState.info("📊 Service→ViewModel: 95% - Preparing for playback")
        loadingState = .loading(progress: 0.95, stage: .preparingPlayback, message: "Preparing for playback...")

        // THE FIX: Wait for the next UI frame
        await Task.yield()

        Logger.loadingState.info("📊 Service→ViewModel: 99% - Finalizing")
        loadingState = .loading(progress: 0.99, stage: .finalizing, message: "Finalizing...")

        // THE FIX: Wait for the next UI frame
        await Task.yield()

        Logger.loadingState.info("📊 Service→ViewModel: 100% - Fully ready")
        let previousState = loadingState
        let newState = LoadingState.fullyReady(asset)

        if newState.validateMonotonicTransition(from: previousState) {
            loadingState = newState
            Logger.loadingState.info("✅ AddMoveViewModel: UI Observation: Monotonic transition to fullyReady successful")
        }
        
    } else {
        // ... error handling ...
    }
}
````

## Why This Works

1.  **Directly Fixes the Warning**: This change directly addresses the "multiple updates per frame" on the `loadingState` property.
2.  **Guarantees Rendering**: Each `await Task.yield()` cedes control to the `MainActor` scheduler, allowing SwiftUI to render the 95% state, then the 99% state, and finally the 100% state.
3.  **Restores Correct Architecture**: The `SharedVideoPlayer`'s "fire-and-forget" `Task` for its *internal* `isReady` property is the correct pattern *for that service*. This change correctly places the UI-facing state separation logic in the ViewModel, where it belongs.
