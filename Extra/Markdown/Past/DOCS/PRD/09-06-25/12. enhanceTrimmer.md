## Specify

- Intent: Deliver a two‑handle trimmer that feels physically tethered to the finger, achieves frame‑exact boundaries on every drag, and never “falls behind” due to media subsystem latency. [1][2]
- Non‑negotiables: No playhead or thumbnails, no gray action bar, no implicit animations on properties updated by drag, and a guaranteed one‑frame gap so handles never touch. [3][4]

## First‑principles architecture

- Decouple input, quantization, preview, and export: the handle position follows the finger at high‑fidelity; a quantizer maps position→time→frame; a seek scheduler updates preview asynchronously; export consumes the snapped range. [1][2]
- The UI always renders from the input model immediately, while the preview trails via coalesced, single‑flight seeks, ensuring dots never wait on I/O. [2][5]

## Interaction model

- Drag both handles horizontally; slower or vertical‑offset drags increase precision continuously within the same gesture, eliminating mode switches. [6][7]
- Live preview updates are scheduled but never block handle motion; haptics tick on each frame detent and tap on grab/release. [2][8]
- Start initializes at 0, End at duration, and the minimum selectable span is exactly one frame at the asset’s time base. [9][10]

## Functional requirements

- FR1 High‑fidelity tracking: acquire coalesced touches via a pan‑recognizer bridge or equivalent so handle X updates at display cadence with predicted samples when available. [1][13]
- FR2 Deterministic mapping: position→time uses $$t = \frac{x}{W}\cdot D$$ with double precision, then quantizes to the nearest frame time using CMTime at an asset‑appropriate timescale. [9][10]
- FR3 Frame quantization: choose timescale 600 or the asset’s nominal frame resolution; snap each handle to the nearest frame boundary by rounding to the closest $$\frac{1}{\text{fps}}$$. [9][10]
- FR4 One‑frame gap: enforce $$t_{end} \ge t_{start} + \Delta_{frame}$$ and $$t_{start} \le t_{end} - \Delta_{frame}$$ at all times to prevent overlap. [9][10]
- FR5 Seek scheduler: maintain a single in‑flight seek; store latestTargetTime and issue the next seek only in the prior completion, using tolerance rules below. [2][5]
- FR6 Seek tolerances: if the item can step, use zero/zero tolerance; if it can fast‑forward, use zero/+$$\infty$$; otherwise +$$\infty$$/+$$\infty$$ for fastest approach. [5]
- FR7 Preview fallback: when seek thrash is observed, use AVPlayerItem.stepByCount for frame stepping or AVAssetImageGenerator with tight requestedTimeTolerance for near‑instant frame imagery. [5][14]
- FR8 No implicit animations: drag‑mutated values never use implicit/global animations; only transient label opacity may animate to avoid invalid animatable samples and lag. [3][15]
- FR9 Precision scaling: apply velocity‑ and vertical‑distance‑based sensitivity so flicks traverse quickly, while slow/offset drags resolve to frame‑by‑frame detents. [6][7]
- FR10 Haptics: emit one light tick per snapped frame index change, with a soft impact on begin/end, and debounce to exactly once per detent. [8]

## Non‑functional requirements

- Latency: handle position visually tracks finger with no perceptible lag on modern devices; preview may trail but must feel responsive under the scheduler. [1][2]
- Stability: zero “Invalid sample AnimatablePair…” warnings under rapid reversals and pinch/drag interplay by removing conflicting implicit animations. [3][15]
- Accessibility: ≥44 pt targets, VoiceOver labels “Start at t=…”, “End at t=…”, and contrast that meets platform guidance in light/dark. [4]

## Algorithms and rules

- Position→time: compute raw time $$t_r$$, then snapped time $$t_s = \text{round}(t_r \cdot \text{timescale})/\text{timescale}$$, where timescale is ≥600 or derived from fps. [9][10]
- Detents: index $$k = \text{round}(t_r/\Delta_{frame})$$; snapped $$t_s = k \cdot \Delta_{frame}$$; trigger haptic when $$k$$ changes. [9][8]
- Scheduler: if isSeeking is false, issue seek to latestTargetTime and set isSeeking true; in completion, set isSeeking false and re‑issue if latestTargetTime advanced meanwhile. [2][5]
- Fallback: if average seek completion exceeds threshold N ms during drag, switch preview to stepByCount or image generator until drag ends, then restore player. [5][14]

## Contracts

- Inputs: asset reference, duration $$D$$, nominal fps or preferredTimescale, initial start/end, flags for detent haptics and vertical‑precision scrubbing. [9][16]
- Outputs: startTime and endTime as snapped CMTime values, plus events onBeginDrag/onChange/onEndDrag/onConfirm and onSeekStarted/onSeekCompleted. [10][2]

## Edge cases

- VFR content: derive frame duration from the asset’s time base and snap using that duration rather than assuming CFR. [9][10]
- Extremely short clips: enforce selectable span ≥ one frame, and clamp both handles to [0, D] while preserving the gap. [9][10]
- Multi‑touch/interrupts: detect gesture cancellation or interruption and reset transient state without issuing stale seeks. [17][15]

## Risks and mitigations

- Seek thrash on older devices: rely on queued seeks with zero/zero tolerance for step‑capable items and switch to stepByCount when latency spikes. [5][2]
- Precision drift with doubles: keep CMTime as the source of truth and only derive doubles for layout math, re‑creating CMTime per snap. [9][10]
- Gesture interruptions: handle cancellations explicitly and clear the scheduler’s pending target to prevent chasing stale times. [17][2]
