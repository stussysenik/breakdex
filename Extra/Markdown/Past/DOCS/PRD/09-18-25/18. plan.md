You're seeing a black screen in the Pre-Trim View because the video player is being created before its content (`AVPlayerItem`) is fully loaded and ready for playback. This is a classic race condition.

-----

### The Root Cause: An Unreliable Wait

The logs confirm this diagnosis. You can see the app trying to play the video, but the item's status is `0` (unknown), which results in a black screen.

  - **Log Evidence:**
      - `🎬 VIEWMODEL: ⚠️ Player item not ready (status: 0) - this may cause black screen`
      - `⚠️ 🎬 UNIFIED_VIDEO_PLAYER_VIEWMODEL (preview): startPlayback() called, but item is not ready (status: 0). Waiting for readiness.`

The problem is in **`AddMoveViewModel.swift`**, which uses `Task.sleep` to "wait" for the `AVPlayerItem` to become ready. A fixed-time delay is not a reliable way to handle an asynchronous operation of unknown duration.

-----

### The Fix: Asynchronously Load the Player Item

The solution is to replace the unreliable `Task.sleep` with a modern `async/await` call that deterministically waits for the `AVPlayerItem`'s status to be resolved.

#### **File to Modify: `AddMoveViewModel.swift`**

Replace the entire `// --- Completion ---` section at the end of the `loadVideo(from:)` function with the corrected code below.

**Before (Problematic Code):**

```swift
// --- Completion ---
guard let asset = finalAsset else {
    // ... error handling
}

// ... Unreliable asset loading checks and sleeps ...
        
// 1. Create the player item from the fully loaded asset
let playerItem = AVPlayerItem(asset: asset)
        
// 2. Wait for player item to become ready
try await Task.sleep(nanoseconds: 200_000_000) // Unreliable wait

if playerItem.status != .readyToPlay {
    logger.warning("...")
}
        
// 3. Create the player
let player = AVPlayer(playerItem: playerItem)

// ... create playerViewModel and set state ...
```

**After (Corrected Code):**

```swift
// --- Completion ---
guard let asset = finalAsset else {
    throw NSError(domain: "AddMoveViewModel", code: -3, userInfo: [NSLocalizedDescriptionKey: "Failed to load video asset"])
}
        
// 1. Create the player item from the loaded asset
let playerItem = AVPlayerItem(asset: asset)

// 2. Asynchronously and reliably wait for the item's status to be ready. THIS IS THE FIX.
try await playerItem.load(.status)
        
// 3. Guard against loading failures
guard playerItem.status == .readyToPlay else {
    logger.error("🎬 VIEWMODEL: 🚨 PlayerItem failed to become ready. Status: \(playerItem.status.rawValue), Error: \(String(describing: playerItem.error))")
    throw playerItem.error ?? NSError(domain: "AddMoveViewModel", code: -4, userInfo: [NSLocalizedDescriptionKey: "AVPlayerItem failed to load."])
}
        
// 4. Create the player with a GUARANTEED ready-to-play item
let player = AVPlayer(playerItem: playerItem)
        
// 5. Create the UnifiedVideoPlayerViewModel
let playerViewModel = UnifiedVideoPlayerViewModel(
    player: player,
    mode: .preview,
    appContainer: AppContainer.shared
)
        
// 6. Get rotation and transition to the previewing state
let rotation = await asset.rotation()
logger.info("🎬 VIEWMODEL: ✅ Video loaded and player item is ready. Transitioning to previewing.")
        
state = .previewing(
    playerViewModel: playerViewModel,
    asset: asset,
    photosIdentifier: photosIdentifier,
    rotationQuarterTurns: rotation
)
```

-----

### Why This Works

This fix replaces a fragile, time-based guess with a direct command to the `AVFoundation` framework: "Pause execution here and do not continue until you have confirmed this video item is either ready to play or has failed."

This completely eliminates the race condition, ensuring that the `CustomVideoPlayerView` always receives a player that is ready to display video content, which resolves the black screen issue. ✅
