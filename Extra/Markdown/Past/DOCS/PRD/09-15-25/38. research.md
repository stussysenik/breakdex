When a video lives in iCloud, Photos must download the data before playback, and PHVideoRequestOptions controls that fetch.  
Enable network access in PHVideoRequestOptions so the system can retrieve the original asset rather than failing or stalling on a placeholder.  
Use the progressHandler in PHVideoRequestOptions to receive a 0–1 progress fraction during the iCloud download and drive a visible progress bar.  
Request the underlying AVAsset with PHImageManager.requestAVAsset(forVideo:options:resultHandler:) because this path surfaces progress reliably and yields an asset ready for AVFoundation.  
Keep work that touches the network or disk off the main thread, and only mutate UI state on the main actor to prevent hitches.  
After obtaining an AVAsset, load needed properties asynchronously (for example, playable, duration, tracks) instead of querying them synchronously to avoid blocking.  
Bridge progress updates into a lightweight stream (such as an AsyncStream) so a view model can observe and publish smooth, throttled updates to the UI.  
Model overall progress as iCloud download progress plus asset-readiness progress, reaching 100% only when the player item is actually ready to present.  
When the player becomes ready, transition the UI state with a short animation (around 0.1 seconds) for a seamless handoff into the preview.  
Handle cancellations and failures by inspecting the Photos result-info dictionary and cancelling outstanding requests when views disappear to conserve bandwidth and memory.
