## 1\. Root Cause Analysis: A Categorical Perspective

### The Flawed Morphism Composition

The bug arises from a flawed composition of morphisms during the "Change Video" flow. The current implementation of `replaceSelectedVideo` is incorrect.

**Current (Buggy) Flow:**

1.  The system is in a state with `VideoAssetState₁` containing `RotationState₁ = (intrinsic₁, user₁)`. The user may have applied rotations, so `user₁ > 0`.
2.  The user taps "Change Video", triggering the `replaceSelectedVideo` morphism with a new `PhotosPickerItem`.
3.  The `replaceSelectedVideo` function (in `AddMoveUnifiedState.swift:1836`) executes. It correctly resets `videoAsset` and `photosIdentifier` but **fails to reset `userAppliedRotation`**.
4.  It then calls `loadVideo(from:)`, which loads the new asset and determines its `intrinsic₂`.
5.  The final state becomes `VideoAssetState₂` with `RotationState₂ = (intrinsic₂, user₁)`.

This is a **non-commutative diagram**. The user expects the "Change Video" action to result in a state equivalent to loading the video for the first time. However, the current flow is equivalent to `(Load New Video) ∘ (Preserve Old User Rotation)`, which produces an incorrect final state where the old rotation is applied to the new video. This violates the WYSIWYG principle.

## 2\. The Blind Spot: Missing State Reset Morphism

The system's blind spot is the **absence of an explicit state reset morphism** within the video replacement workflow. The developers implicitly assumed that all state preservation was desirable, failing to differentiate between the state tied to the asset (which should be discarded) and state tied to the view's configuration (which might be preserved).

For the "Change Video" feature, the `userAppliedRotation` is fundamentally tied to the *previous* video asset. Preserving it is a categorical error; it's applying a property of a discarded object to a new, unrelated object.

This guarantees that the system's state remains isomorphic with the user's mental model: a new video should always start in its natural orientation.
