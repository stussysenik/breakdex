  The Isomorphism Issue with Change Button vs Back Button


⏺ The issue you're describing stems from the rotation state management in TrimmerViewModel.swift. Here's what's happening:

  # The Problem
  When entering via Change button:
  1. New video is loaded with initialIntrinsicRotation: 0, initialUserRotation: 0
  2. But then setupAsync() loads the intrinsic rotation from the new asset
  3. Previous user rotation might be preserved if not properly reset
  4. This creates inconsistent state where rotation doesn't match user expectations

  # Solution Location
  The issue is in the state synchronization between the change button flow and the TrimmerViewModel initialization. The
  change button should:

  1. Reset user-applied rotation when loading a new video
  2. Only preserve intrinsic rotation from the new asset
  3. Ensure the total rotation calculation starts fresh for the new video

  # The key files to examine are:
  - TrimmerViewModel.swift:376-382 (initialization)
  - TrimmerViewModel.swift:673-680 (setupAsync rotation loading)
  - The change button implementation in whichever view initiates new video selection
