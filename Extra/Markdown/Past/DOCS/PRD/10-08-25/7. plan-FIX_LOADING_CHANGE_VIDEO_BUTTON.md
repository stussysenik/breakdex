The "Change Video" button incorrectly transitions to the "Select a clip" screen because its action triggers a full state reset *before* presenting the `PhotosPicker`. This reset destroys the trimmer view, preventing the picker from ever appearing. The correct sequence is to present the picker first and then perform the reset and load operations after a new video is selected.

This plan corrects the order of operations to ensure the `PhotosPicker` is presented correctly and the video replacement workflow completes successfully.

## 1\. Root Cause Analysis (Categorical Model)

The workflow fails because a state-altering morphism (`prepareForNewVideoSelection`) is executed prematurely, which destroys the context (the `FeatureRichTrimmerView` object) required for the subsequent morphism (`showPhotosPicker`).

  * **Objects:**
      * `A`: The `FeatureRichTrimmerView` in the `.trimming` state.
      * `B`: The `PhotosPicker` view, presented modally.
      * `C`: The `AddMoveSelectClipViewUnified` in the `.ready` state.
  * **Intended Morphism Chain:** The user action (`Button Tap`) should trigger a transition from `A` to `A + B` (Trimmer view with a modal Picker).
  * **Actual Morphism Chain:**
    1.  `Button Tap` in `A` calls `prepareForNewVideoSelection()`.
    2.  `prepareForNewVideoSelection()` immediately transitions the global state to `.ready`.
    3.  The parent view (`AddMoveContainer`) reacts to the `.ready` state and replaces `A` with `C`.
    4.  The code to present `B` is never executed because its parent view `A` has been destroyed.

The system incorrectly executes the path `A → C` instead of the intended `A → A + B`. The fix is to re-order the morphisms so the picker is presented before the destructive state reset occurs.

/// 🎯 ATOMIC VIDEO REPLACEMENT: Orchestrates the "Change Video" workflow.
/// This method ensures the correct sequence of operations:
/// 1. A full atomic state reset to tear down the old video and UI components.
/// 2. Immediate initiation of the new video loading process from a clean state.
/// This fixes the bug where the UI would navigate away before the PhotosPicker could be presented.
///
/// - Parameter item: The new PhotosPickerItem selected by the user.
@MainActor
public func handleVideoReplacement(_ item: PhotosPickerItem) async {
    let correlationId = UUID().uuidString.prefix(8)
    logger.info("🎯 ATOMIC_REPLACEMENT: 🚀 Starting video replacement workflow [\(correlationId)]")

    do {
        // STEP 1: Perform the full atomic state reset. This will transition the state
        // from .trimming to .ready, tearing down the trimmer UI.
        logger.info("🎯 ATOMIC_REPLACEMENT: 🔄 STEP 1 - Performing atomic state reset [\(correlationId)]")
        try await prepareForNewVideoSelection()
        logger.info("🎯 ATOMIC_REPLACEMENT: ✅ STEP 1 Complete - State is now .ready [\(correlationId)]")

        // STEP 2: Immediately call didSelectVideo. Since the state is now .ready,
        // this will correctly transition to .loadingVideo and begin the loading process
        // for the new video item.
        logger.info("🎯 ATOMIC_REPLACEMENT: 🔄 STEP 2 - Initiating new video load [\(correlationId)]")
        didSelectVideo(item)
        logger.info("🎯 ATOMIC_REPLACEMENT: ✅ STEP 2 Complete - New video loading task started [\(correlationId)]")

    } catch {
        logger.error("🎯 ATOMIC_REPLACEMENT: ❌ Video replacement failed during state reset: \(error.localizedDescription) [\(correlationId)]")
        await setError(message: "Failed to prepare for new video.", underlying: error.localizedDescription)
    }
}
