Analysis of the latest logs confirms two distinct issues. First, the "Change Video" workflow is broken; it incorrectly transitions to the initial selection screen instead of presenting a `PhotosPicker`. This is caused by a state reset being triggered prematurely, which destroys the trimmer view before it can present the picker. Second, the loading progress bar is stuck at 0% during the "Initializing" phase for all video loading operations, which provides poor user feedback.

The following plan addresses both issues by correcting the workflow sequence and refining the progress calculation logic.

-----

## ✅ Implementation Plan Checklist

1.  **Correct the "Change Video" Workflow:** Modify the `FeatureRichTrimmerView` to present the `PhotosPicker` *before* resetting the application state. The state reset and new video load will only occur *after* the user makes a selection.
2.  **Fix the "Stuck at 0%" Progress Bar:** Adjust the `UnifiedProgressEngine` to grant immediate progress for the "Initializing" phase. This ensures the progress bar moves from 0% to 3% as soon as loading begins, providing immediate feedback.

-----

## 1\. Root Cause Analysis

  * **Workflow Failure ("Change Video"):** The `prepareForNewVideoSelection()` method is called from the "Change Video" button's action. This method transitions the `flowState` to `.ready`. The `AddMoveContainer` view reacts to this state change by replacing the `FeatureRichTrimmerView` with the `AddMoveSelectClipViewUnified`. This happens before the code to present the `PhotosPicker` can execute, as the view context that was supposed to present it has been destroyed.

  * **Progress Stall ("Stuck at 0%"):** The `UnifiedProgressEngine.beginLoading()` method calls `calculateDeterministicProgress(phase: .initializing, phaseProgress: 0.0)`. The calculation logic correctly yields a progress of `0.0`, as no phases are complete and the progress within the current phase is zero. The UI displays "Initializing" but the progress bar remains at 0% until the next phase (`.requestingDownload` or `.downloadingFromCloud`) begins, which is a poor user experience. The logs explicitly identify this incorrect expectation: `Expected: Should be > 0% (initializing weight: 3%)`.

-----

```swift
/// 🎯 ATOMIC VIDEO REPLACEMENT: Orchestrates the "Change Video" workflow.
/// This method ensures the correct sequence: a full atomic state reset followed
/// immediately by the initiation of the new video loading process.
/// - Parameter item: The new PhotosPickerItem selected by the user.
@MainActor
public func handleVideoReplacement(_ item: PhotosPickerItem) async {
    let correlationId = UUID().uuidString.prefix(8)
    logger.info("🎯 ATOMIC_REPLACEMENT: 🚀 Starting video replacement workflow [\(correlationId)]")

    do {
        // STEP 1: Perform the full atomic state reset. This transitions the state
        // from .trimming to .ready, tearing down the trimmer UI.
        logger.info("🎯 ATOMIC_REPLACEMENT: 🔄 STEP 1 - Performing atomic state reset [\(correlationId)]")
        try await prepareForNewVideoSelection()
        logger.info("🎯 ATOMIC_REPLACEMENT: ✅ STEP 1 Complete - State is now .ready [\(correlationId)]")

        // STEP 2: Immediately call didSelectVideo. Since the state is now .ready,
        // this will correctly transition to .loadingVideo and begin loading.
        logger.info("🎯 ATOMIC_REPLACEMENT: 🚀 STEP 2 - Starting video loading [\(correlationId)]")
        didSelectVideo(item)

    } catch {
        logger.error("🎯 ATOMIC_REPLACEMENT: ❌ Video replacement failed during state reset: \(error.localizedDescription) [\(correlationId)]")
        await setError(message: "Failed to prepare for new video.", underlying: error.localizedDescription)
    }
}
```

```swift
/// Begin a new video loading operation with optional file size estimate
public func beginLoading(fileSizeEstimate: Int64 = 0) {
    logger.info("🎯 DeterministicProgressEngine: 📥 Beginning deterministic video loading operation")
    progressLogger.info("📊 Operation started - File size estimate: \(ByteCountFormatter.string(fromByteCount: fileSizeEstimate, countStyle: .file))")

    resetProgress()
    operationStartTime = Date()
    lastProgressUpdate = Date()
    startF1Timer()

    if animationTimer == nil || !(animationTimer?.isValid ?? false) {
        logger.info("🎯 DeterministicProgressEngine: 🔄 Animation timer is invalid, re-initializing for new operation.")
        setupAnimationTimer()
    }

    updatePhase(.initializing)
    
    // BEFORE (Incorrect):
    // calculateDeterministicProgress(phase: .initializing, phaseProgress: 0.0)

    // AFTER (Correct):
    // By setting phaseProgress to 1.0, we signal that the 'initializing' phase
    // has completed its contribution to the overall progress, which is 3%.
    // This moves the progress bar immediately from 0% to 3% for better UX.
    calculateDeterministicProgress(phase: .initializing, phaseProgress: 1.0)
    
    logger.info("🎯 DeterministicProgressEngine: ✅ Deterministic loading operation initialized")
    progressLogger.info("📊 Initial progress: \(String(format: "%.3f", self.unifiedProgress)) (\(Int(self.unifiedProgress * 100))%)")
}
```
