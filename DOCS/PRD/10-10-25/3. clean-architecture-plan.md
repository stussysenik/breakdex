# Clean Architecture Plan for breakdex
## Date: 2025-10-10
## Goal: Production-ready, maintainable architecture for video flashcard app

---

## 🎯 EXECUTIVE SUMMARY

**Current State:** Complexity crisis with 20+ video files, 12+ managers, and a history of 7k LOC monolith
**Solution:** "Build Clean Highway Through Jungle" approach - leverage existing clean AddMoveUnifiedState.swift and gradually migrate
**Timeline:** 4 weeks to clean, production-ready architecture
**Philosophy:** Build alongside, don't fix the over-engineered mess

---

## 📊 CURRENT SITUATION ANALYSIS

### What's Working (Keep & Build Upon)
✅ **AddMoveUnifiedState.swift** - Clean 180-line implementation
✅ **AppContainer.swift** - Dependency injection hub
✅ **VideoProcessingPipeline.swift** - Proven video processing
✅ **UnifiedPlayerManager** - Video playback logic
✅ **Core Data Models** - Move, Combo, Review entities
✅ **Main Architecture** - Tab-based navigation working

### What's Over-Engineered (Phase Out/Delete)
❌ **AddMoveUnifiedState-OLD.swift** - 7k LOC monolith
❌ **20 Video files** doing what 4 files should do
❌ **12 Manager files** for simple operations
❌ **Multiple orchestras, coordinators, monitors** for basic tasks
❌ **Complex state validation** for simple workflows

### Core User Journey (What Actually Matters)
1. User taps "+" tab → Opens Photos picker
2. User selects video → Video loads and displays
3. User can trim video (optional) → Trimming interface
4. User names move → Naming screen
5. User saves → Move saved to Core Data and Photos album

## 🔧 IMPLEMENTATION PRINCIPLES

### 1. Single Responsibility Principle
- Each file has ONE clear purpose
- Maximum 300-500 lines per file
- Clear separation between Views, ViewModels, and Services

### 2. Dependency Injection
- All dependencies injected via AppContainer
- No singleton patterns (except AppContainer)
- Testable components

### 3. State Management
- Unidirectional data flow
- @Published properties for reactive UI
- Clear state transitions

### 4. Error Handling
- Graceful degradation
- User-friendly error messages
- Comprehensive logging

### 5. Video Processing
- Async/await patterns
- Progress tracking
- Memory management

## 🚨 RISK MITIGATION

### Technical Risks
1. **Video Processing Regression:** Keep existing VideoProcessingPipeline until migration complete
2. **Core Data Issues:** Don't modify data models during migration
3. **Performance Regression:** Profile each phase before proceeding

### Timeline Risks
1. **Scope Creep:** Focus on essential features only
2. **Perfectionism:** "Good enough" is better than "perfect but delayed"
3. **Analysis Paralysis:** Build incrementally, test early

### User Experience Risks
1. **Feature Loss:** Test each user journey before and after migration
2. **Performance Issues:** Monitor memory usage and build times
3. **Breaking Changes:** Maintain API compatibility during transition
