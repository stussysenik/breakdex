# Analysis

## Component Roles and Interactions

### 1. **SelectClip.swift** - Entry Point for Video Selection
- **Role**: Simple "select a clip" UI component
- **Functionality**:
  - Displays a "Select a Clip" button using `SelectClipButtonStyle()`
  - Opens iOS Photos picker for video selection (`PhotosUI.PhotosPicker`)
  - Handles video selection through `handleVideoSelection()` method
  - Calls `unifiedState.loadVideo(from: newItem)` to process selected video
- **Key Pattern**: Minimal UI component that forwards user actions to state management

### 2. **TrimmerView.swift** - Video Loading and Trimming Interface
- **Role**: Main interface for video loading, preview, and trimming setup
- **Key Features**:
  - Robust video loading with `ResilientVideoLoader` for iCloud/offline scenarios
  - Comprehensive loading states (initializing, downloading, transferring, validating, etc.)
  - Error handling with retry logic and network status monitoring
  - Empty state, loading state, error state, and video-ready state management
  - Currently shows placeholder trimming controls (lines 315-329)
- **Integration**: Uses `AddMoveUnifiedState` for state management and observes loading progress
- **Current Status**: Loading infrastructure is complete, trimming UI is placeholder

### 3. **VideoPlayer.swift** - Core Video Playback Engine
- **Role**: Reusable video player component with `AVFoundation` integration
- **Architecture**:
  - `@MainActor` class with `ObservableObject` for SwiftUI reactivity
  - Supports two modes: `.main` (full-featured) and `.preview` (lightweight)
  - Comprehensive state management (`PlayerState` enum: idle, loading, ready, playing, paused, ended, error)
- **Features**:
  - Play/pause/stop/seek functionality
  - Progress tracking and time updates
  - Buffering status monitoring
  - Volume and mute controls
  - Automatic resource cleanup in deinit
- **Integration**: Designed to be instantiated by `VideoPlayerView` for UI layer

### 4. **VideoPlayerView.swift** - SwiftUI Video Player UI
- **Role**: SwiftUI wrapper around `SharedVideoPlayer` with UI controls
- **Architecture**: Clean separation between view layer and player logic
- **Features**:
  - Configurable player modes (default, preview, minimal)
  - Auto-hiding controls with timer
  - Fullscreen video support
  - Loading and error overlay handling
  - Time display and playback controls
- **Current Issue**: `getPlayerInstance()` returns nil (line 279) - needs integration with `SharedVideoPlayer`

### 5. **VideoTrimmer.swift** - Video Processing Engine
- **Role**: Advanced video trimming and processing functionality
- **Architecture**:
  - Uses `VideoProcessingPipeline` for actual video operations
  - `TrimConfiguration` struct for trim parameters (start/end times, rotation)
  - Comprehensive error handling with `VideoTrimmerError` enum
- **Features**:
  - Time range validation
  - Progress tracking during processing
  - Support for video rotation
  - Cancellation support
- **Current Status**: Core infrastructure in place but needs integration with actual `VideoProcessingPipeline`

### 6. **AddMoveUnifiedState.swift** - Central State Management
- **Role**: Centralized state management for the entire AddMove workflow
- **Key Properties**:
  - Video data: `selectedVideo`, `trimmedAsset`, `originalVideoURL`
  - Trimming info: `trimStartTime`, `trimEndTime`
  - Flow state: `currentTab`, `flowState`, `loadingProgress`
  - Move information: `moveName`, `moveDescription`, etc.
- **Key Methods**:
  - `loadVideo(from: PhotosPickerItem)` - handles video loading from Photos picker
  - `processTrim(from:to:)` - currently placeholder, needs actual trimming implementation
  - State validation and error handling

## Intended Workflow Integration

### Current State Flow:
1. **User clicks "Select a Clip"** in `SelectClip.swift`
2. **Photos picker opens** → user selects video
3. **`SelectClip.handleVideoSelection()`** calls `unifiedState.loadVideo(from:)`
4. **`AddMoveUnifiedState.loadVideo()`** processes `PhotosPickerItem` → creates `AVAsset`
5. **State change triggers navigation** to trimming interface
6. **`TrimmerView`** displays loading progress, error states, or video preview
7. **Video ready** → placeholder trimming controls appear (not yet implemented)

### Intended Complete Workflow:
1. **Video Selection** → `SelectClip` → `AddMoveUnifiedState`
2. **Video Loading** → `TrimmerView` with `ResilientVideoLoader`
3. **Video Preview** → `VideoPlayerView` using `SharedVideoPlayer`
4. **Trimming Interface** → `VideoTrimmer` integration in `TrimmerView`
5. **Trim Processing** → `VideoTrimmer.trimVideo()` → `VideoProcessingPipeline`
6. **Result Storage** → `trimmedAsset` in `AddMoveUnifiedState`

## Key Integration Points Missing:

1. **VideoPlayer Integration**: `VideoPlayerView.getPlayerInstance()` needs to expose `AVPlayer` from `SharedVideoPlayer`
2. **Trimmer UI**: `TrimmerView` lines 315-329 need actual trimming controls using `VideoTrimmer`
3. **Processing Pipeline**: `VideoTrimmer` needs integration with `VideoProcessingPipeline`
4. **State Synchronization**: `AddMoveUnifiedState.processTrim()` needs actual trimming implementation
