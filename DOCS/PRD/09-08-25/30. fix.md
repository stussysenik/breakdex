Ideal direction: implement a typed, cancelable PhotosClient actor for asset intake and unify rotation+trim via a shared AVFoundation composition builder, then remove all SwiftUI transforms from video views so previews never go black and always match the exported file. [1][2][3]

## Objective
- Provide exact file-by-file instructions to replace brittle continuations with a robust Photos wrapper and to preview/export rotation+trim using the same AVFoundation pipeline, eliminating black-screen previews and type-inference build errors. [1][4][5]

## Non‑goals
- No additional effects beyond quarter-turn rotation and trimming, no multi-track editing, and no non-Photos media sources beyond current app flows. [1]

## Spec: Photos intake (fix the continuation/type issues)
- New file: Managers/Photos/PhotosClient.swift (Actor). [1]
  - Purpose: Own all PhotoKit calls, expose concrete async APIs with progress via AsyncStream, and wire cancellation to PhotoKit request IDs to avoid continuation ambiguity and missed resumes. [1][2][6]
  - API:
    - func resolveAsset(for asset: PHAsset, allowNetwork: Bool) async throws -> AssetHandle where AssetHandle = .file(URL) | .composed(AVAsset). [1][2]
    - func downloadWithProgress(for asset: PHAsset, allowNetwork: Bool) -> AsyncThrowingStream<Double, Error> to expose PHVideoRequestOptions.progressHandler as 0…1 progress. [1][7][6]
  - Behavior: Use PHImageManager.requestAVAsset(forVideo:options:resultHandler:) with networkAccessAllowed and capture the PHImageRequestID to cancel via cancelImageRequest if Task is cancelled. [1][8][2]
  - File-backed guarantee: If the result AVAsset isn’t file-based (e.g., AVComposition/HLS), materialize the original resource to a temp file via PhotoKit before returning .file(URL) to ensure videoComposition is supported downstream. [1][3][9]

## Spec: Shared AVFoundation builder (preview/export parity)
- File: Video/Processing/VideoTransformBuilder.swift (create if not present, then use everywhere). [1]
  - Purpose: Given (asset, trimRange, quarterTurns) return (composition, videoComposition) with rotation and render size applied identically for preview and export. [1][5]
  - API: build(asset: AVAsset, trim: CMTimeRange, quarterTurns: Int) throws -> (AVMutableComposition, AVMutableVideoComposition). [1][5]
  - Algorithm:
    - Read the first video track and get preferredTransform $$R_{src}$$. [1][10]
    - Determine source presentation size $$(w, h)$$ after applying $$R_{src}$$. [1][10]
    - Compute user rotation $$R(\theta)$$ for quarterTurns ∈ {0,1,2,3}, where $$\theta \in \{0,\frac{\pi}{2},\pi,\frac{3\pi}{2}\}$$. [1][5]
    - Compute translation $$T$$ to keep content in-bounds; common cases: 90° CW translate by $$(h, 0)$$, 270° CW translate by $$(0, w)$$, 180° translate by $$(w, h)$$ as needed given top-left origin. [1][11][10]
    - Insert CMTimeRange into a composition track, create one instruction over duration, and apply setTransform($$T \cdot R(\theta) \cdot R_{src}$$, at: .zero) on a single layer instruction. [1][12][5]
    - Set renderSize = $$(w, h)$$ for 0°/180° and $$(h, w)$$ for 90°/270°, and choose frameDuration based on source nominal frame rate or a safe default (e.g., 1/30). [1][5]

## Guardrails and telemetry
- Add a debug-only assertion in video player views: “Player hierarchy must not have non-identity transform,” to prevent regressions that reintroduce black previews. [1]

## Error handling policy
- Photos intake: if request returns nil or is cancelled, surface explicit errors and allow retry with network enabled and visible progress via AsyncStream. [1][2][7]
- Non-file assets: on preview/export failure with videoComposition, force materialization to temp file and retry once before surfacing an error. [1][3][9]
- Export: on empty file or wrong duration, delete temp output, report error, and provide retry with a safer preset. [1][15]

## Performance targets
- Preview rotation response: perceived update <100 ms by reusing one AVPlayer and swapping only AVPlayerItem with a cached videoComposition when possible. [1][13]
- Export: single composition pass, no intermediate renders, aggressive cleanup of temp files post-persist. [1][15]
- UI: stable 60 fps overlays by avoiding any transforms on the video surface. [1]

## Testing and acceptance
- Matrix: portrait/landscape assets, all quarter-turns, slo-mo/time-mapped sources, long 4K HEVC/H.264, cloud-only items under poor network and cancellations. [1][2]
- Assertions: preview orientation equals export orientation, presentation size equals renderSize, duration tolerance within ±1 frame, output track preferredTransform is identity when rotation is baked, and no black preview for any rotation. [1][15][10]
- File-backed rule: confirm AVPlayerItem.videoComposition is only used with file-based media, never HLS; if violated, fallback to materialization path. [1][3]

## Rollout plan
- Ship behind a feature flag “AVCompositionRotation,” enable in internal/beta, monitor telemetry for black-screen incidents, export timings, iCloud retries, then ramp to 100%. [1]
- Keep an emergency fallback to “no-rotation preview” while export remains composition-based to preserve correctness if a device-specific preview renderer bug appears. [1]

By implementing PhotosClient for deterministic async intake and centralizing rotation+trim in VideoTransformBuilder for both preview and export, the build errors and black previews are removed, and the flow becomes “pick, set **rotation**, set **trim**, save,” with identical preview/export behavior across local and iCloud-backed videos.
