### Root Cause Analysis

The core problem is a **race condition** combined with a **state lifecycle bug**. Even though `AddMoveStateOwner` correctly creates a single, persistent instance of `AddMoveUnifiedState`, the way the loading process is initiated allows progress updates to arrive *before* the state machine has officially transitioned to `.loadingVideo`.

Here's the step-by-step failure from your latest logs:

1.  **Selection**: You select a video. `didSelectVideo` is called.
2.  **Task Creation**: `didSelectVideo` creates a new `Task` to handle the entire loading operation. This is good because it encapsulates the workflow.
3.  **The Race Begins**: Inside this `Task`, two things happen almost simultaneously:
      * `beginLoadingState()` is called to transition the `flowState` from `.ready` to `.loadingVideo`. This happens on the main actor.
      * `loadVideoWithCancellation()` is called, which immediately triggers the `modernVideoLoadingService`. This service starts fetching the video and publishing progress updates on a background thread.
4.  **Race Condition Lost**: The `modernVideoLoadingService` is so fast, especially for local or cached videos, that it publishes its first progress update (`.initializing`) *before* the main actor has had a chance to fully process the state change to `.loadingVideo`.
5.  **State Mismatch**: Your `handleVideoLoadingProgress` function receives the progress update. It checks the `flowState` and finds it's still `.ready` (or in some cases, a new, incorrect instance's state).
6.  **Error State**: Seeing a progress update in an invalid state, the `CATEGORICAL_LIMIT_VIOLATION` guard is triggered, and the state machine correctly transitions to `.error`, causing the UI to show a failure.

This explains why both "Select a Clip" and "Change Video" fail—they use the same flawed, racy `didSelectVideo` entry point.

### Solution Implementation

To fix this, we must ensure the state transition to `.loadingVideo` is **fully complete and synchronous** before any asynchronous code that can generate progress updates is executed.

#### 1\. Fix the Loading Race Condition in `AddMoveUnifiedState.swift`

We will refactor the `didSelectVideo` function to be more robust and sequential. This ensures the state transition is atomic and happens before the loading task begins.

Replace the `didSelectVideo` function in `AddMoveUnifiedState.swift` with the following implementation:

```swift
// In: AddMoveUnifiedState.swift

@MainActor
public func didSelectVideo(_ item: PhotosPickerItem) {
    let identifier = item.itemIdentifier ?? "unknown"
    let correlationId = String(UUID().uuidString.prefix(8))

    logger.info("🎯 UNIFIED_LOADING_ENTRY: 🚀 VIDEO_SELECTION_START [\(correlationId)] - Processing video selection: \(identifier)")

    // 1. Cancel any previous loading task.
    videoLoadingTask?.cancel()

    // 2. Perform a full atomic reset to ensure a clean state.
    // This is now synchronous within the MainActor context.
    Task {
        do {
            try await prepareForNewVideoSelection()

            // 3. SYNCHRONOUSLY transition to the .loadingVideo state.
            // This is the critical fix. It guarantees the state is correct
            // before any async file loading begins.
            let transitionSuccess = self.beginLoadingState(from: self.flowState, videoIdentifier: identifier)
            guard transitionSuccess else {
                self.logger.error("❌ Initial state transition to .loadingVideo failed. Aborting.")
                await self.setError(message: "Failed to initialize loading state.")
                return
            }

            // 4. With the state now correctly set, start the async loading work in a new Task.
            self.videoLoadingTask = Task { [weak self] in
                guard let self = self else { return }
                
                await self.fetchAndDisplayFileSize(from: item, correlationId: correlationId)
                try Task.checkCancellation()
                
                await self.loadVideoWithCancellation(from: item, correlationId: correlationId)
            }
        } catch {
            logger.error("❌ Failed during pre-loading reset: \(error.localizedDescription)")
            await setError(message: "Failed to prepare for new video.", underlying: error.localizedDescription)
        }
    }
}
```

@MainActor
private func setupTrimmerViewModel() async {
    // Add this new function to FeatureRichTrimmerView
    let correlationId = String(UUID().uuidString.prefix(8))
    diagnosticLogger.logInfo("🚀 LAZY_VIEWMODEL_SETUP - Starting async TrimmerViewModel creation [\(correlationId)]")

    guard viewModel == nil else {
        diagnosticLogger.logInfo("⚠️ LAZY_VIEWMODEL_SETUP - Skipping, ViewModel already exists. [\(correlationId)]")
        return
    }

    isViewModelLoading = true
    viewModelLoadError = nil

    do {
        guard let videoAsset = unifiedState.videoAsset,
              let photosIdentifier = unifiedState.photosIdentifier,
              let playerViewModel = unifiedState.currentPlayerViewModel as? UnifiedVideoPlayerViewModel else {
            throw TrimmerSetupError.missingDependencies
        }
        
        diagnosticLogger.logInfo("✅ DEPENDENCIES_VALIDATED for lazy setup. [\(correlationId)]")

        let startTime = CMTime(seconds: unifiedState.trimStartTime, preferredTimescale: 600)
        let endTime = CMTime(seconds: unifiedState.trimEndTime, preferredTimescale: 600)

        let trimmerVM = TrimmerViewModel(
            asset: videoAsset,
            photosIdentifier: photosIdentifier,
            initialIntrinsicRotation: unifiedState.intrinsicAssetRotation,
            initialUserRotation: unifiedState.userAppliedRotation,
            initialStartTime: startTime,
            initialEndTime: endTime,
            playerViewModel: playerViewModel
        )

        try await trimmerVM.setupAsync()
        self.viewModel = trimmerVM
        
        diagnosticLogger.logInfo("🎉 LAZY_VIEWMODEL_SUCCESS - TrimmerViewModel created and set up. [\(correlationId)]")

    } catch {
        viewModelLoadError = error.localizedDescription
        diagnosticLogger.logError("❌ LAZY_VIEWMODEL_FAILED - TrimmerViewModel creation failed [\(correlationId)]", error: error)
    }

    isViewModelLoading = false
}
