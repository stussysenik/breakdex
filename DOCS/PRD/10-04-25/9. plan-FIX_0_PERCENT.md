### **1. Overview (The "What" and "Why")**

#### **1.1. Goal 🎯**

This specification outlines the re-architecture of the video import loading experience. The primary goal is to **replace the current fractured, two-phase loading interface with a single, unified, and continuous progress bar**. This new implementation must provide psychological transparency, aligning the user's mental model of a single "import" action with the system's feedback to build trust and eliminate friction.

#### **1.2. Persona & User Journey 🏃**

The target user is "The Athlete," a persona who values precision, reliability, and a frictionless workflow, akin to a mechanical watch.

  * **User Journey:**
    1.  The user selects a training video to import.
    2.  They expect a single, clear indication that the system is working on their request.
    3.  The system provides continuous, trustworthy feedback on the import progress.
    4.  Upon completion, the system seamlessly transitions to the trimming view.

The current journey, with its disjointed phases and perceived stalls at 0% or 45%, breaks this expectation of precision and introduces cognitive load.

#### **1.3. Desired Outcomes ✨**

  * **Increased User Trust:** A single, smooth progress bar that accurately reflects the real-world operation will feel more reliable and professional.
  * **Reduced Perceived Wait Time:** By using psychologically-proven animation principles (e.g., acceleration), the loading process will feel faster and less frustrating.
  * **Elimination of "Hangs":** The notorious stall during the loading phase must be completely eradicated.
  * **Architectural Decoupling:** The UI state will be decoupled from the raw, discrete phases of the backend, leading to a more maintainable and robust architecture.

#### **1.4. Non-Goals ❌**

  * **Multi-File Batch Import:** This spec focuses exclusively on the single-video import flow. The architecture should not preclude future batch-import work but is not required to implement it now.
  * **Major UI Redesign:** The existing aesthetic of the `LoadingOverlayView` should be maintained. This is an architectural and experiential enhancement, not a visual redesign.

### **2. Functional Requirements (The "What")**

#### **2.1. Unified Progress Calculation**

The system shall expose a single, unified progress value ranging from 0.0 to 1.0 that represents the entire import operation—from the initial network request to the final asset validation.

#### **2.2. Predictive Weighting**

The system must not allocate static percentages to backend phases. Instead, it must dynamically calculate **predictive weights** for the primary time-consuming phases (iCloud download and local file processing) *before* the operation begins.

  * This weighting must be a function of, at a minimum, **file size** and the device's current **network conditions** (e.g., Wi-Fi vs. cellular).
  * The unified progress will be calculated as a weighted sum of the progress of each sub-phase.

#### **2.3. Smooth UI Animation**

The UI progress bar must not be bound directly to the discrete, often irregular progress updates from backend APIs.

  * A **smoothing and interpolation layer** must be implemented to animate the displayed progress fluidly towards the calculated target progress.
  * The animation must follow a gentle **acceleration curve (ease-in)** to reduce perceived duration and increase user satisfaction.

#### **2.4. Graceful Error & State Handling**

The system must be resilient and communicate failures clearly. It shall handle the following scenarios:

  * **Network Loss:** During an iCloud download, if the network is lost, the operation must pause and the UI must clearly communicate this state. The download must be capable of resuming automatically when connectivity is restored.
  * **Insufficient Storage:** If a local file copy fails due to lack of disk space, the operation must fail gracefully. The UI must display a clear, actionable error message, and any partially created temporary files must be deleted.
  * **User Cancellation:** The user must be able to cancel the import at any time. A cancellation event must immediately terminate all backend operations and perform necessary cleanup.
