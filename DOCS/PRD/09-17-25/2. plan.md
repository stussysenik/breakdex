### 1. What happens when you press the "Back" button?

This action takes you all the way back to the initial video selection screen.

* **UI (What you see):**
    1.  You tap the back arrow on the "Video Preview" screen (`Pre-TrimView`).
    2.  The preview screen disappears, and you immediately see the "Select Clip" screen again, ready to pick a new video.
* **State (What the code does):**
    1.  The `reset()` function in the `AddMoveViewModel` is called.
    2.  It first **cleans up** the current video session, releasing the video player and freeing up memory.
    3.  It then changes the app's state from `.previewing` to `.ready`.
    4.  The `AddMoveContainer` sees the state is now `.ready` and automatically shows the `AddMoveSelectClipView`.

---

### 2. What happens when you press "Change"?

This lets you replace the current video with a different one from your library.

* **UI (What you see):**
    1.  You tap "Change" in the top-right corner of the preview screen.
    2.  The Photos library picker slides up over the app.
    3.  You select a new video.
    4.  The picker dismisses, and a loading indicator briefly appears with messages like "Preparing to load video...".
    5.  The new video you selected now appears in the same preview screen, ready to play.
* **State (What the code does):**
    1.  Tapping "Change" shows the `PhotosPicker`.
    2.  When you select a new video, the `handleDirectVideoSelection` function is called.
    3.  This triggers the `loadVideo` function, which **first cleans up** the old video player session.
    4.  The state changes from `.previewing` to `.loading`, which displays the progress indicator.
    5.  Once the new video is loaded, the state transitions back to `.previewing`, and the `AddMoveContainer` shows the `PreTrimView` again, but now with the new video's content.

---

### 3. What happens when you tap "Trim & Edit"?

This takes you to the detailed editing screen where you can shorten the clip.

* **UI (What you see):**
    1.  You tap the "Trim & Edit" button.
    2.  The preview screen is replaced by the `TrimmerView`, which shows a timeline of the video with handles you can drag to set start and end points.
* **State (What the code does):**
    1.  The `startTrimming()` function in the `AddMoveViewModel` is called.
    2.  It changes the app state from `.previewing` to `.trimming`.
    3.  The `AddMoveContainer` sees this state change and switches the view to the `TrimmerViewWrapper`.

---

### 4. What happens when you tap "Use Full Video"?

This skips the trimming step and moves you directly to the final step: naming your move.

* **UI (What you see):**
    1.  You tap the "Use Full Video" button.
    2.  The video preview disappears and is replaced by a screen with a text box, prompting you to "Name Your Move".
* **State (What the code does):**
    1.  The `startNaming()` function in the `AddMoveViewModel` is called.
    2.  It changes the app state from `.previewing` to `.naming`.
    3.  The `AddMoveContainer` detects the `.naming` state and displays the `NameMoveView`.
