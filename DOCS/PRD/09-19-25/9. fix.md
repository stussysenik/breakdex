## **Spec-Kit: Robust Video Preview in NameMoveView**

### **1. Objective**

To fix a critical reliability bug in the `NameMoveView` where the trimmed and rotated video preview fails to load, presenting the user with a blank player. The implementation must guarantee that the video preview is fully composed and ready for playback before the player UI is displayed.

### **2. Background & Diagnosis**

The root cause is a race condition within the `.task` modifier of `NameMoveView.swift`.

  * **Current Flawed Logic**: The code initiates a video composition using `VideoTransformBuilder.createPlayerItem`. It then uses a fixed, unreliable `Task.sleep(nanoseconds: 200_000_000)` to "wait" for this composition to complete.
  * **Evidence**: Logs confirm this approach is failing. The composition takes longer than the 0.2-second sleep, and the code proceeds even when the `AVPlayerItem` status is `0` (`.unknown`). The log message `Composed player item not ready (status: 0), continuing anyway...` explicitly identifies the failure point.
  * **Result**: A `UnifiedVideoPlayerViewModel` is initialized with an unprepared `AVPlayerItem`, leading to a blank video player and a poor user experience.

### **3. Proposed Solution**

The unreliable `Task.sleep` must be replaced with a deterministic, asynchronous wait. The codebase already contains the necessary tool for this: the `AVPlayerItem.waitForStatus(_:timeout:)` extension method located in `UnifiedVideoPlayerViewModel.swift`.

This solution will involve:

1.  Calling `VideoTransformBuilder.createPlayerItem` to get the `AVComposition`.
2.  `await`-ing the `composedPlayerItem.waitForStatus(.readyToPlay, timeout: 15.0)` method.
3.  Proceeding with `AVPlayer` and `UnifiedVideoPlayerViewModel` initialization only *after* the await successfully completes.
4.  Implementing robust error handling in the `catch` block to manage composition failures or timeouts, transitioning the UI to a user-friendly error state.

#### **Final Code Structure:**

The final `do-catch` block inside the `.task` modifier should look like this:

```swift
do {
    let timeRange = CMTimeRange(
        start: CMTime(seconds: trimStartTime, preferredTimescale: 600),
        end: CMTime(seconds: trimEndTime, preferredTimescale: 600)
    )

    // 1. Create the composed player item.
    let composedPlayerItem = try await VideoTransformBuilder.createPlayerItem(
        asset: originalAsset,
        trimRange: timeRange,
        quarterTurns: rotation
    )
    
    // 2. Await readiness deterministically.
    logger.info("🎬 NAME_MOVE_VIEW: Waiting for composed player item to become ready...")
    try await composedPlayerItem.waitForStatus(.readyToPlay, timeout: 15.0)
    logger.info("🎬 NAME_MOVE_VIEW: ✅ Composed player item is now readyToPlay.")

    // 3. Create player and ViewModel now that the item is ready.
    let player = AVPlayer(playerItem: composedPlayerItem)
    let newPlayerViewModel = UnifiedVideoPlayerViewModel(
        player: player,
        mode: .preview,
        appContainer: AppContainer.shared
    )
    
    // 4. Update UI state on the main thread.
    await MainActor.run {
        self.playerViewModel = newPlayerViewModel
        isLoadingPreview = false
    }
    
    logger.info("🎬 NAME_MOVE_VIEW: ✅ Player view model created with a guaranteed ready-to-play item.")

} catch {
    logger.error("🎬 NAME_MOVE_VIEW: 🚨 Failed to create or prepare composed player: \(error.localizedDescription)")
    await MainActor.run {
        isLoadingPreview = false
        // Provide more specific error messaging to the user.
        let errorMessage = (error as? AVPlayerItem.AVPlayerItemError) == .timedOut
            ? "Preview generation timed out."
            : "Could not create video preview."
        viewModel.setErrorState(message: errorMessage)
    }
}
```
