Based on my exploration of the codebase, here's how the rotate functionality flows through the entire video trimming and naming process:

## **Video Preview Rotation Flow**

### **1. TrimmerView (User Interaction)**
When the user taps the rotate button in the trimmer:
- **TrimmerView** calls `rotationQuarterTurns = (rotationQuarterTurns + 1) % 4` 
- It emits the new rotation via `onRotate(newRotationQuarterTurns)` callback
- **CustomVideoPlayerView** immediately receives the updated `rotationQuarterTurns` parameter and applies it to the video preview

### **2. Video Preview Display (CustomVideoPlayerView)**
The video preview rotation happens through **VideoTransformBuilder**:
- When `rotationQuarterTurns != 0`, it creates an **AVMutableVideoComposition** with rotation transforms
- Uses `VideoTransformBuilder.build(asset: asset, quarterTurns: rotationQuarterTurns)` 
- The composition includes both **rotation** and **trimming** transforms if needed
- The video player applies the composition via `playerItem.videoComposition = transformResult.videoComposition`

## **Rotation Persistence Through State Flow**

### **3. AddMoveContainer State Management**
The rotation gets stored in the **AddMoveViewModel state**:
- When rotation changes: `viewModel.updateTrimmingRotation(rotationQuarterTurns: newRotation)`
- This updates the state: `.trimming(asset: asset, photosIdentifier: photosIdentifier, rotationQuarterTurns: rotationQuarterTurns)`

### **4. Passing to NameMoveView**
When the user saves the trimmed video:
- **TrimmerView** calls `onSave()` → **AddMoveContainer** calls `viewModel.finishTrimming(with: trimmerViewModel)`
- The viewModel transitions to **`.naming`** state with all the context:
  ```swift
  case .naming(let photosIdentifier, let originalAsset, let trimmedAsset, _, _, let rotationQuarterTurns)
  ```

### **5. NameMoveView Video Display Logic**

The **NameMoveView** has smart rotation handling:

**For Trimmed Videos** (already exported):
- Sets `effectiveRotation = 0` because **rotation was baked into the exported file** during trimming
- Displays: `CustomVideoPlayerView(asset: trimmedAsset, rotationQuarterTurns: 0)`
- **Prevents double-rotation** since the trimmer already applied rotation during export

**For Original Videos** (untrimmed):
- Uses the stored rotation: `CustomVideoPlayerView(asset: originalAsset, rotationQuarterTurns: rotationQuarterTurns)`
- Applies rotation live via VideoTransformBuilder

**For Photos Videos**:
- Uses the stored rotation: `CustomVideoPlayerView(photosIdentifier: photosIdentifier, rotationQuarterTurns: rotationQuarterTurns)`
- Applies rotation via VideoTransformBuilder for Photos assets

## **Key Design Decisions**

1. **Rotation State Persistence**: The rotation is stored in the viewModel state, not just locally in the trimmer
2. **Smart Double-Rotation Prevention**: NameMoveView detects if video is already trimmed and doesn't re-apply rotation
3. **Live Preview**: CustomVideoPlayerView immediately applies rotation changes for instant visual feedback
4. **Export-Time Application**: During trimming export, rotation gets permanently baked into the video file
5. **State-Driven Flow**: Rotation flows through the entire navigation chain via the viewModel state

This ensures the rotation is consistently applied throughout the entire workflow - from trimming to naming to final save - with no loss of the user's rotation preference.
