Ideal approach: implement rotation and trim entirely in AVFoundation for both preview and export with a shared composition builder, and remove all view-tree transforms from any SwiftUI hierarchy that hosts the video surface to eliminate black frames and guarantee preview/export parity. [11]

This spec-kit gives exact responsibilities, file changes, APIs, and acceptance criteria so an agent can ship a simple, reliable, performant solution. [11]

## Objective
- Deliver a rock-solid video rotation + trim flow where the preview exactly matches the exported file with no black-screen regressions across devices and iCloud-backed assets. [11]
- Keep the user flow minimal and intuitive: pick video, set **rotation**, set **trim**, save, and the system handles all edge cases and performance concerns automatically. [11]

## Scope
- In-scope: live preview rotation via AVPlayerItem.videoComposition, export rotation via AVAssetExportSession.videoComposition, state propagation, iCloud-backed intake, robust error handling, and telemetry. [11]
- Out-of-scope: multi-track editing, effects beyond quarter-turn rotation, or non-Photos sources beyond the existing app pathways. [11]

## User stories
- As a user, rotating a video by 0°/90°/180°/270° should immediately reflect in the preview and match the saved video orientation. [11]
- As a user, trimming should be accurate to the chosen range in both the preview and the saved video, including iCloud-only videos after download. [11]

## Non‑functional goals
- Reliability: no black-screen playback in preview or after saving, across device generations and orientations. [11]
- Performance: immediate visual response on rotation and smooth scrubbing, with a single export pass when saving. [11]
- Maintainability: one shared composition builder used by both preview and export to guarantee parity and reduce code duplication. [11]

## Architecture
- Single source of truth: rotationQuarterTurns ∈ {0,1,2,3} and CMTimeRange trimRange stored in view model state and routed across views. [11]
- AVFoundation parity: build AVMutableComposition for trim and AVMutableVideoComposition for rotation, attach to AVPlayerItem for preview and to AVAssetExportSession for export. [11]
- No UI transforms: do not apply .rotationEffect/.transformEffect/CATransform3D to any SwiftUI/UIView hierarchy containing the player surface. [11]

## Transform algorithm
- Compute final layer transform as $$T \cdot R(\theta) \cdot R_{src}$$ where $$R_{src}$$ is the track’s preferredTransform, $$R(\theta)$$ is the user’s quarter‑turn rotation, and $$T$$ is a translation to move the rotated content into positive coordinates. [11]
- Set renderSize to $$(w,h)$$ for 0°/180° and $$(h,w)$$ for 90°/270°, where $$(w,h)$$ is the natural presentation size derived from the source. [11]

## Public API contracts
- VideoTransformBuilder.build(asset: AVAsset, trim: CMTimeRange, quarterTurns: Int) -> (composition: AVMutableComposition, videoComposition: AVMutableVideoComposition). [11]
- TrimmerViewModel.updatePreview(asset: AVAsset, trim: CMTimeRange, quarterTurns: Int) -> AVPlayerItem configured with videoComposition. [11]
- TrimmerViewModel.exportVideo(asset: AVAsset, trim: CMTimeRange, quarterTurns: Int) -> URL of baked file with identity preferredTransform and trimmed duration. [11]

## Detailed implementation steps
- Build VideoTransformBuilder.swift
  - Read the asset’s first video track and preferredTransform $$R_{src}$$. [11]
  - Determine source presentation size $$(w,h)$$ after considering $$R_{src}$$. [11]
  - Compute user quarter‑turn matrix $$R(\theta)$$ for the given quarterTurns. [11]
  - Compute translation $$T$$ needed for the chosen $$R(\theta)$$: for 90° clockwise, translate by $$(h,0)$$; for 270° clockwise, translate by $$(0,w)$$; for 180°, translate by $$(w,h)$$ if required by origin placement. [11]
  - Insert CMTimeRange into an AVMutableComposition track and create one AVMutableVideoCompositionInstruction spanning the duration, with one AVMutableVideoCompositionLayerInstruction applying setTransform at time zero. [11]
  - Set AVMutableVideoComposition.renderSize to $$(w,h)$$ or $$(h,w)$$ as per rotation, and set a reasonable frameDuration (e.g., 1/30) while respecting source timescale when feasible. [11]
- Update TrimmerViewModel.swift
  - Maintain a single AVPlayer instance and replace only the AVPlayerItem on changes to rotation or trim. [11]
  - On updatePreview(asset, trim, quarterTurns), call the builder, create an AVPlayerItem with the composition, set item.videoComposition, set item.seekingWaitsForVideoCompositionRendering = true for precise scrubs, then replace the player’s currentItem. [11]
  - On exportVideo(asset, trim, quarterTurns), call the builder, create AVAssetExportSession with composition, assign export.videoComposition, select a composition‑capable preset, export to a temp URL, and return it. [11]
  - Validate export: file exists, size > 0, duration ≈ trimRange within ±1 frame, and preferredTransform identity on output track when rotation is baked. [11]
- Update TrimmerView.swift
  - Remove any .rotationEffect/.transformEffect on VideoPlayer or its parent stacks. [11]
  - Forward rotation button taps to increment rotationQuarterTurns and trigger TrimmerViewModel.updatePreview via onChange handlers. [11]
  - Keep controls in SwiftUI overlays; do not rotate overlay UI to keep 60 fps interactions. [11]
- Update CustomVideoPlayerView.swift
  - Remove ZStack-level .rotationEffect previously applied to the player or container. [11]
  - Initialize playback by constructing an AVPlayerItem via VideoTransformBuilder using stored rotationQuarterTurns and trimRange, assign item.videoComposition, and play. [11]
- Update NameMoveView.swift
  - When showing the saved/trimmed asset, construct the AVPlayerItem via VideoTransformBuilder with rotationQuarterTurns and the known trimmed time range to guarantee parity with the final export. [11]
- Update AddMoveViewModel.swift
  - Ensure state carries rotationQuarterTurns and exact CMTimeRange consistently through .trimming → .naming → saveMove. [11]
  - On save, reuse the builder and set export.videoComposition to bake orientation. [11]

## iCloud and intake requirements
- Always request the AVAsset with network access allowed and a progress UI; if the returned asset is not file‑backed (e.g., AVComposition or streaming), materialize it to a temp file before building compositions to ensure preview videoComposition is supported. [11]
- Persist Photos identifiers, but always build preview/export from a locally resolvable asset URL at the moment of use to avoid intermittent black playback. [11]

## Guardrails
- Add a runtime assertion: “Player view must not have non‑identity transform” to catch any reintroduced SwiftUI/CALayer rotations in debug builds. [11]
- Log rotationQuarterTurns, renderSize, chosen preset, export duration, and whether materialization was required for troubleshooting and performance insights. [11]

## Error handling
- Export failures: surface concise, actionable messages and auto‑retry once after materializing the source to a temp file if the first attempt used a non‑file asset. [11]
- Validation failures: if output is empty or duration is off by more than a frame, delete the temp file, report failure, and offer retry. [11]
- iCloud cancellations: stop gracefully, keep user state, and allow resume with progress. [11]

## Performance targets
- Preview updates: <100 ms perceived reaction to rotation taps by reusing the same player and only swapping AVPlayerItem with precomputed composition. [11]
- Export: single pass, no intermediate renders, with resource cleanup of temp files immediately after persistence. [11]
- UI: no jank in overlays since they’re never rotated or composited with the video layer. [11]

## Testing plan
- Device matrix: recent and older devices, low battery mode, nearly full storage, offline/slow network for iCloud. [11]
- Asset matrix: portrait/landscape, 0°/90°/180°/270°, slo‑mo/time‑mapped, long 4K + HEVC/H.264. [11]
- Assertions: preview orientation = export orientation, presentation size matches renderSize, duration tolerance within ±1 frame, and identity preferredTransform on output. [11]

## Acceptance criteria
- No black frames on preview or saved playback for any quarter turn or asset orientation. [11]
- Preview and export match in framing, rotation, and duration for all tested assets including iCloud-backed videos. [11]
- No SwiftUI/CALayer transforms applied to the video surface in any view, verified by runtime assertion in debug builds. [11]

## Rollout plan
- Stage behind a feature flag for rotation-by-composition, ship to internal/beta, collect telemetry on black-screen incidents, export durations, and iCloud retries, then graduate to 100%. [11]
- Keep a fallback path to “no rotation” preview for emergency disable while export remains composition-based to preserve correctness. [11]
