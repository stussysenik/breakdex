## 📋 **Problem Statement: Video Rotation Feature Implementation**

### **🎯 Core Problem**
Implement a **video rotation feature** in the BreakingFlashcards iOS app where users can rotate videos during the trimming process, with the rotation being **visually consistent** across all views and **correctly applied** to the final saved video.

### **🔍 Detailed Requirements**

#### **1. User Experience Flow**
```
1. User selects video from Photos
2. User enters Trimming View 
3. User can rotate video (90°, 180°, 270°, 0°) using rotate button
4. User sees IMMEDIATE visual feedback of rotation
5. User trims video as needed
6. User presses "Save Trim" → moves to Naming View
7. User sees video with SAME rotation as in Trimming View
8. User enters move name and saves
9. Final video is saved to database with CORRECT rotation applied
```

#### **2. Technical Implementation Requirements**

**Visual Feedback (TrimmerView):**
- ✅ SwiftUI `rotationEffect()` for immediate visual response
- ✅ Smooth animations during rotation
- ✅ Haptic feedback on rotation
- ✅ Accessibility announcements ("Rotated ninety degrees")

**State Management:**
- ✅ Pass rotation information through `AddMoveState.naming`
- ✅ Store rotation as degrees in state management
- ✅ Handle rotation in all view transitions

**Consistency Across Views:**
- ✅ TrimmerView shows rotated video with SwiftUI transforms
- ✅ NameMoveView shows same rotation using SwiftUI transforms  
- ✅ Final exported video has rotation baked in via AVFoundation

**Export Process:**
- ✅ Convert SwiftUI rotation degrees to AVFoundation quarter turns
- ✅ Apply correct `CGAffineTransform` during video composition
- ✅ Handle video dimensions correctly for landscape/portrait

#### **3. Technical Constraints**

**Coordinate Systems:**
- SwiftUI uses different coordinate system than AVFoundation
- Need to translate between `Angle.degrees` and `CGAffineTransform` rotations
- Handle video natural size vs render size calculations

**State Synchronization:**
- SwiftUI `rotationAngle` state must sync with `TrimmerViewModel.rotationQuarterTurns`
- State must persist through view transitions
- Handle edge cases (no rotation, invalid states)

**Performance Considerations:**
- Video composition should be efficient
- Rotation transforms should be calculated once
- Memory management for large video files

#### **4. Edge Cases & Error Handling**

**Video Orientation:**
- Handle videos shot in portrait vs landscape
- Account for device orientation during recording
- Correctly apply transforms based on video's `preferredTransform`

**User Interactions:**
- Handle multiple rotations (cycle through 0°, 90°, 180°, 270°)
- Allow back navigation with rotation preserved
- Handle rotation before/after trimming

**Export Scenarios:**
- No rotation applied (identity transform)
- Single rotation (90°)
- Multiple rotations (180°, 270°)
- Error handling during export process
