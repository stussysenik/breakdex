### **Spec 2.0: Unified & Accessible Loading Experience**

#### **1. Overview & Goals**

**Goal:** Refactor the video loading and trimmer preparation process into a **single, uninterrupted, and accessible loading state**. From the moment a user selects a video to the moment the trimmer is fully interactive, they will see one consistent `LoadingOverlayView` with a continuously running timer and progress bar.

**Why:** "The Athlete" persona perceives the entire process—from selection to trimming—as one atomic "loading" task. Exposing internal state transitions (like `PreviewToTrimTransitionView`) feels like a glitch and breaks the "mechanical watch" precision we're aiming for. This refinement ensures the UI perfectly maps to the user's mental model.

-----

#### **2. Verifiable Elements**

**New/Refined Acceptance Criteria:**

  * **AC1 (Format):** Timer format remains `MM:SS.ss`.
  * **AC2 (Update Frequency):** Timer data updates at a `0.01s` interval.
  * **AC3 (Accessibility - Color):** The color palette for the loading overlay must meet WCAG AA standards for contrast. **Hue alone will not be used** to convey progress.
  * **AC4 (Font):** Monospaced font is maintained.
  * **AC5 (Accuracy):** The final timer value reflects the total time for *both* video loading and trimmer setup.
  * **AC6 (Uninterrupted Experience):** The `LoadingOverlayView` **must remain visible and active** from the moment a video is selected until the `FeatureRichTrimmerView` is fully rendered and interactive. No intermediate transition views shall be visible.
  * **AC7 (Layout Integrity):** The linear progress bar must never visually exceed the bounds of its container, regardless of the device size or progress value.

**Edge Cases:**

  * **EC1 (Ultra-fast Operations):** If the combined load + setup time is less than the `minimumLoadingDisplayTime` (currently 1.2s), the overlay must still display for the minimum duration to ensure a smooth, perceptible transition. `GrepTool(pattern="UX_ENHANCEMENT: Elapsed time", path="48. logs.md")`

-----

#### **3. Refinement: Closing the State Management Gap**

The root cause of the inconsistent UI is that the app transitions from `loadingVideo` to `trimming` *before* the trimmer UI is actually ready. This triggers `AddMoveContainer` to show a temporary transition view (`PreviewToTrimTransitionView`) while `TrimmerViewModel.setupAsync()` runs.

**Solution:** We will introduce a more comprehensive loading phase that encompasses both video download and trimmer setup. The `AddMoveUnifiedState` will orchestrate this entire sequence *before* making the final, single transition to the `.trimming` state, ensuring the destination view is 100% ready.

##### **Step 2: Create a Unified Loading State Logic**

We must prevent the UI from leaving the loading state prematurely. This requires modifying the state machine and the loading completion logic.

  * **Task:** Update the state transition logic in `AddMoveUnifiedState` to wait for trimmer setup to complete *before* exiting the loading state.
  * **File:** `AddMoveUnifiedState.swift`
  * **Command:** `GrepTool(pattern="func handleVideoLoadingCompletion", path="AddMoveUnifiedState.swift")`
  * **Implementation:**
    ```swift
    // Modify the function that handles the completion of the video loading service.
    private func handleVideoLoadingCompletion(with result: Result<VideoAsset, Error>) {
        // ... existing logic to handle success/error from loading ...

        guard let videoAsset = try? result.get() else {
            // Error handling remains the same...
            return
        }
        
        // 🛑 CRITICAL CHANGE: DO NOT TRANSITION TO .trimming YET.
        // Instead, update the loading status and begin trimmer setup.
        
        // Update UI to show the next phase.
        self.loadingStatusMessage = "Preparing Trimmer..."
        
        // Now, set up the trimmer while still in the loading state.
        Task {
            do {
                // This existing function already creates and sets up the TrimmerViewModel.
                try await self.setupTrimmer(with: videoAsset)
                
                // Now that the trimmer is 100% ready, perform the final transition.
                await self.transitionToTrimmingWithDelay()
            } catch {
                // Handle errors from trimmer setup.
                await MainActor.run {
                    self.flowState = .error(message: "Failed to prepare video trimmer.", underlyingError: error.localizedDescription)
                }
            }
        }
    }

    // This is the new final step, replacing the direct transition logic.
    private func transitionToTrimmingWithDelay() async {
        // This logic respects the minimum display time for the loading overlay.
        let elapsedTime = Date().timeIntervalSince(loadingStartTime)
        let minimumDisplayTime = 1.2 // As seen in logs
        
        if elapsedTime < minimumDisplayTime {
            let delay = minimumDisplayTime - elapsedTime
            try? await Task.sleep(for: .seconds(delay))
        }
        
        await MainActor.run {
            self.timerManagementService.stopLoadTimer()
            self.flowState = .trimming
        }
    }
    ```

    ```swift
    struct LoadingOverlayView: View {
        @ObservedObject var unifiedState: AddMoveUnifiedState

        var body: some View {
            ZStack {
                // The main content is now inside this VStack
                VStack(spacing: 12) {
                    // 1. Status Text
                    Text(unifiedState.loadingStatusMessage)
                        .font(.headline)
                        .fontWeight(.semibold)
                        .foregroundColor(DesignSystem.Colors.textPrimary)
                        .fixedSize(horizontal: false, vertical: true) // Prevents text wrapping from pushing layout

                    // 2. Progress Bar
                    ProgressView(value: unifiedState.loadingProgress)
                        // Use the high-contrast accent color
                        .progressViewStyle(LinearProgressViewStyle(tint: DesignSystem.Colors.accentWhite))
                        .padding(.horizontal, 24) // Padding inside the bar's space

                    // 3. Percentage and Timer Row
                    HStack {
                        Text("\(Int(unifiedState.loadingProgress * 100))%")
                            .font(.ibmPlexMono(size: 14, weight: .regular))
                            .foregroundColor(DesignSystem.Colors.accentWhite)
                        
                        Spacer()
                        
                        HStack(spacing: 4) {
                            Image(systemName: "clock")
                                .font(.caption2)
                            Text(formatTime(unifiedState.loadElapsedTime))
                                .font(.system(.caption, design: .monospaced))
                        }
                        .foregroundColor(DesignSystem.Colors.textSecondary)
                    }
                    .padding(.horizontal, 24)
                }
                .padding(.vertical, 24)
                .background(
                    // Use the primary brand blue for the background
                    DesignSystem.Colors.primaryBlue
                        .opacity(0.95)
                        .background(.ultraThinMaterial) // Maintain a subtle material effect behind the color
                )
                .cornerRadius(20)
                .shadow(color: .black.opacity(0.4), radius: 25, y: 10)
                .padding(.horizontal, 32) // Outer padding for the entire card
            }
            .frame(maxWidth: .infinity, maxHeight: .infinity)
            .background(Color.black.opacity(0.5).ignoresSafeArea()) // Dimming background
            .animation(.easeInOut, value: unifiedState.loadingProgress)
            .transition(.opacity)
        }

        private func formatTime(_ seconds: TimeInterval) -> String {
            let minutes = Int(seconds) / 60
            let secs = Int(seconds) % 60
            let centiseconds = Int((seconds.truncatingRemainder(dividingBy: 1)) * 100)
            return String(format: "%02d:%02d.%02d", minutes, secs, centiseconds)
        }
    }
    ```
