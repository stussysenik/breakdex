## Spec: Fix Video Loading Hang and Logical Stall

  * **Version**: 1.0
  * **Date**: October 5, 2025
  * **Author**: Gemini

### 1\. Overview ("What" and "Why")

#### **1.1. Goal**

This specification outlines the work required to resolve a critical bug where the video loading process hangs the application and, even without the hang, is logically incapable of completion. The successful implementation will ensure that selecting a video results in a smooth, reliable, and complete transition from the loading screen to the trimming screen.

#### **1.2. User Persona & Journey**

  * **Persona**: "The Athlete". This user values precision, reliability, and a frictionless experience. They expect the app to function like a high-quality "mechanical watch"—flawlessly and without error.
  * **User Journey**:
    1.  User taps to add a new move and selects a video from the Photos picker.
    2.  The app displays a loading overlay with a progress bar and an elapsed timer.
    3.  **FAILURE POINT**: The app currently hangs, becoming unresponsive, and is terminated by the system. If it didn't hang, it would get stuck at 75% progress indefinitely.
    4.  **Expected Outcome**: The progress bar smoothly advances to 100%, and the app automatically transitions to the video trimming interface.

#### **1.3. Business Value**

Resolving this bug is critical for user retention and trust. A hanging or failing core feature leads to user frustration, uninstalls, and negative reviews. A successful fix will unblock the primary value proposition of the "Add Move" feature, directly impacting user engagement and the app's reputation for quality.

#### **1.4. Non-Goals**

  * A complete architectural redesign of the `UnifiedProgressEngine` or `AddMoveUnifiedState`.
  * Replacing the `TimerManagementService`.
  * Altering the visual design of the `LoadingOverlayView`.
  * Implementing the *real* video loading logic; this spec focuses on fixing the hang and the existing **simulated** loading flow to prove the system's viability.

-----

### 2\. Verifiable Elements

#### **2.1. Acceptance Criteria**

1.  **AC1: Immediate & Clean State**: When a video is selected, the `LoadingOverlayView` must appear instantly with progress displayed at exactly "0%" and the elapsed time at "00:00.00". There must be no flash of stale data (e.g., a previous 100% value).
2.  **AC2: Main Thread Responsiveness**: The application UI, including the animations on the `LoadingOverlayView`, must remain fluid and responsive throughout the entire loading process. The main thread must not be blocked.
3.  **AC3: Logical Completion**: The simulated loading process must progress deterministically and reach exactly 100%.
4.  **AC4: Successful Transition**: Upon reaching 100%, the application must automatically and smoothly transition from the `loadingVideo` state to the `trimming` state.
5.  **AC5: Performance**: The debug console must not be flooded with log messages. Timer-related logging during the loading phase should be minimal and not impact performance.
6.  **AC6: Minimum Display Time**: To prevent jarring UI flashes on fast loads, the `LoadingOverlayView` must remain visible for a minimum of 1.2 seconds, even if the underlying process finishes faster.

#### **2.2. Key Metrics**

  * **Main Thread Hangs**: `0`. The iOS watchdog timer must never terminate the app during the loading flow.
  * **P95 UI Reset Latency**: `< 100ms`. The time from tapping a video to the `LoadingOverlayView` appearing in its clean initial state must be under 100ms for 95% of users.
  * **Transition Success Rate**: `> 99.9%`. The end-to-end flow from video selection to the appearance of the trimming screen must succeed reliably.
  * **Log Volume**: Timer-related log entries during loading must be reduced by \>99%.

#### **2.3. Edge Cases to Consider**

  * **Rapid Re-selection**: If a user selects Video A, and then immediately selects Video B while A is loading, the system must gracefully cancel the first operation and cleanly start the second without state corruption. The existing `ATOMIC_RESET` logic should handle this, but its success is paramount.
  * **Fast Load**: If loading finishes in under the minimum display time (e.g., 0.5s), the system must wait the remainder of the duration before transitioning to trimming, ensuring a smooth user experience.
