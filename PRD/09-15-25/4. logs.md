RESEARCH:

Fast 1080p/4K playback on first load comes from preloading the asset’s required keys and only starting once it’s ready, then reusing the same player to avoid setup costs between items. For smooth switching and revisits, pre-create the next items, keep a small cache of recent assets/items, and prefer HLS so adaptive bitrate and offline downloads make new and already-seen videos feel instant. [1][2][3][4][5]

Preload critical properties with async loading (for example, try await asset.load(.playable, .tracks, .duration)) so the first play doesn’t block on the main thread. [1][2]
Reuse a single AVPlayer and swap items with replaceCurrentItem(with:) instead of creating new players, which minimizes layer churn and reduces hitches during video changes. [3][4][7]
To make switches feel instant, pre-create upcoming AVPlayerItems and call preroll(atRate:) to buffer before a user navigates to them; for sequences, use AVQueuePlayer and author HLS for gapless transitions. [8][5]
Tune buffering: enable or disable automaticallyWaitsToMinimizeStalling based on startup vs. stability goals, and set preferredForwardBufferDuration to control how aggressively the player pre-buffers. [9][10]
For streaming, prefer **HLS**; cap bandwidth or resolution when needed using preferredPeakBitRate and preferredMaximumResolution so 4K doesn’t overwhelm networks or devices. [11][12][13]
Make “already accessed” videos instant by downloading HLS for offline with AVAssetDownloadTask and checking AVAssetCache.isPlayableOffline before play. [6][14][15]
For Photo Library content, request a player item directly with PHImageManager.requestPlayerItem and “preheat” with PHCachingImageManager to accelerate first view and quick revisits. [16][17][18]
Keep a tiny in-memory LRU of AVURLAsset/AVPlayerItem and reuse the same AVAsset when possible so AVFoundation reuses fetched media data and avoids redundant work for revisits. [3][19]
Generate thumbnails asynchronously with AVAssetImageGenerator, applying the track transform and a maximum size to avoid UI stalls while browsing. [20][21][22]
Profile and iterate: watch timeControlStatus/reasonForWaitingToPlay for startup delays and use a telemetry SDK to monitor rebuffering, bitrate shifts, and startup time in production. [23][24]
