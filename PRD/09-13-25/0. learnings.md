  XCode-Generated Files vs Manual File Creation:

  When XCode creates files:
  - ✅ Automatically adds to current target
  - ✅ Sets correct build phases
  - ✅ Handles folder references
  - ✅ Manages file dependencies

  When you manually create files:
  - ❌ Just creates the file on disk
  - ❌ No target membership
  - ❌ No build phase inclusion
  - ❌ Invisible to compiler

  Common Scenarios Where This Happens:

  1. CLI/External Editors - Files created in VS Code, terminal, or other editors
  2. File copying - Copying files from another project
  3. Git operations - Files pulled from repository that weren't added to XCode project
  4. Script generation - Files created by build scripts or code generators

  The Technical Reason:
  XCode projects have two layers:
  - File system - where files actually exist on disk
  - Project metadata - .pbxproj file that defines what gets built

  When you create a file outside XCode, it only exists in the file system layer. XCode's build system only looks at the project metadata layer.

  How to Check:
  In XCode, select the file → File Inspector → "Target Membership" section - if unchecked, it won't compile.

  Pro Tip: Always create files through XCode interface (File → New → File...) unless you specifically need to manage them externally and manually add them to targets later.

  Great question! Core Data file target membership is a common source of confusion. Here's the breakdown:

  Files That SHOULD Have Target Membership:

  1. .xcdatamodeld files ✅
    - The Core Data model definition
    - Must be included so the compiler generates NSManagedObject subclasses
    - Without this, you'll get "class not found" errors
  2. Custom NSManagedObject subclasses ✅
    - If you create custom entity classes (e.g., Move.swift, Session.swift)
    - These are your actual data model objects

  Files That Should NOT Have Target Membership:

  1. .xcdatamodeld/contents ❌
    - The internal XML file within the model package
    - XCode handles this automatically - adding it manually causes conflicts
  2. Auto-generated classes ❌
    - Files like Move+CoreDataClass.swift, Move+CoreDataProperties.swift
    - These are generated by XCode from the model
    - Including them causes "duplicate symbol" errors
  3. .sqlite database files ❌
    - The actual database files created at runtime
    - These are data files, not source code
  4. .sqlite-wal, .sqlite-shm ❌
    - SQLite journal files
    - Runtime artifacts, not build assets

  Common Errors When Wrong Files Are Included:

  1. "Duplicate symbol" linker errors - Usually from including auto-generated files
  2. "No such file" errors - From including internal model files
  3. Build phase conflicts - Multiple sources trying to process the same file

  Proper Setup:
  - Only the .xcdatamodeld package (not its contents)
  - Only your custom entity classes (if any)
  - Never the auto-generated Core Data files

  Check Rule: If you didn't write the code yourself and XCode generated it, it probably shouldn't have target membership.

  Here's exactly which Core Data files should have target membership:

  ✅ SHOULD HAVE TARGET MEMBERSHIP:

  1. Model Definition:
  - BreakingFlashcards.xcdatamodeld (the package folder)

  2. Custom Core Data Stack:
  - Persistence.swift (your custom Core Data setup)

  ❌ SHOULD NOT HAVE TARGET MEMBERSHIP:

  Auto-Generated Files (remove these):
  - Move+CoreDataClass.swift
  - Move+CoreDataProperties.swift
  - Review+CoreDataClass.swift
  - Review+CoreDataProperties.swift
  - Combo+CoreDataClass.swift
  - Combo+CoreDataProperties.swift
  - ComboMove+CoreDataClass.swift
  - ComboMove+CoreDataProperties.swift

  Internal Model Files:
  - BreakingFlashcards.xcdatamodeld/.xccurrentversion
  - BreakingFlashcards.xcdatamodeld/BreakingFlashcards.xcdatamodel (internal contents)

  Why This Causes Errors:

  The Problem: XCode auto-generates those *CoreData* files from your .xcdatamodeld. When you manually include them in targets, you get:
  - Duplicate symbol errors - Both XCode's generated version and your included version try to compile
  - Class conflicts - Same class defined multiple times
  - Build phase issues - Multiple files competing for the same compilation

  The Fix: Remove all the auto-generated *CoreData* files from target membership. XCode will generate them automatically during build from your .xcdatamodeld.

  Quick Test: Remove target membership from all files in the CoreData/ directory except Persistence.swift, and only keep BreakingFlashcards.xcdatamodeld (the folder) in targets.
