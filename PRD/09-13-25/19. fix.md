A clean, long-term fix is to eliminate the PlayerStateMonitor retain cycle and harden its lifecycle: make all outbound callbacks and observer/closure references weak, centralize cancellation/removal for AVPlayer, NotificationCenter, KVO, Combine, and Task, and ensure deinit never creates work or registrations. [1][2][3][4][5]

### Goals
- Break the **retain cycle** so PlayerStateMonitor deallocates deterministically when VideoPlayerViewModel deinitializes, with no new work or registrations performed during deallocation. [1][2]
- Demonstrate no leak across repeated start/stop cycles using Xcode’s Memory Graph and Instruments/Leaks, with stable object counts and no purple “suspicious cycle” markers. [10][2]

### Architecture
- Ownership model: VideoPlayerViewModel strongly owns PlayerStateMonitor; PlayerStateMonitor only keeps weak back-references (delegates, closures) to its owner and UI; no strong cycles are permitted. [1][2]
- Lifecycle API: PlayerStateMonitor exposes start(player:) and stop(), where start registers observers and stop synchronously tears everything down; deinit must only call a synchronous stop() if necessary and must not create tasks, observers, or closures. [1][2]
- Concurrency: Track every Task started by the monitor, cancel them in stop(), and use cooperative cancellation (Task.checkCancellation / Task.isCancelled) or withTaskCancellationHandler to clean up non-cooperative work. [9][11][12]

### Observers and tokens
- AVPlayer time and boundary observers: hold the returned token and remove it via removeTimeObserver(_:) during stop(); releasing the token without removal is not sufficient per Apple docs. [3][4]
- NotificationCenter block-based observers: capture the returned NSObjectProtocol tokens in an array and remove them in stop(); block-based observers still need manual removal. [6][5][13]
- KVO (Swift key-path): keep NSKeyValueObservation tokens; they auto-invalidate on deinit, but use [weak self] in the KVO closure to avoid capturing self strongly. [7][14][15]
- Combine: store AnyCancellable in a Set and cancel them in stop() (store(in:) is the standard pattern); also use [weak self] inside sink/assign closures when self could be retained. [8][16][15]
- Delegates: protocol-typed delegates on the monitor must be weak to prevent cycles. [2]

### Coding guidelines
- Closures: default to [weak self] and conditionally promote to strong via guard let self = self else { return } when needed; use unowned only if lifetime relationships guarantee non-nil access. [15][17]
- Deinitialization: deinit must not allocate, register, or capture self in any new closure; limit deinit to synchronous, idempotent cleanup (e.g., calling stop()) so no new strong references are formed during teardown. [1][2]
- AVPlayer capture: when adding periodic/boundary time observers, capture [weak self] in the block to avoid holding the monitor strongly through the AVPlayer’s observer callback. [3][4]
- NotificationCenter capture: block-based observers retain their blocks; always use [weak self] inside the block to prevent the notification center retaining the monitor through the closure. [6][13]

### Reference implementation
- The following sketch shows explicit registration and teardown by the monitor with token tracking and weak captures. [3][4][6][5][7]

```swift
final class PlayerStateMonitor {
    // Tokens
    private var timeObserver: Any?
    private var boundaryObserver: Any?
    private var notifObservers: [NSObjectProtocol] = []
    private var kvoObservers: [NSKeyValueObservation] = []
    private var cancellables = Set<AnyCancellable>()
    private var tasks = [Task<Void, Never>]()
    
    // Weak outbound references
    weak var delegate: PlayerStateMonitorDelegate?
    
    // Lifecycle
    func start(player: AVPlayer) {
        // AVPlayer periodic observer
        timeObserver = player.addPeriodicTimeObserver(forInterval: CMTime(seconds: 0.25, preferredTimescale: 600), queue: .main) { [weak self] _ in
            guard let self else { return }
            self.tick()
        }
        
        // NotificationCenter example
        let token = NotificationCenter.default.addObserver(forName: .AVPlayerItemDidPlayToEndTime, object: nil, queue: .main) { [weak self] _ in
            self?.delegate?.didFinish()
        }
        notifObservers.append(token)
        
        // KVO example
        let kvo = player.observe(\.timeControlStatus, options: [.initial, .new]) { [weak self] _, _ in
            self?.handleStatus()
        }
        kvoObservers.append(kvo)
        
        // Combine example
        somePublisher
            .sink { [weak self] _ in self?.handleEvent() }
            .store(in: &cancellables)
        
        // Task example
        tasks.append(Task { [weak self] in
            guard let self else { return }
            await self.pollLoop()
        })
    }
    
    func stop() {
        // AVPlayer observers: require explicit removal
        if let obs = timeObserver, let player = currentPlayer {
            player.removeTimeObserver(obs)
            timeObserver = nil
        }
        if let obs = boundaryObserver, let player = currentPlayer {
            player.removeTimeObserver(obs)
            boundaryObserver = nil
        }
        
        // NotificationCenter
        for token in notifObservers {
            NotificationCenter.default.removeObserver(token)
        }
        notifObservers.removeAll()
        
        // KVO (auto invalidates on deinit, but drop references now)
        kvoObservers.removeAll()
        
        // Combine
        cancellables.forEach { $0.cancel() }
        cancellables.removeAll()
        
        // Tasks
        tasks.forEach { $0.cancel() }
        tasks.removeAll()
    }
    
    deinit {
        stop()
    }
}
```

- addPeriodicTimeObserver requires pairing with removeTimeObserver and weakly capturing self to prevent AVPlayer from retaining the monitor. [3][4]
- NotificationCenter block-based observers require removal; storing tokens and removing in stop() avoids leaks and cycles. [6][5][13]
- NSKeyValueObservation invalidates on deinit, but weakly capturing self in closures is still required to avoid retaining the monitor. [7][14][15]
- Combine subscriptions should be stored and canceled; avoid capturing self strongly inside sinks. [8][16][15]
- Tasks must be tracked and canceled cooperatively to avoid dangling async work holding resources. [9][11][12]

### Migration steps
- Add stop() to PlayerStateMonitor, refactor all registrations into start() and all removals into stop(), and ensure deinit calls stop() without introducing any new allocations or registrations. [1][2]
- Replace any strong delegate or callback fields with weak references, and add [weak self] capture lists to all closures registered with AVPlayer, NotificationCenter, KVO, Combine, and Tasks. [15][3][6][7][8]
- Verify AVPlayer time/boundary observers are removed explicitly, and NotificationCenter block-based observers are removed using stored tokens. [3][4][6][5][13]

### Pitfalls to avoid
- Avoid performing asynchronous work or registering observers in deinit, as this can create a new strong reference path and recreate the leak during teardown. [1][2]
- Do not rely on token deallocation alone for AVPlayer observers; removal is required to stop AVPlayer from retaining the callback. [3][4]
- Remember that block-based NotificationCenter observers must be unregistered; relying on automatic removal applies only to selector-based observers. [6][5][13]
