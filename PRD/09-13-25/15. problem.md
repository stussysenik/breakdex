  4. Root Cause Analysis:

  The problem is in your view lifecycle management. When transitioning from preview to trimming state:

  1. SwiftUI evaluates the new view hierarchy
  2. The old CUSTOM_VIDEO_PLAYER gets onDisappear called
  3. It aggressively tears down all player resources
  4. The new trimmer view tries to use what should be the cached player
  5. But the cache now contains a dead reference to a destroyed player

  You need to implement smarter lifecycle management where:

  - Don't tear down the player during view transitions
  - Keep the player alive during the state change
  - Only clean up resources when actually leaving the entire flow
  - Ensure the cache contains valid, active player instances
