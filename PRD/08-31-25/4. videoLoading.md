## **Feature Doc: Performant Video Loading & Processing**

* **Author**: Gemini
* **Date**: August 31, 2025
* **Status**: Proposed

### ## 1. Overview & Goal

**Problem:** The application's video import process can feel slow and unresponsive, especially for videos stored in iCloud. Users lack clear feedback on the loading progress, leading to a poor user experience and potential abandonment of the flow.

**Goal:** Implement a highly performant, responsive, and informative video loading system. This system will provide users with immediate feedback, clear status updates (including ETAs), and handle all video types (local and cloud-based) gracefully without blocking the UI.

**Key Principles:**

* **Centralized Logic:** A single, dedicated service should manage all video loading and caching to ensure consistency and maintainability.
* **Proactive Feedback:** The UI must respond instantly to user actions and provide continuous, informative updates throughout the loading process.
* **Robust State Management:** The system will rely on a clear, granular state machine to drive the UI, ensuring the user always sees a relevant and accurate view.
* **Asynchronous Operations:** All intensive work (file I/O, video processing) must be performed on background threads to keep the UI smooth and interactive.

### ## 2. Core Components & Architecture

#### ### 2.1. MediaManager (Singleton Service)

[cite_start]This will be a new singleton class (`MediaManager`) responsible for the entire video asset lifecycle[cite: 50].

* **Purpose:** To act as the single source of truth for fetching, processing, and caching video assets.
* **Key Responsibilities:**
    * [cite_start]**Asynchronous Loading:** It will expose a `loadVideo(from: URL)` method that immediately begins processing on a background queue[cite: 54]. [cite_start]This method will load essential asset properties (`"playable"`, `"duration"`, `"tracks"`) asynchronously[cite: 61].
    * [cite_start]**Caching:** It will implement an `NSCache` to store `AVAsset` objects[cite: 50]. [cite_start]This prevents re-processing of the same video, providing instantaneous loads for recently used assets[cite: 61]. [cite_start]The cache should have sensible limits for count (e.g., 10) and total cost (e.g., 100MB) to manage memory[cite: 54].
    * [cite_start]**Status Publishing:** It will use a `@Published` property to broadcast its current status, allowing any part of the app to observe the loading state in real-time[cite: 50].

#### ### 2.2. State Machine

A two-level state machine will manage the loading flow.

* [cite_start]**`MediaManager.MediaStatus` (Low-Level State):** This enum within the `MediaManager` defines the core processing states[cite: 50]:
    * `.idle`: No operation is active.
    * `.loading(progress: Double, status: String, eta: String?)`: An asset is being downloaded or processed. It carries the progress, a user-facing status message, and an estimated time of arrival.
    * `.loaded(asset: AVAsset, url: URL)`: The asset is ready for use.
    * `.failed(error: Error)`: An error occurred.

* **`AddMoveState` (High-Level UI State):** This enum in the view layer drives the UI. [cite_start]It's more descriptive of the user's journey and is derived from the `MediaManager`'s status[cite: 77]:
    * `.ready`: The initial state, ready for user input.
    * [cite_start]`.downloadingFromiCloud(...)`: Actively downloading a video from iCloud, showing specific progress[cite: 104].
    * [cite_start]`.loadingVideo(...)`: Processing a local video file, showing simulated progress[cite: 121].
    * [cite_start]`.previewing(asset: AVAsset, url: URL)`: The video is loaded and ready for user preview/trimming[cite: 80].
    * [cite_start]`.error(message: String)`: A user-facing error screen[cite: 80].

### ## 3. User Experience (UX) Flow

#### ### 3.1. Immediate Feedback & ETA

The key to the UX is eliminating dead air. The moment a user selects a video, the app must provide feedback.

1.  [cite_start]**Instant Transition:** The UI immediately transitions to a loading state (`.loadingVideo` or `.downloadingFromiCloud`)[cite: 54].
2.  [cite_start]**Progress Simulation:** For local processing, where a determinate progress is unavailable, a `Timer` will be used to drive a progress bar forward[cite: 71]. This provides a sense of activity and is capped at 90% until the load is complete.
3.  [cite_start]**ETA Calculation:** A utility function (`calculateETA`) will estimate the remaining time based on the elapsed time and current progress[cite: 76]. This text ("ETA: ~15s") will be displayed prominently, managing user expectations.

#### ### 3.2. Robust iCloud Handling

The video picker must be enhanced to transparently handle videos stored in iCloud.

* [cite_start]**Real Progress Tracking:** The implementation must use `PHAssetResourceManager` and its `progressHandler` to receive real download progress updates from the system when a cloud asset is chosen[cite: 208].
* [cite_start]**Dedicated UI:** The progress, start time, and status will be passed back to the main view, which will enter the dedicated `.downloadingFromiCloud` state[cite: 104]. [cite_start]This state should feature a distinct UI, such as a cloud icon and a circular progress indicator, to clearly communicate what is happening[cite: 104].

### ## 4. Implementation Details & Requirements

* [cite_start]**Video Picker:** The `VideoPickerSheet` must be refactored to use `PHAssetResourceManager.default().writeData(...)` for fetching assets[cite: 208]. [cite_start]It should use `@Binding` properties to report download progress, status, and start time to its parent view[cite: 201].
* **View Logic:**
    * [cite_start]The primary view (`AddMoveView`) must subscribe to the `MediaManager`'s status updates using `.onReceive(mediaManager.$status)`[cite: 177].
    * [cite_start]Upon receiving a new `MediaStatus`, the view will update its own `AddMoveState` to render the correct UI[cite: 177].
    * [cite_start]The view is responsible for calling `mediaManager.loadVideo(from: url)` once a video URL is obtained from the picker[cite: 188].
* **Save Process:** The final save operation must also be robust. [cite_start]It should be performed on a background queue, copy the video file to a persistent location in the app's document directory, and then update the Core Data entry on the main thread[cite: 189, 193]. This prevents data corruption and keeps the UI responsive.

### ## 5. Success Metrics

* **Performance:** Perceived load time for all videos is under 2 seconds (excluding network download time).
* **Responsiveness:** The UI maintains 60 FPS with no stutters or freezes during the entire import and processing flow.
* **User Engagement:** A measurable reduction in the number of users who abandon the video import flow.
* **Stability:** Zero crashes related to file handling, memory pressure from large videos, or threading issues.
