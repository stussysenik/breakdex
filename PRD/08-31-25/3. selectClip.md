The flow is Select Clip → loading with progress → preview choices (Change/Use/Trim) → precise trim → name move → save to Core Data + media index → success banner with return to Add tab, with errors surfaced via alerts and logs at each step.[1][2][3][4]
This preserves the exact Select a Clip layout and adds a sturdy, state-machine driven path from pick to persisted move.[2][1]

## Start state
- Screen: black background, centered blue “Select a Clip” button, gray “Supports .mp4, .mov files” text, and “Import / Export” row below, with the Add tab highlighted in the bottom bar.[1]
- Tapping Import / Export opens the existing import/export sheet; closing returns to this screen without altering state.[1]

## Pick a clip
- Tap Select a Clip to open PhotosPicker restricted to videos; allow iCloud-backed items and begin download automatically if needed.[2][1]
- While the item provider loads or iCloud downloads, show a linear progress bar with status text (e.g., “Downloading from iCloud…”), keeping the Add screen visible until the asset is ready.[2][1]

## Loading state
- When a selection is made, transition to state: loading(progress, status) and stream PhotosPicker/ItemProvider progress to the bar; if the user cancels, pop back to the ready state with no side effects.[1][2]
- After data arrives, build AVAsset from a local URL (download to a temp/app sandbox if needed) and advance to previewing(asset, url).[2][1]

## Preview choices
- Present a full-width video preview with three primary actions: Change Video, Use Original, and Trim Video.[1]
- Change Video returns to the Select a Clip screen; Use Original advances directly to naming(url); Trim Video pushes the trimming view with the current asset.[1]

## Trim video
- Show a precise trimmer: timeline thumbnails, draggable in/out handles, current-time scrubber, and play/pause, with Back and Save Trim buttons.[3][1]
- On Save Trim, export with AVAssetExportSession using a safe preset, write to a new file URL, and go to naming(trimmedURL); display an export progress bar and allow cancel.[3][1]

## Name the move
- Present Name Move screen with text field, optional state tag (defaults to NEW), and Save button; Back returns to Preview/Trim without losing the generated file.[1]
- On Save, validate a non-empty name, then enter saving and disable inputs to prevent duplicate taps.[1]

## Persist and index
- Create Move in Core Data with id, name, createdAt, learningState, and a reference payload to the file path (not raw video data) for performance.[4][1]
- Upsert into MediaIndexManager with file URL, size, and hash to maintain integrity and fast relinking.[1]

## Success and return
- After persistence completes, show the existing “Your move has been added” success view/sheet and return to the Add tab context; the Add screen remains accessible for adding another clip.[1]
- If the user dismisses success, keep navigation in the Add flow root (Select a Clip) for the quickest repeat action.[1]

## Errors and recovery
- Surface user-facing alerts for iCloud unavailable, permission denied, unsupported format, export cancelled, out-of-space, or file write failures; each alert offers Retry or Choose Different Video.[3][2][1]
- Log errors with os.Logger, include underlying error codes, and safely roll back intermediate files and Core Data changes to prevent orphaned entries.[4][1]
