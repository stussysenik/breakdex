# 🔧 **BreakDex Architecture: 10 Deterministic Axioms + Codebase Impact**

## **Axiom 1: Photos Album as Primary Storage**
**Implementation**: Use `PHAssetCollection` API to create/manage "BreakDex" album
**Codebase Impact**: 
- **NEW FILE**: `BreakDexAlbumManager.swift` - Singleton for album operations
- **MODIFY**: `AddMoveViewModel.swift` - Replace file copying with album copying
- **JUSTIFICATION**: Single source of truth for video storage, user-visible and controllable

## **Axiom 2: Core Data Stores Only Metadata**  
**Implementation**: Store Photos localIdentifier, trim ranges, learning data
**Codebase Impact**:
- **MODIFY**: `Move+CoreDataProperties.swift` - Add `photosIdentifier`, `trimStartTime`, `trimEndTime` fields
- **MODIFY**: `Combo+CoreDataProperties.swift` - Reference moves by Photos ID
- **JUSTIFICATION**: Lightweight app footprint, Photos handles actual video storage

## **Axiom 3: Streaming Playback with Trim Application**
**Implementation**: Use `PHAssetResourceManager` for streaming + `AVPlayer` time ranges
**Codebase Impact**:
- **MODIFY**: `CustomVideoPlayerView.swift` - Add trim range application via `AVPlayerItem.timeRange`
- **JUSTIFICATION**: No local video copies needed, real-time trim application

## **Axiom 4: Photos Permission & Album Health Checks**
**Implementation**: Check permissions + album existence on app launch
**Codebase Impact**:
- **NEW FILE**: `PhotosPermissionManager.swift` - Handle permission requests and status
- **MODIFY**: `BreakingFlashcardsApp.swift` - Add album health check in `onAppear`
- **JUSTIFICATION**: Proactive error prevention, user permission management

## **Axiom 5: Video Import via Album Copy**
**Implementation**: Copy selected video to BreakDex album, store metadata
**Codebase Impact**:
- **MODIFY**: `AddMoveViewModel.swift` - Use `PHAssetChangeRequest` for album operations
- **JUSTIFICATION**: Reliable video reference system, user can see/manage content

## **Axiom 6: Error Handling for Missing Videos**
**Implementation**: Detect missing Photos IDs, provide relink UI
**Codebase Impact**:
- **NEW FILE**: `VideoRelinkManager.swift` - Handle missing video scenarios
- **MODIFY**: `CustomVideoPlayerView.swift` - Add error state for missing videos
- **JUSTIFICATION**: Graceful degradation when videos are deleted/moved

## **Axiom 7: Learning System Integration**
**Implementation**: Review scheduling based on stored metadata only
**Codebase Impact**:
- **MODIFY**: `ReviewView.swift` - Load move metadata, stream videos on demand
- **MODIFY**: `FlashcardsReviewView.swift` - Same approach for practice sessions
- **JUSTIFICATION**: Core business logic remains metadata-driven

## **Axiom 8: Album Content Synchronization**
**Implementation**: Periodic sync between Core Data and BreakDex contents
**Codebase Impact**:
- **NEW FILE**: `AlbumSyncManager.swift` - Compare stored IDs with album contents
- **JUSTIFICATION**: Detect orphaned metadata, maintain data integrity

## **Axiom 9: Consolidate Media Management Files**
**Implementation**: Remove file-based media management
**Codebase Impact**:
- **DELETE**: `MediaManager.swift` - No longer needed (Photos handles caching)
- **DELETE**: `MediaIndexManager.swift` - No longer needed (Photos provides indexing)
- **DELETE**: `ThumbnailGenerator.swift` - Use Photos thumbnails instead
- **JUSTIFICATION**: Eliminates unnecessary abstraction layer

## **Axiom 10: Streamline Video Processing**
**Implementation**: Remove local video processing, use Photos APIs
**Codebase Impact**:
- **MODIFY**: `TrimmerViewModel.swift` - Store trim ranges only, no file export
- **MODIFY**: `PreciseVideoTrimmerView.swift` - Preview with Photos streaming
- **JUSTIFICATION**: Simplifies architecture, leverages Photos' video processing

# 🔄 **Import/Export + Re-link Integration in BreakDex System**

## 🎯 **New Paradigm: Metadata + Album Recovery**

### **Export Functionality (BreakDex-Native)**

**What Gets Exported:**
- ✅ Core Data metadata (move names, learning states, trim ranges)
- ✅ Photos localIdentifiers for each move
- ✅ Learning progress and review history
- ✅ BreakDex album reference (for cross-device import)

**Export Process:**
```swift
struct LearningLibraryExport: Codable {
    let moves: [MoveExport]
    let combos: [ComboExport] 
    let breakDexAlbumIdentifier: String? // Photos album ID
    let exportDate: Date
}

struct MoveExport: Codable {
    let name: String
    let photosIdentifier: String  // Key for re-linking
    let trimStartTime: Double?
    let trimEndTime: Double?
    let learningState: String
    let reviewHistory: [ReviewExport]
}
```

### **Import Functionality (Smart Recovery)**

**Import Process:**
1. **Parse JSON** → Extract metadata and Photos IDs
2. **Check BreakDex** → See which videos exist in current album
3. **Match & Create** → Create moves for found videos
4. **Re-link Queue** → Queue missing videos for user recovery

**Smart Matching Logic:**
```swift
// For each imported move
if videoExistsInBreakDex(photosIdentifier) {
    // ✅ Direct match - create move
    createMoveFromImport(moveData)
} else {
    // 🔄 Needs re-linking
    addToRelinkQueue(moveData)
}
```

### **Re-link Integration (Recovery Hub)**

**Re-link Becomes the Recovery Engine:**
- **Single UI** for all missing video scenarios
- **Import-time recovery** for bulk operations
- **Runtime recovery** for individual missing videos
- **Cross-device recovery** when importing on new devices

**Re-link Flow:**
```
Import JSON → Parse Metadata → Check BreakDex → 
├── Found Videos → Auto-create moves ✅
└── Missing Videos → Re-link Queue 📋
    ├── Scan BreakDex for matches 🔍
    ├── User selects replacement 🎯
    ├── Update Photos ID 🔄
    └── Create move ✅
```
