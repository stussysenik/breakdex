Here’s a case‑driven Spec‑Kit update that makes the range slider ultra‑precise and reliably “caught up” with the finger, while removing the bottom‑bar gray and keeping the UI minimal. [1]

## Direct answer
Make the control precise by separating finger tracking from preview seeking, sampling touches at high fidelity, quantizing to frame‑exact times, and queuing seeks so the UI never waits on the player. [2][3]
Use large, Apple‑blue handles with ≥44 pt hit targets, true‑black actions with native button styles, and enforce a one‑frame minimum gap so dots never touch. [4][5]

## Specify

- Intent: Deliver a two‑handle trimmer that tracks the finger at display‑rate, snaps to exact frame boundaries, and never visually lags behind due to player seeks or animations. [2][3]
- Non‑negotiables: No playhead, no implicit animations on drag‑mutated values, and no gray action background; adopt pure black with native prominent/borderless button styles. [6][4]

## First‑principles model

- Decouple concerns: 1) Input loop moves handles every touch sample; 2) Quantizer maps x→time→frame; 3) Preview loop coalesces/sequences seeks; 4) Export uses the quantized range. [2][3]
- The UI must never block on media I/O; handle positions are rendered from input state, while preview updates trail behind via a queued seek pipeline. [3][7]

## Research‑driven practices applied

- High‑fidelity input: Prefer coalesced touches via a UIKit pan recognizer bridge or equivalent to get >60 Hz sample streams on supported devices. [2][8]
- Drag stability: Avoid implicit/global animations on values updated by DragGesture to prevent “invalid sample AnimatablePair” and visual lag. [6][9]
- Smooth scrubbing: Queue seeks and wait for completion rather than firing seek calls every tick, or use frame‑stepping/image generation when ultra‑low latency is required. [3][7][10]
- Frame precision: Quantize to the asset time base using CMTime with a suitable timescale (e.g., 600 for video), or the exact frame duration when known. [5][11]
- Precision interaction: Support slowed/vertical scrubbing to change sensitivity within one continuous gesture when needed. [12][13]
- Haptics: Play light ticks on frame detents and soft taps on grab/release to confirm precision without visual motion. [14][4]
- Color and layout: Use true black background for the action row, systemBlue for in‑range track/handles, and 44×44 pt touch targets with consistent spacing tokens. [4][15]

## Experience

- Visual: Thin track, in‑range segment in systemBlue, two circular handles with halo hit‑zones, and Start/Duration/End readouts below; no playhead or thumbnails. [4][1]
- Interaction: Drag either handle to scrub; handle motion is immediate and exact, while the preview updates via the queued seek loop so dots always “lead” the video. [3][2]
- Precision: Slower/vertical scrubbing dynamically increases temporal resolution for single‑frame selection without mode switches. [12][13]
- Bottom actions: Remove gray bar and render buttons directly on black; primary Save uses borderedProminent+tint(.blue), secondary actions are borderless with subtle tint. [4][15]

## Functional requirements

- FR1 Finger tracking: Sample at display cadence using coalesced touches or a high‑rate pan bridge, updating handle X each sample on the main thread. [2][8]
- FR2 Quantization: Map handle X to normalized progress, multiply by duration, then snap to nearest frame time using CMTime with asset‑appropriate timescale or frame duration. [5][11]
- FR3 Seek queue: Maintain a single in‑flight seek; on drag, set latestTargetTime and only issue the next seek in the prior completion handler with zero or small tolerances. [3][16]
- FR4 Alternative preview: If repeated seeks are still sluggish, use AVPlayerItem.stepByCount or AVAssetImageGenerator for instantaneous frame images during drag. [7][10]
- FR5 No implicit animations: Disable implicit animations on properties driven by drag; allow only opacity fades for transient labels if desired. [6][9]
- FR6 Haptics: Generate a tick once per snapped frame change and a light impact on drag begin/end. [14][4]
- FR7 Bounds: Start initializes to 0, End to duration; enforce a minimum gap of one frame so handles never overlap. [5][4]
- FR8 Touch targets: Each handle exposes ≥44×44 pt interactive area regardless of its visual size. [4]
- FR9 Colors: In‑range track and handles use systemBlue; out‑of‑range uses secondary; actions on true black with native button styles. [4][15]

## Non‑functional requirements

- Latency: Handle position updates must feel instant with no perceptible lag, independent of preview responsiveness. [2][3]
- Reliability: Under rapid reversals or long drags, there are zero dropped updates, zero animation warnings, and consistent frame‑accurate snapping. [6][11]
- Accessibility: VoiceOver exposes “Start handle at t=…” and “End handle at t=…” with clear contrast and touch target compliance. [4]

## Contracts

- Inputs: asset reference, duration, nominal frame rate or preferred timescale, initial start/end, flags for detent haptics and precision scrubbing. [5][16]
- Outputs: startTime and endTime as snapped CMTime values for export and for preview seek requests. [11][17]
- Events: onBeginDrag, onChange(time, whichHandle), onEndDrag, onConfirm, onSeekStarted/Completed for analytics and backpressure handling. [3][1]

## Acceptance criteria

- AC1 Tracking fidelity: On a 10‑minute clip, the handle visually tracks the finger with no lag or catch‑up, including rapid reversals. [2][8]
- AC2 Frame accuracy: When paused on any frame, dragging to the next detent advances exactly one frame per tick with audible/tactile confirmation. [14][5]
- AC3 Seek smoothness: Console shows no overlapping seeks; queued seeks complete in order with smooth preview updates and no “invalid sample” logs. [3][6]
- AC4 Export parity: The exported clip’s first and last frames match the previewed boundaries exactly at the chosen timescale. [11][17]
- AC5 Aesthetics: Action buttons render on black with native styles, and spacing aligns with platform guidelines and the rest of the app’s bottom navigation. [4][15]

## Tasks

- T1 Input bridge: Wrap UIPanGestureRecognizer in a SwiftUI representable to access coalesced touches and predicted updates, feeding a high‑rate position stream. [2][8]
- T2 Quantizer: Implement x→time mapping with double precision and CMTime snapping using asset frame duration or a 600 timescale; expose one‑frame min gap. [5][11]
- T3 Seek scheduler: Build a single‑flight seek queue using seek(to:toleranceBefore:toleranceAfter:completionHandler:), pausing playback during scrubs and resuming after. [3][7]
- T4 Preview fallback: Add a strategy toggle to use stepByCount or AVAssetImageGenerator for preview when seek latency exceeds threshold on device. [7][10]
- T5 Animation hygiene: Remove any implicit animations from drag‑driven properties and verify no AnimatablePair warnings under thrash testing. [6][9]
- T6 Haptics: Emit ticks only when snapped frame index changes; debounce to exactly one tick per frame step. [14]
- T7 Actions restyle: Remove gray bar, apply borderedProminent+tint(.blue) for primary and borderless for secondary on black, with tokenized spacing. [4][15]
- T8 QA matrix: Test long clips, high‑FPS footage, variable frame rate, rapid reversals, multi‑touch interrupts, and vertical‑precision drags. [18][19]

## Risks and mitigations

- Seek thrash: Avoid concurrent seeks; use completion‑chained scheduling and small or zero tolerances, with preview fallback if needed. [3][7]
- VFR assets: Quantize using CMTime at the asset’s effective time base rather than naive milliseconds to prevent drift. [5][11]
- Gesture interruptions: Detect canceled/interrupting gestures and reset transient state to prevent stuck UI or stale seeks. [18][9]
