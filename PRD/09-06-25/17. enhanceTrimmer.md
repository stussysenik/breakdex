## Spec-Kit: Achieving Precision, Fluidity, and Visual Polish

### Vision Statement

Our goal is to evolve the video trimmer from a functional slider into a **precision instrument**. It must feel fluid, provide intentional feedback, and be visually flawless. The user's interaction should feel like a direct, intuitive manipulation of time, with controls that are both responsive for quick adjustments and precise for frame-perfect edits.

---

### Root Cause Analysis

A joint engineering and design review has identified four root causes for the current issues:

1.  **State & Animation Conflict:** The `Invalid sample AnimatablePair` error is a direct result of updating the primary view state (`startTime`, `endTime`) faster than SwiftUI's animation system can render it. Drag gestures produce a continuous stream of updates, which conflicts with any implicit or explicit animations tied to the view.
2.  **Over-Eager Feedback:** The `rate-limit threshold` error for haptics is caused by firing feedback on every minor pixel change during a drag, rather than on discrete, meaningful events (like crossing a frame boundary).
3.  **Lack of Dynamic Control:** The 1:1 finger tracking, while direct, lacks a mechanism for fine control. This makes the handles feel "too fast" and difficult to position accurately, which is a common UX issue in media editors.
4.  **Visual Inconsistencies:** The "extra" blue line extending past the handles is a rendering artifact. Using a standard `Capsule` shape, whose rounded ends draw outside its defined frame width, creates a visual representation that is mathematically inexact and looks unprofessional.

---

### Implementation Directives

To resolve these issues, we will adhere to the following four principles.

#### 1. Decouple Live-Drag State from Committed State

The view's state must be separated into two types: the **transient** state (the handle's immediate position during a drag) and the **committed** state (the video's actual `startTime` and `endTime`).

* **Action:** Refactor the drag gesture to use a `@GestureState` variable to track the handle's immediate translation. This state is temporary, lives only for the duration of the gesture, and won't conflict with SwiftUI's main animation system. The view model's `startTime` and `endTime` should only be updated *within* this gesture logic, ideally inside a `Transaction` that disables animations, as we did previously. This completely resolves the `AnimatablePair` error.

#### 2. Enforce Intentional, Event-Driven Haptics

Haptic feedback must feel purposeful and confirm a specific action. It should not be a continuous buzz.

* **Action:** The haptic feedback logic must be debounced. Inside the drag gesture, store the *previous* snapped frame index. Trigger the `.selectionChanged()` haptic **only when the newly calculated frame index is different from the previous one**. This ensures the feedback fires exactly once per frame crossed, eliminating the rate-limit errors and making the interaction feel crisp.

#### 3. Implement Dynamic Precision Scrubbing

To address the control sensitivity, we will implement a standard interaction pattern from professional editing software: vertical scrubbing for precision.

* **Action:** During a drag gesture, calculate a `scaleFactor` based on the **vertical distance** of the user's finger from the timeline (`dragValue.translation.height`). A greater vertical distance should result in a smaller `scaleFactor` (e.g., `0.1`), slowing down the handle's horizontal movement. A vertical distance near zero should use a `scaleFactor` of `1.0`. Apply this `scaleFactor` to the horizontal translation before calculating the new position. This gives the user intuitive, dynamic control over the trimming sensitivity without needing to change modes.

#### 4. Achieve Visual & Logical Integrity

The visual representation must be a pixel-perfect depiction of the selected range, and its underlying constraints must be inviolable.

* **Action for Visuals:** To fix the "ugly extras," **replace the `Capsule()` shape with a `Rectangle()`**. Apply a corner radius to the rectangle that is equal to half its height (`.cornerRadius(3)` for a 6pt tall line). This creates the exact same rounded-end appearance but ensures the shape's visual edges align perfectly with its frame, providing a clean, professional look. * **Action for Logic:** The clamping logic from our last iteration is sound, but must be diligently maintained. The handle's valid pixel range is always calculated *before* converting its position to a time value. The start handle must be clamped to `max(0, ...)` and the end handle to `min(totalWidth, ...)`, with the minimum pixel gap always enforced between them. This guarantees the handles never cross or leave their track.
