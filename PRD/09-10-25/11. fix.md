Short answer: Unify media ownership in a tiny VideoPlayerViewModel that exclusively owns AVPlayer and all async builds, fence and cancel every build task, and perform a hard player reset when leaving a rotated composition; this yields clean SwiftUI lifecycles, reliable back navigation, and scalable maintenance. [1][2][3][4][5]

## Core principles
- Single owner: only one object creates, holds, and mutates AVPlayer/AVPlayerItem so SwiftUI views become pure renderers with no media side-effects. [1][5]
- Cancellable builds: every asset/rotation build runs in a replaceable Task with a generation fence so late completions are ignored. [1][5]
- Hard reset boundary: whenever switching from a composition (rotated/trimmed) back to a plain asset, pause, replaceCurrentItem(nil), cancel prerolls, then attach a fresh item and seek to zero. [1][2]

## Minimal architecture
- Introduce VideoPlayerViewModel (@MainActor, @Observable) that holds let asset: AVAsset, @Published state (.loading/.playing/.error), a single AVPlayer, and two utilities: startBuild(gen-fenced) and applyItem(hardReset:). [1][5]
- Views depend only on this model: TrimmerView and PreTrimView read the model and never start AV work directly, eliminating lifecycle mismatches during navigation. [2][4][1]

## Drop‑in implementation
- The current CustomVideoPlayerView already contains the crucial pieces (buildTask, buildGen, startBuild, applyItem with hardReset and onDisappear cancellation); extract these into VideoPlayerViewModel so the view is ~100 lines and purely declarative. [1][5]
- Public API of the model: setRotation(quarterTurns:), setSource(asset/url/photosId:), and teardown() for navigation; each mutator cancels the previous Task, bumps generation, and rebuilds the item accordingly. [1][5]

```swift
// Sketch: keep this minimal and focused
@MainActor
final class VideoPlayerViewModel: ObservableObject {
  enum State { case loading, playing(AVPlayer), error(String) }
  @Published private(set) var state: State = .loading
  private(set) var player = AVPlayer()
  private var buildTask: Task<Void, Never>?
  private var gen = 0
  private var asset: AVAsset?
  private var quarterTurns = 0

  func setSource(asset: AVAsset, quarterTurns: Int = 0) {
    self.asset = asset
    self.quarterTurns = quarterTurns
    rebuild(hardReset: quarterTurns == 0)
  }
  func setRotation(_ turns: Int) {
    quarterTurns = turns
    rebuild(hardReset: turns == 0) // composition → plain asset needs reset
  }
  func teardown() {
    buildTask?.cancel()
    player.pause()
    player.replaceCurrentItem(with: nil)
    player.cancelPendingPrerolls()
    state = .loading
  }

  private func rebuild(hardReset: Bool) {
    buildTask?.cancel()
    gen &+= 1; let current = gen
    buildTask = Task { [asset, quarterTurns] in
      guard let asset else { return }
      do {
        let item: AVPlayerItem
        if quarterTurns != 0 {
          // reuse project’s transformer
          let pi = try await VideoTransformBuilder.createPlayerItem(asset: asset, quarterTurns: quarterTurns)
          item = pi
        } else {
          item = AVPlayerItem(asset: asset)
        }
        await MainActor.run {
          guard current == self.gen else { return }
          if hardReset {
            self.player.pause()
            self.player.replaceCurrentItem(with: nil)
            self.player.cancelPendingPrerolls()
          }
          if case .playing = self.state {
            self.player.replaceCurrentItem(with: item)
          } else {
            self.player = AVPlayer(playerItem: item)
          }
          self.player.seek(to: .zero, toleranceBefore: .zero, toleranceAfter: .zero)
          self.player.play()
          self.state = .playing(self.player)
        }
      } catch {
        await MainActor.run {
          guard current == self.gen else { return }
          self.state = .error("Failed to process video: \(error.localizedDescription)")
        }
      }
    }
  }
}
```
This is a direct lift of logic already present in CustomVideoPlayerView (startBuild/applyItem/hardReset), but moved behind a clean API. [1][5]

## View wiring
- TrimmerView: create and pass a shared VideoPlayerViewModel (or reuse the existing trimmerViewModel.player if preferred), call model.setSource(asset: trimmerViewModel.asset, quarterTurns: rotationQuarterTurns) in .onAppear, call model.setRotation(newTurns) on rotate tap, and call model.teardown() in Back before onCancel(). [2][3][1]
- PreTrimView: reuse the same model or a fresh one, and always invoke model.setSource(asset: asset, quarterTurns: 0) on appear so Pre‑Trim starts clean and unrotated; the model’s hard reset guarantees no cached composition frames. [4][1]

```swift

// becomes a light wrapper around videoModel.state to render VideoPlayer(player:)

onCancel: {
  trimmerViewModel.stopCoalescing()
  /* videoModel.teardown() */
  onCancel()
}
```
This keeps the current rotation propagation to TrimmerViewModel while giving the player a dedicated lifecycle. [2][3]

## Back navigation reliability
- With teardown() called and the view model cancelling buildTask and clearing the player item, no late Task can mutate UI after dismissal, removing the race and memory leaks noted in the debug write‑up. [2][1]
- Pre‑Trim rebinds to rotationQuarterTurns == 0 and benefits from the hard reset boundary, so users never see the lingering rotated frame. [4][1]

## Rotation propagation and naming
- Continue mirroring rotationQuarterTurns into TrimmerViewModel and pass that to the naming state, preserving the documented “live preview rotates + value flows downstream; export may bake rotation.” [2][3][5]
- NameMoveView can keep its “baked export → effectiveRotation = 0” rule, because the upstream state still carries the user’s intention for non‑baked paths. [5]

## Timecode display hygiene
- The single‑line, non‑wrapping time labels in TrimmerView already include lineLimit/minimumScaleFactor/tightening with monospaced digits; keep these modifiers on all three labels to avoid decimal splits across lines. [2]
- Give each time column equal width via .frame(maxWidth: .infinity) to reduce wrap pressure on smaller devices. [2]

## Progressive cleanup path
- Short term: move the existing startBuild/applyItem/hardReset/onDisappear logic from CustomVideoPlayerView into VideoPlayerViewModel and keep the view as a thin renderer over state. [1][5]
- Medium term: extract a VideoPlayerService (transform/build/export) so both Trimmer and Name screens share identical, testable media logic without duplicating Tasks in views. [5]

This solution preserves current behavior, fixes the lifecycle and back issues, and gives a clean seam for future features with minimal surface area changes. [1][2][3][4][5]
