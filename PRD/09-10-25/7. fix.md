Short answer: Yes—the back navigation glitch is caused by async player-building tasks and reused AVPlayer state outliving the view; fix it by cancelling builds on disappear/back, fencing late async completions, and doing a hard player reset when returning to Pre‑Trim. [1][2]

## Why it breaks
- Async Tasks that build compositions keep running after TrimmerView is dismissed, then apply results back into a view/player that should no longer exist, leaving stale players and cached rotated frames alive. [1]
- Replacing the current item isn’t always enough to flush a previously rotated AVMutableVideoComposition, so the preview can remain visually rotated even though Pre‑Trim requests rotation 0. [2]

## Minimal, performant fix
- Add a single source of truth for player creation with three guards: **cancel tasks**, **generation fence**, and **hard reset** when leaving rotation. [1][2]
- Trigger cancellation on both back tap and view disappear, and ensure Pre‑Trim rebuilds the player from a fresh AVPlayerItem with a brief clear/seek for a guaranteed visual reset. [1][2]

## Patch: task cancel + fence
- In CustomVideoPlayerView, keep one build Task and a generation counter so late completions are ignored. [2]
```swift
@State private var buildTask: Task<Void, Never>?
@State private var buildGen: Int = 0

private func startBuild(_ work: @escaping @Sendable () async -> Void) {
  buildTask?.cancel()
  buildGen &+= 1
  let gen = buildGen
  buildTask = Task {
    guard !Task.isCancelled else { return }
    await work()
    // Each MainActor apply must re-check generation
  }
}

@MainActor
private func applyItem(_ item: AVPlayerItem, hardReset: Bool) {
  switch playerState {
  case .playing(let existing):
    if hardReset {
      existing.pause()
      existing.replaceCurrentItem(with: nil)
      existing.cancelPendingPrerolls()
      let fresh = AVPlayer(playerItem: item)
      playerState = .playing(player: fresh)
    } else {
      existing.replaceCurrentItem(with: item)
    }
  default:
    playerState = .playing(player: AVPlayer(playerItem: item))
  }
  if case .playing(let p) = playerState {
    p.seek(to: .zero, toleranceBefore: .zero, toleranceAfter: .zero)
    p.play()
  }
}
```


## Patch: rebuild with reset
- Rebuild on rotation change; use hardReset only when going from composition to plain asset (turns == 0). [2]
```swift
.onDisappear {
  buildTask?.cancel()
  if case .playing(let p) = playerState {
    p.pause()
    p.replaceCurrentItem(with: nil)
  }
  playerState = .loading
}

.onChange(of: rotationQuarterTurns) { _, newTurns in
  startBuild {
    guard let asset = asset else { return }
    do {
      if newTurns != 0 {
        let r = try await VideoTransformBuilder.build(asset: asset, quarterTurns: newTurns)
        let item = AVPlayerItem(asset: r.composition)
        item.videoComposition = r.videoComposition
        item.seekingWaitsForVideoCompositionRendering = true
        await MainActor.run { applyItem(item, hardReset: false) }
      } else {
        let item = AVPlayerItem(asset: asset)
        await MainActor.run { applyItem(item, hardReset: true) }
      }
    } catch {
      await MainActor.run { playerState = .error(message: "Failed to process video: \(error.localizedDescription)") }
    }
  }
}
```


## Hook into back
- On back: call stopCoalescing, then rely on view disappear to cancel tasks and clear the player, preventing any late rotated item from being applied during navigation. [1][2]
```swift
// In TrimmerView back handler
onCancel: {
  trimmerViewModel.stopCoalescing()
  onCancel() // triggers state -> PreTrim
}
```


## Pre‑Trim guarantee
- Pre‑Trim should instantiate CustomVideoPlayerView with rotationQuarterTurns: 0; the hardReset path above ensures cached rotated frames are flushed and the plain asset renders immediately. [1][2]

## Result
- Back navigation becomes reliable because no stray tasks or players survive the dismissal, and the preview consistently resets to an unrotated frame with minimal overhead. [1][2]
