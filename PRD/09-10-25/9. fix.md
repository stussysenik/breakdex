Short answer: Yes—the back glitch is from async player builds and shared AVPlayer state outliving TrimmerView; cancel those tasks, fence late completions, and hard‑reset the player when navigating back so Pre‑Trim always starts clean. [1][2][3]

## Root cause
- The player setup runs in Tasks that can finish after TrimmerView disappears, applying items into a view that’s gone and keeping decoded buffers alive, which matches the “lifecycle mismatch” described. [1][2]
- Simply replacing the item isn’t enough to clear a rotated composition frame; a short hard reset is needed when switching from composition back to a plain asset. [2]

## Simple fix overview
- Add three guards to CustomVideoPlayerView: cancel any in‑flight build task, fence with a generation counter so late results are ignored, and hard‑reset the AVPlayer when quarterTurns returns to 0 or the view disappears. [2][1]
- On Back in TrimmerView, stop the coalesced preview loop and rely on the player’s onDisappear cleanup so no background work survives navigation. [3][2]
- Pre‑Trim always instantiates a fresh player at rotation 0; forcing a new identity is optional but can be used as a last resort.   

## Code patches (minimal)
- In CustomVideoPlayerView, finalize the task fence and hard reset path. [2]
```swift
@State private var buildTask: Task<Void, Never>?
@State private var buildGen: Int = 0

private func startBuild(_ work: @escaping @Sendable (_ gen: Int) async -> Void) {
  buildTask?.cancel()
  buildGen &+= 1
  let gen = buildGen
  buildTask = Task { await work(gen) }
}

@MainActor
private func applyItem(_ item: AVPlayerItem, hardReset: Bool = false, gen: Int) {
  guard gen == buildGen else { return }                      // fence late completions
  switch playerState {
  case .playing(let existing):
    if hardReset {
      existing.pause()
      existing.replaceCurrentItem(with: nil)
      existing.cancelPendingPrerolls()
      playerState = .playing(player: AVPlayer(playerItem: item))
    } else {
      existing.replaceCurrentItem(with: item)
    }
  default:
    playerState = .playing(player: AVPlayer(playerItem: item))
  }
  if case .playing(let p) = playerState {
    p.seek(to: .zero, toleranceBefore: .zero, toleranceAfter: .zero)
    p.play()
}
```
Use the fence in all build sites: [2]
```swift
.onChange(of: rotationQuarterTurns) { _, newTurns in
  startBuild { gen in
    guard let asset = asset else { return }
    do {
      if newTurns != 0 {
        let item = try await VideoTransformBuilder.createPlayerItem(asset: asset, quarterTurns: newTurns)
        await MainActor.run { applyItem(item, gen: gen) }     // reuse player
      } else {
        let item = AVPlayerItem(asset: asset)
        await MainActor.run { applyItem(item, hardReset: true, gen: gen) } // flush rotated buffers
      }
    } catch {
      await MainActor.run { playerState = .error(message: "Failed to process video: \(error.localizedDescription)") }
    }
  }
}

.onDisappear {
  buildTask?.cancel()
  if case .playing(let p) = playerState {
    p.pause()
    p.replaceCurrentItem(with: nil)
    p.cancelPendingPrerolls()
  }
  playerState = .loading
}
```
These changes ensure no stray task can update the player after dismissal and that rotation is fully cleared when leaving the trimmer. [2]

## Back button hook
- Keep TrimmerView’s Back handler, but guarantee preview loop cleanup before navigation. [3]
```swift
onCancel: {
  trimmerViewModel.stopCoalescing()   // pauses player + ends displayLink

}
```
Optionally add a teardown entry point for any extra ViewModel cleanup: [4]
```swift
@MainActor func teardownForDismissal() {
  pendingPreviewTime = nil

  isDraggingEndHandle = false
}
```
Call it alongside stopCoalescing if desired. [4]

## Pre‑Trim start clean
- Pre‑Trim already builds a fresh player with rotation 0, which is correct; if a rare device still shows a cached frame, force a new identity to rebuild the subtree.   
```swift
CustomVideoPlayerView(AVPlayer(playerItem: AVPlayerItem(asset: asset)), asset: asset, rotationQuarterTurns: 0)
  .id("pretrim-\(asset.hashValue)")
```
This is rarely needed once the hard reset is active but is a safe fallback. [2]
