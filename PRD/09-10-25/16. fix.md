Short answer: Make one object the single media owner, inject it everywhere, and guarantee cancellation, generation fencing, and a hard reset boundary; this yields reliable back navigation, instant rotation feedback, clean timecodes, and scalable maintenance. [1][2][3][4]

## Target behavior
- Back always returns to Pre‑Trim with an unrotated, fresh preview and zero leaked tasks or players. [3][1]
- Rotate button rotates the preview immediately and the same rotation value flows into naming, with rotation baked on export or applied live when untrimmed. [2][4]
- Timecode labels always render on one line without breaking at the decimal, across device widths. [2]
- Trimmer’s live scrubbing stays smooth via coalesced seek, independent of the player lifecycle. [3]

## Inversion rule plan
Design the minimal system that cannot exhibit the bad states first, then wire views to it. [1]

### 1) One media owner
- Use VideoPlayerViewModel as the only place that creates and mutates AVPlayer/AVPlayerItem, exposing setSource(...), setRotation(_), teardown(), and an enum State for UI. [1][5]
- Ensure every build is cancelable and fenced by a generation counter; apply items only if gen matches. [1]

### 2) Boundaries that flush caches
- When going from rotated composition → plain asset, perform a “hard reset”: pause, replaceCurrentItem(nil), cancel prerolls, then attach the new item and seek to zero. [1]
- Keep “soft update” (replaceCurrentItem) for composition→composition or asset→composition to remain fast. [1]

### 3) Views become pure
- CustomVideoPlayerView should be a thin renderer of videoModel.state, and it should not spin its own long‑lived AV tasks. [1]
- On disappear, call videoModel.teardown() so no async work or buffers outlive navigation. [1]

## Precise changes
- Deduplicate VideoPlayerViewModel: keep the complete implementation in CustomVideoPlayerView.swift or, preferably, the standalone VideoPlayerViewModel.swift file, and delete duplicate definitions to avoid symbol clashes. [1][5]
- Allow model injection into CustomVideoPlayerView and remove its private StateObject so the same instance can be owned by TrimmerView and torn down on Back. [1]
  - Add an initializer: CustomVideoPlayerView(videoModel: VideoPlayerViewModel, asset: AVAsset, rotationQuarterTurns: Int). [1]
  - Inside task, just call videoModel.setSource(asset:…, quarterTurns:…); rotation updates call videoModel.setRotation(newTurns). [1]
- TrimmerView: own @StateObject var videoModel = VideoPlayerViewModel(), pass it into CustomVideoPlayerView, call videoModel.setRotation on rotate, and call videoModel.teardown before onCancel(). [2]
  - Replace CustomVideoPlayerView(asset: trimmerViewModel.asset, rotationQuarterTurns: rotationQuarterTurns) with CustomVideoPlayerView(videoModel: videoModel, asset: trimmerViewModel.asset, rotationQuarterTurns: rotationQuarterTurns). [2]
  - Keep trimmerViewModel.stopCoalescing() so scrubbing displayLink is halted before navigation. [3]
- Pre‑Trim: instantiate a fresh VideoPlayerViewModel or let the view construct one; it calls setSource(asset:…, quarterTurns: 0) on appear, and on disappear teardown is called automatically by the player view. [3][1]
- NameMoveView: keep the rule “trimmed → effectiveRotation = 0” to avoid double rotation; for original or Photos assets, pass the rotationQuarterTurns so the same transform is applied live. [4]
  - You can also switch NameMoveView to the same CustomVideoPlayerView(videoModel: …) signature if sharing state ever becomes useful. [4][1]

## Timecode one‑line fix
- The Start/Duration/End texts already include .lineLimit(1).minimumScaleFactor(0.8).allowsTightening(true).monospacedDigit(), and each column uses .frame(maxWidth: .infinity) to prevent decimal wrapping; keep that exactly. [2]

## Back navigation reliability
- The combination of teardown() on disappear/back, generation fencing, and the hard reset when quarterTurns returns to 0 eliminates late item applications and cached rotated frames. [1][2][3]
- TrimmerView already stops coalesced preview seeking before navigating away, removing another source of async churn. [2][3]

## Acceptance checks
- Logs: ensure teardown() prints before navigation, and Pre‑Trim’s “no rotation” logs appear, confirming a fresh pipeline. [3][1]
- Visual: rotate in Trimmer, see preview rotate; export and proceed to NameMove, see effectiveRotation = 0 for trimmed, or same rotation for original/Photos. [2][4]
- Leak/latency: navigate back repeatedly and confirm no accumulating players or tasks and instant render of unrotated frames thanks to hard reset. [1]

## Why this scales
- Media logic is centralized, testable, and reusable across Pre‑Trim, Trimmer, and Naming, while UI remains declarative and minimal. [1][5]
- The generation‑fenced builder plus explicit reset boundary prevents class of lifecycle bugs without extra complexity or runtime cost. [1]
