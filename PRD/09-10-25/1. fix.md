Short answer: Standardize the handle coordinate system, do all min-duration enforcement in the ViewModel, and coalesced seek on drag so the preview live-scrubs—then remove the in-trimmer alert and show only the bottom warning bound to ViewModel state for a simple, jitter-free, performant flow. [1][2][3]

## What’s going wrong
- Mixed coordinate conventions are causing imprecision: the handle is sometimes treated as if the position is its “center” (subtracting half-width when converting to time) and other times as “left edge,” plus the drag gesture uses a local coordinate space, so the handle can’t reliably reach the start/end pixels of the track. [1]
- Min-duration logic is split: HybridPreciseTrimmerView shows its own limit-alert while the bottom alert is driven by ViewModel.showMinimumDurationWarning, causing duplicated or lingering warnings. [1][2][3]
- Live preview is already implemented with coalesced seeks (displayLink + pendingPreviewTime + seekTo), but it’s safest to drive all live updates from proposeTime on drag and stop coalescing on end to guarantee smooth scrubbing. [3]

## Minimal, stable plan
- Use one coordinate system: represent handle positions as “left edge” in a named track coordinate space, and make both time→x and x→time use trackWidth = geometry.width − handleWidth. [1]
- Enforce the 3s minimum entirely in the ViewModel during proposeTime/validate so UI stays stateless and fast; the View shows only the bottom warning bound to showMinimumDurationWarning. [2][3]
- Coalesced live-seek: call startCoalescing on drag begin, proposeTime for each move, and stopCoalescing on drag end, letting tick() do framed, zero-tolerance seeks for crisp scrubbing. [3]

```swift
private func timeToXLeft(_ t: CMTime, trackWidth: CGFloat) -> CGFloat {
  guard viewModel.videoDuration.seconds > 0 else { return 0 }
  let p = t.seconds / viewModel.videoDuration.seconds
  return CGFloat(p) * trackWidth
}
private func xLeftToTime(_ x: CGFloat, trackWidth: CGFloat) -> CMTime {
  let clamped = max(0, min(x, trackWidth))
  let seconds = Double(clamped / trackWidth) * viewModel.videoDuration.seconds
  return CMTime(seconds: seconds, preferredTimescale: viewModel.videoDuration.timescale)
}
```

- Make gestures use the track coordinate space and perform all min-distance logic in pixels using the same left-edge convention, then convert to time and call proposeTime:
```swift
private func minDistancePx(_ g: GeometryProxy) -> CGFloat {
  let trackWidth = g.size.width - handleWidth
  let pps = trackWidth / viewModel.videoDuration.seconds
  return pps * viewModel.minimumDuration.seconds
}

private func drag(handle: HandleType, in g: GeometryProxy) -> some Gesture {
  DragGesture(minimumDistance: 0, coordinateSpace: .named("track"))
    .onChanged { value in
      if handle == .start && !viewModel.isDraggingStartHandle {
        viewModel.isDraggingStartHandle = true
        viewModel.startCoalescing()
      } else if handle == .end && !viewModel.isDraggingEndHandle {
        viewModel.isDraggingEndHandle = true
        viewModel.startCoalescing()
      }

      let trackWidth = g.size.width - handleWidth
      let startX = timeToXLeft(viewModel.startTime, trackWidth: trackWidth)
      let endX   = timeToXLeft(viewModel.endTime,   trackWidth: trackWidth)
      let minPx  = minDistancePx(g)

      // finger-aligned center -> left-edge
      var proposedLeft = value.location.x - handleWidth/2
      proposedLeft = max(0, min(proposedLeft, trackWidth))

      // bumper
      switch handle {
        case .start:
          proposedLeft = min(proposedLeft, endX - minPx)
        case .end:
          proposedLeft = max(proposedLeft, startX + minPx)
      }

      let t = xLeftToTime(proposedLeft, trackWidth: trackWidth)
      viewModel.proposeTime(t, for: handle)
    }
    .onEnded { value in
      let trackWidth = g.size.width - handleWidth
      var xLeft = value.location.x - handleWidth/2
      xLeft = max(0, min(xLeft, trackWidth))
      let t = xLeftToTime(xLeft, trackWidth: trackWidth)
      viewModel.commitTime(t, for: handle)

      if handle == .start { viewModel.isDraggingStartHandle = false }
      else { viewModel.isDraggingEndHandle = false }

      viewModel.stopCoalescing()
    }
}
```

## ViewModel tweaks (single source of truth)
Make the ViewModel the only place that enforces the 3-second bumper and drives the bottom alert and the live preview seek. [3]

- Keep validate() as the authoritative clamp, but ensure the warning turns on while at/under the minimum and turns off when moving away by recomputing after each proposeTime change:
```swift
func proposeTime(_ proposedTime: CMTime, for handle: HandleType) {
  let validated = validate(proposedTime, for: handle)

  switch handle {
  case .start:
    if startTime != validated { startTime = validated }
  case .end:
    if endTime != validated { endTime = validated }
  }

  pendingPreviewTime = validated

  // Show while duration <= minimum during drag
  let atOrBelowMin = (endTime - startTime) <= minimumDuration
  showMinimumDurationWarning = atOrBelowMin
}
```


- Don’t forcibly hide the warning on commit; keep it true if the user lands exactly on the minimum, and it will clear naturally once the trim exceeds the minimum on the next edit:
```swift
func commitTime(_ time: CMTime, for handle: HandleType) {
  let validated = validate(time, for: handle)
  switch handle {
    case .start: startTime = validated
    case .end:   endTime   = validated
  }
  // Keep warning consistent with the final committed range
  showMinimumDurationWarning = (endTime - startTime) <= minimumDuration
}
```


- Coalesced live preview is already correct: startCoalescing pauses the player, proposeTime feeds pendingPreviewTime, tick() calls seekTo with zero tolerance, and stopCoalescing ends the loop, which is ideal for responsive scrub feedback. [3]

## Show only the bottom alert
- Remove the HybridPreciseTrimmerView contextual bottom alert entirely and rely on TrimmerView’s overlay that reads trimmerViewModel.showMinimumDurationWarning, keeping UX consistent and minimal. [1][2][3]
- With the above proposeTime/commitTime changes, the warning appears only when the active duration is at or below the minimum and otherwise clears, matching the desired behavior. [2][3]

## Resulting UX and performance
- Handles track precisely across the full slider width, including exact alignment to 0 and the video end, because both mapping functions and constraints share the same left-edge track space and named coordinate space. [1]
- The alert appears once, at the bottom, only when the duration is at/below the minimum, eliminating duplicates and flicker from dual-state alert logic. [2][3]
- Live frame scrubbing remains smooth due to coalesced, zero-tolerance seeks during drag, which is both performant and aligned with a clean, modern interaction feel. [3]
