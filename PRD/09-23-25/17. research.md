### 📍 Root Cause Analysis

The core issue is a race condition between the `AddMoveUnifiedState` changing its `flowState` and the `TrimmerViewModel` completing its `setupAsync()` method.

1.  **State Transition is Too Fast**: The `AddMoveUnifiedState` transitions from `.loading` -\> `.trimming_setup` -\> `.trimming` very quickly. The `.trimming_setup` state correctly calls `await setupTrimmerViewModel()`.
2.  **Async Setup is Slow**: Inside `setupTrimmerViewModel()`, a new `TrimmerViewModel` is created and its `setupAsync()` method is called. This method needs to load asset properties like duration and track information, which is an I/O operation that takes a moment.
3.  **UI Renders Prematurely**: The `AddMoveContainer` sees the `flowState` change to `.trimming` and immediately tries to render `FeatureRichTrimmerView`.
4.  **Readiness Check Fails**: The `isReadyToShowTrimmer` computed property inside `FeatureRichTrimmerView` checks if `unifiedState.flowState == .trimming`. While this is true, the underlying `TrimmerViewModel`'s `isReady` property (which is set *inside* `setupAsync()`) is still `false`. This leads to the view getting "stuck" or not having the necessary data to render the timeline correctly.

The log entry `🎬 UNIFIED_STATE: ✅ Video preparation complete. Transitioning to trimming_setup.` confirms the start of this problematic sequence.
