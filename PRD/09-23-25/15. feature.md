## 🏛️ Key Architectural Concepts in Action

  * **Asynchronous Coordination**: The use of `async/await` is paramount. It ensures that the `AVPlayerItem` is fully reconfigured *before* the UI transitions. This prevents the `NameMoveView` from appearing with a non-trimmed or non-rotated video, solving the primary performance and readiness bottleneck.
  * **State-Driven UI**: We don't manually push a new view. The entire transition is driven by changing `unifiedState.flowState = .naming`. The `AddMoveContainer` is built to react to this change, making the navigation logic clean and centralized.
  * **Asset Inheritance**: The trimmed and rotated video is "inherited" by the next view not by passing a new video file, but by modifying the `AVPlayerItem` within the persistent `UnifiedPlayerManager`. This manager survives the view transition, providing the correctly configured player to `NameMoveView` instantly.
  * **Resource Management**: The call to `cleanupTrimmerViewModel()` upon entering the `.naming` state is a critical performance optimization. It deallocates the `TrimmerViewModel` and its associated components, freeing up significant memory for the next steps in the flow (naming and saving).
