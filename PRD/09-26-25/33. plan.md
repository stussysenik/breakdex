## 2\. Correcting the `applyRotation` Morphism

[cite\_start]The "cropped square effect" is a direct result of an incorrect geometric transformation that rotates the video's pixels but fails to resize the output canvas (`renderSize`) to accommodate the new dimensions[cite: 80, 84, 120]. [cite\_start]This discards pixel data, making the operation non-invertible and thus not an isomorphism[cite: 87, 88].

The solution is to construct a composite `CGAffineTransform` that accounts for both the video's pre-existing orientation metadata and the user's requested rotation.

### The Correct Transformation Sequence

[cite\_start]The correction requires a four-step process that must be executed in a specific, non-commutative order[cite: 111, 112]:

1.  **Determine Video Geometry**: Extract the video track's `naturalSize` and its `preferredTransform` matrix. [cite\_start]This matrix, not a simple angle, encodes the device's recording orientation (e.g., portrait vs. landscape)[cite: 93, 94, 113].
2.  **Calculate Render Size**: Adjust the `AVMutableVideoComposition.renderSize` to fit the final rotated dimensions. [cite\_start]For example, a 1920x1080 video rotated by 90 degrees requires a render canvas of 1080x1920[cite: 117, 118, 119]. [cite\_start]Setting this incorrectly is the primary cause of the bug[cite: 120].
3.  [cite\_start]**Compose the Final Transform**: The final transform, $T_{final}$, is a composition of the original transform ($T_{preferred}$), the user's rotation ($T_{rotation}$), and a translation ($T_{translation}$) to re-center the video in the new canvas[cite: 121, 128]. The correct composition is:
    $$
    $$$$T\_{final} = T\_{preferred} \\cdot T\_{rotation} \\cdot T\_{translation}
    $$
    $$$$
    $$
4.  [cite\_start]**Apply to Layer Instruction**: This composite transform is applied to the `AVMutableVideoCompositionLayerInstruction`[cite: 131].

### Implementation

The following code snippet demonstrates the correct implementation for the `buildCorrectVideoComposition` function.

```swift
// In a helper class like VideoTransformBuilder from TrimmerViewModel.swift
import AVFoundation

func buildCorrectVideoComposition(for asset: AVAsset, rotationAngleInRadians: CGFloat) -> AVMutableVideoComposition {
    // Ensure we have a video track
    guard let videoTrack = asset.tracks(withMediaType: .video).first else {
        return AVMutableVideoComposition(asset: asset) { _ in }
    }

    let composition = AVMutableComposition()
    guard let compositionTrack = composition.addMutableTrack(withMediaType: .video, preferredTrackID: kCMPersistentTrackID_Invalid) else {
        return AVMutableVideoComposition(asset: asset) { _ in }
    }

    let assetTimeRange = CMTimeRange(start: .zero, duration: asset.duration)
    try? compositionTrack.insertTimeRange(assetTimeRange, of: videoTrack, at: .zero)

    let videoComposition = AVMutableVideoComposition()
    videoComposition.frameDuration = CMTime(value: 1, timescale: 30) // Set a reasonable frame rate

    let instruction = AVMutableVideoCompositionInstruction()
    instruction.timeRange = assetTimeRange

    let layerInstruction = AVMutableVideoCompositionLayerInstruction(assetTrack: compositionTrack)

    let originalTransform = videoTrack.preferredTransform
    let naturalSize = videoTrack.naturalSize
    
    // Determine the asset's true visual size after its preferredTransform is applied.
    let transformedSize = naturalSize.applying(originalTransform)
    let assetSize = CGSize(width: abs(transformedSize.width), height: abs(transformedSize.height))

    var finalTransform = originalTransform
    var renderSize = assetSize

    let rotation = rotationAngleInRadians
    
    if rotation == .pi / 2 || rotation == 3 * .pi / 2 { // 90 or 270 degrees
        renderSize = CGSize(width: assetSize.height, height: assetSize.width)
        let rotationTransform = CGAffineTransform(rotationAngle: rotation)
        
        var translationTransform: CGAffineTransform
        if rotation == .pi / 2 { // 90 degrees
            translationTransform = CGAffineTransform(translationX: assetSize.height, y: 0)
        } else { // 270 degrees
            translationTransform = CGAffineTransform(translationX: 0, y: assetSize.width)
        }
        
        finalTransform = finalTransform.concatenating(rotationTransform).concatenating(translationTransform)
        
    } else if rotation == .pi { // 180 degrees
        renderSize = assetSize
        let rotationTransform = CGAffineTransform(rotationAngle: rotation)
        let translationTransform = CGAffineTransform(translationX: assetSize.width, y: assetSize.height)
        finalTransform = finalTransform.concatenating(rotationTransform).concatenating(translationTransform)
    }
    
    videoComposition.renderSize = renderSize
    layerInstruction.setTransform(finalTransform, at: .zero)
    
    instruction.layerInstructions = [layerInstruction]
    videoComposition.instructions = [instruction]

    return videoComposition
}
```

## 3\. Ensuring Idempotent PhotoKit Operations

[cite\_start]The creation of duplicate "BreakDex" albums violates the principle of **idempotency**—an operation that can be run multiple times without changing the result beyond the initial application[cite: 172, 173]. [cite\_start]This is a classic race condition caused by the asynchronous "check-then-act" logic in `PHPhotoLibrary.performChanges`[cite: 183, 185, 192].

The robust solution is to serialize all access to the album using a Swift `actor`. This guarantees that the find-or-create logic is an atomic transaction.

### `AlbumManager` Actor

This actor will serve as the single, thread-safe entry point for all album-related operations, preventing race conditions.

```swift
// In a new file, AlbumManager.swift
import Photos
import Foundation

actor AlbumManager {
    static let shared = AlbumManager()
    private let albumName = "BreakDex"
    private var cachedAlbum: PHAssetCollection?

    private init() {}

    func getAlbum() async throws -> PHAssetCollection {
        // 1. Check actor's internal cache first.
        if let cachedAlbum = cachedAlbum {
            // Verify the cached album still exists in the photo library.
            let collections = PHAssetCollection.fetchAssetCollections(withLocalIdentifiers: [cachedAlbum.localIdentifier], options: nil)
            if collections.firstObject != nil {
                return cachedAlbum
            }
        }

        // 2. Fetch from PhotoKit.
        let fetchOptions = PHFetchOptions()
        fetchOptions.predicate = NSPredicate(format: "title = %@", albumName)
        let collections = PHAssetCollection.fetchAssetCollections(with: .album, subtype: .any, options: fetchOptions)

        if let album = collections.firstObject {
            self.cachedAlbum = album
            return album
        }

        // 3. Create if it doesn't exist, using the synchronous API to ensure atomicity.
        var placeholder: PHObjectPlaceholder?
        try await PHPhotoLibrary.shared().performChanges {
            let request = PHAssetCollectionChangeRequest.creationRequestForAssetCollection(withTitle: self.albumName)
            placeholder = request.placeholderForCreatedAssetCollection
        }

        guard let albumIdentifier = placeholder?.localIdentifier else {
            throw NSError(domain: "AlbumManager", code: 1, userInfo: [NSLocalizedDescriptionKey: "Failed to get placeholder for created album."])
        }

        // 4. Re-fetch the newly created album to get a usable instance, then cache and return.
        guard let newAlbum = PHAssetCollection.fetchAssetCollections(withLocalIdentifiers: [albumIdentifier], options: nil).firstObject else {
            throw NSError(domain: "AlbumManager", code: 2, userInfo: [NSLocalizedDescriptionKey: "Failed to fetch album after creation."])
        }
        
        self.cachedAlbum = newAlbum
        return newAlbum
    }
}
```

## 4\. Establishing Data Integrity with a Stable Identifier

[cite\_start]The system architecture designates the Photos library as the "absolute source of asset truth"[cite: 234]. [cite\_start]Therefore, the CoreData database must act as a synchronized local cache[cite: 237, 238]. [cite\_start]Using `PHAsset.localIdentifier` for this link is incorrect because it is not stable across devices or iCloud restores, creating a broken morphism that leads to dangling pointers[cite: 244, 249].

[cite\_start]The correct, Apple-sanctioned solution is the **`PHCloudIdentifier`**, which provides a stable, cross-device unique identifier[cite: 252, 253].

### Revised Persistence Flow

1.  **Storage**: After saving a video and getting the `PHAsset`, retrieve its `localIdentifier`.
2.  [cite\_start]**Conversion**: Use `PHPhotoLibrary.shared().cloudIdentifierMappings(forLocalIdentifiers:)` to asynchronously request the corresponding `PHCloudIdentifier`[cite: 257].
3.  [cite\_start]**Persistence**: Store the `stringValue` of the `PHCloudIdentifier` object in a `String` attribute in the CoreData `Move` entity[cite: 258].
4.  [cite\_start]**Retrieval**: To fetch the video on any device, reverse the process: fetch the string from CoreData, create a `PHCloudIdentifier` from it, convert it back to the *current device's* `localIdentifier`, and then fetch the `PHAsset`[cite: 259, 260, 261, 262, 263].

### Implementation

```swift
// In your CoreData Model (xcdatamodeld), ensure the Move entity has a non-optional String attribute:
// Attribute: videoCloudIdentifier, type: String

// Update the saveMove function in AddMoveUnifiedState.swift or its coordinator
async func saveMove(named name: String, for asset: PHAsset, in context: NSManagedObjectContext) async throws {
    // 1. Get the local identifier from the newly created PHAsset
    let localIdentifier = asset.localIdentifier

    // 2. Convert to the stable cloud identifier
    let mappings = try await PHPhotoLibrary.shared().cloudIdentifierMappings(forLocalIdentifiers: [localIdentifier])
    guard let cloudIdentifier = try mappings[localIdentifier]?.get() else {
        throw NSError(domain: "SaveMove", code: 101, userInfo: [NSLocalizedDescriptionKey: "Could not retrieve cloud identifier."])
    }
    
    // 3. Create the CoreData entity and store the cloud identifier's string value
    let newMove = Move(context: context)
    newMove.name = name
    newMove.videoCloudIdentifier = cloudIdentifier.stringValue // Store the stable string
    
    try context.save()
}
```
