## **Precise Problem Description**

The issue is a **state mutation cascade in TrimmerViewModel's didSet blocks** that creates an infinite loop during video initialization:

### **Exact Sequence (from logs):**

1. **Trigger**: `setupAsync()` sets `endTime = 12.92` during video loading
2. **Cascade Start**: `endTime didSet` fires correction logic: `if endTime < startTime + oneFrameDuration`
3. **First Correction**: Sets `startTime = endTime - oneFrameDuration` (triggering startTime didSet)
4. **Counter-Correction**: `startTime didSet` fires: `if startTime > endTime - oneFrameDuration` 
5. **Second Correction**: Sets `endTime = startTime + oneFrameDuration` (triggering endTime didSet again)
6. **Infinite Loop**: Steps 2-5 repeat indefinitely, each didSet triggering the other

### **Evidence from Logs:**

```
✅ STEP 3: ViewModel endTime updated to: 12.92          ← Initial setup
✅ STEP 3: ViewModel startTime updated to: 0.3716...     ← First correction
✅ STEP 3: ViewModel startTime updated to: 0.3716...     ← Same value (didSet fired)
✅ STEP 3: ViewModel startTime updated to: 0.745         ← Second correction  
✅ STEP 3: ViewModel startTime updated to: 1.118         ← Third correction
...[40+ more identical corrections]...
✅ STEP 3: ViewModel endTime updated to: 12.7116...      ← Counter-correction
✅ STEP 3: ViewModel endTime updated to: 12.7116...      ← Same value (didSet fired)
✅ STEP 3: ViewModel endTime updated to: 12.44           ← Fourth correction
...[more counter-corrections]...
```

### **Root Cause:**

The didSet blocks contain **mutually dependent correction logic** that assumes only one property changes at a time. When both `startTime` and `endTime` are set simultaneously during `setupAsync()`, the corrections fight each other, creating the infinite loop.

### **Why Our Previous Fix Failed:**

We fixed the SwiftUI navigation issue (export succeeds at line 121), but the underlying **state mutation cascade in TrimmerViewModel** still runs during `.onAppear`, causing the same infinite loop at the ViewModel level rather than the View level.

**The problem is architectural**: The correction logic assumes single-property changes but fails with simultaneous property initialization. The didSet blocks need to be redesigned to handle bulk initialization without triggering mutual corrections.
