The core of the problem lies in a classic SwiftUI anti-pattern: **modifying the state of a view while the view is being drawn**.

Here's what's happening:

1.  Your `AddMoveContainer` view's state changes to `.trimming`.
2.  This state change triggers a rebuild of the view's body, which in turn creates the `TrimmerViewWrapper`.
3.  Inside the `TrimmerViewWrapper`'s initializer (or a method called by it), some code is updating a `@Published` property within your `TrimmerViewModel`.
4.  This `@Published` property change immediately notifies any listening views that they need to update.
5.  This notification causes the `AddMoveContainer` to rebuild its body *again*, creating a new `TrimmerViewWrapper`, which then updates the state again, leading to an **infinite loop**.

The "Publishing changes from within view updates is not allowed" error is SwiftUI's way of telling you that you're caught in this loop. Eventually, the system runs out of memory and crashes, which is why you see the "Message from debugger: killed" log entry.
