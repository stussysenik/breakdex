## **Technical Problem Analysis: PhotosPicker Navigation Architecture**

### **The Core Issue**
The "Change Video" functionality in PreTrimView is architecturally broken. When users tap the button, the AddMoveSelectClipView (containing the PhotosPicker) appears for ~100ms and then disappears immediately, creating a completely broken UX.

### **Root Cause Analysis**
I'm attempting **view-level navigation within a view** using conditional rendering:

```swift
// Current broken approach in PreTrimView:
if showingVideoSelection {
    AddMoveSelectClipView(viewModel: viewModel)
        .onDisappear { 
            showingVideoSelection = false // This fires immediately!
        }
} else {
    // Normal preview content
}
```

**The Problem**: SwiftUI's view lifecycle causes `onDisappear` to fire immediately when `AddMoveSelectClipView` renders, resetting the state and causing the view to vanish in the same render cycle.

### **Architectural Violation**
This violates the **single responsibility principle** and **separation of concerns**:

- ❌ **PreTrimView** is handling both video preview AND navigation logic
- ❌ **State management** is scattered across multiple views instead of centralized
- ❌ **Navigation logic** is inverted - views are managing their own transitions

### **Existing Infrastructure**
The codebase already has a proper state machine:
- `AddMoveContainer` handles view routing based on `AddMoveState`
- `AddMoveViewModel` manages state transitions
- State-driven navigation works correctly for the main flow

### **What I Need Help With**
I need to redesign this to use **proper state-driven navigation**:

#### **Option A: New State in AddMoveState**
```swift
enum AddMoveState {
    case ready
    case loading(progress: Double, status: String)
    case previewing(asset: AVAsset, photosIdentifier: String?)
    case selectingVideo(currentAsset: AVAsset?) // NEW: For video selection mode
    // ... other states
}
```

#### **Option B: Flag-based State Management**
Add a flag to track video selection mode without changing the enum.

#### **Option C: Navigation Coordinator Pattern**
Create a dedicated navigation coordinator to handle complex view transitions.

### **Success Criteria**
- ✅ AddMoveSelectClipView stays visible when "Change Video" is tapped
- ✅ Users can select videos without the view disappearing
- ✅ State transitions are clean and predictable  
- ✅ No PhotosPicker conflicts or lifecycle issues
- ✅ Maintains existing functionality for all other flows

### **Risks & Considerations**
- **Breaking Changes**: May require updates to AddMoveContainer logic
- **State Complexity**: Adding new states increases complexity
- **Testing**: Need to verify all existing navigation flows still work
- **Performance**: Ensure view transitions are smooth

### **Preferred Solution Direction**
I'd recommend **Option A** with a new state, as it:
- Leverages the existing state machine architecture
- Keeps navigation logic in the container where it belongs
- Provides clear state transitions
- Is most maintainable long-term
