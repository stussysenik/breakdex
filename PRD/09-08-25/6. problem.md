## Technical Debrief: Video Rotation Black Screen Fix

### Problem Statement
Users were experiencing black screens when viewing rotated videos in the NameMoveView (naming screen) after trimming and rotating videos in the TrimmerView. The issue specifically occurred during video playback, not during the interactive rotation controls themselves.

### Root Cause Analysis
The problem stemmed from SwiftUI's VideoPlayer component having issues with view-tree transforms. When applying `.rotationEffect()` to containers hosting VideoPlayer, the underlying AVPlayerLayer would enter rendering paths that resulted in:
- Black video frames instead of properly rotated content
- Audio continuing to play normally (confirming the issue was rendering, not playback)
- Inconsistent behavior across different iOS versions and devices

This was a classic example of SwiftUI's declarative rendering model clashing with AVFoundation's imperative video pipeline.

### Solution Architecture
Implemented the fix described in the project documentation (PRD/09-08-25/5.fix.md) which advocates moving rotation transforms from SwiftUI to AVFoundation's native composition system.

#### Key Changes Made:

1. **Removed SwiftUI Rotation Effects**
   - Eliminated all `.rotationEffect()` calls from NameMoveView
   - Updated CustomVideoPlayerView to accept `rotationQuarterTurns` parameter
   - Maintained visual feedback in TrimmerView (where it works correctly)

2. **Implemented AVFoundation Composition Transforms**
   - Created `buildVideoComposition()` function in CustomVideoPlayerView
   - Applied proper transform math: `T · Ruser · Rsrc` where:
     - `T` = translation to keep rotated frame in bounds
     - `Ruser` = user-selected quarter-turn rotation matrix  
     - `Rsrc` = source video's preferredTransform
   - Set appropriate `renderSize` for 90°/270° rotations
   - Used `AVMutableVideoComposition` with `AVMutableVideoCompositionLayerInstruction`

3. **Enhanced Player Configuration**
   - Set `playerItem.videoComposition` for rotated content
   - Enabled `seekingWaitsForVideoCompositionRendering = true` for smooth playback
   - Maintained fallback to direct asset playback when no rotation needed

### Technical Challenges & Resolutions

#### Challenge 1: Import/Scope Issues
**Problem**: Initially created separate `VideoTransformBuilder` utility class, but it wasn't accessible from CustomVideoPlayerView due to build target configuration issues.

**Solution**: Inlined the transform logic directly into CustomVideoPlayerView as a private method, eliminating external dependencies and ensuring 100% reliable access.

#### Challenge 2: Transform Math Precision
**Problem**: Needed to ensure identical transform math between preview and export pipelines.

**Solution**: Implemented exact transform sequence matching the existing TrimmerViewModel:
```swift
// Combine transforms: T · Ruser · Rsrc
let finalTransform = translation.concatenating(Ruser).concatenating(Rsrc)
```

#### Challenge 3: Performance Optimization
**Problem**: VideoComposition rendering can introduce seek latency.

**Solution**: 
- Only applied composition when `rotationQuarterTurns != 0`
- Set `seekingWaitsForVideoCompositionRendering = true` for smooth playback
- Maintained direct asset playback for non-rotated videos

### Implementation Details

#### Code Structure:
```
CustomVideoPlayerView
├── setupPlayer() - Main player setup logic
│   ├── Direct asset playback (no rotation)
│   └── buildVideoComposition() (with rotation)
│
├── buildVideoComposition() - Private method
│   ├── AVMutableComposition creation
│   ├── Transform calculation (T · Ruser · Rsrc)
│   ├── AVMutableVideoComposition setup
│   └── Proper renderSize handling
│
└── setupPlayerFromPhotos() - Photos asset handling
    └── Integrated composition transforms
```

#### Transform Logic:
- **0°**: Identity transforms, natural renderSize
- **90°**: π/2 rotation, translation by naturalSize.height, swapped renderSize
- **180°**: π rotation, translation by naturalSize, natural renderSize  
- **270°**: 3π/2 rotation, translation by naturalSize.width, swapped renderSize
