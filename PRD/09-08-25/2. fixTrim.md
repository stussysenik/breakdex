A simple, robust spec is to keep one source of truth for rotation and trim, render all previews with SwiftUI transforms for immediacy, and then bake those decisions into a single AVFoundation export pipeline that tolerates iCloud-backed assets and odd orientations by design. [1][2][3]

Below is a spec-kit style plan covering UX, data flow, composition math, iCloud handling, performance budgets, and failure modes for an iOS 18–compatible, fault‑tolerant implementation. [1][4][5]

## Goals
- Immediate visual rotation feedback while trimming, with the exact same orientation shown during naming and baked into the exported file. [1]
- Single, resilient export pipeline that handles local and iCloud-only videos, portrait/landscape quirks, slow‑mo, variable frame rates, and very large files. [1][3][2]
- Performant and intuitive UX focused on choosing a video, setting **rotation**, and selecting the **trim** range, with the app managing all technical edge cases. [1]

## UX flow
- Selection → Trimming View: show the asset as-is, enable rotation button cycling 0°/90°/180°/270°, animate with haptics, and read-only scrub preview for trim; all visual transforms use SwiftUI rotationEffect for zero-latency feedback. [1]
- Trim Save → Naming View: carry forward the same rotation and trim; display using SwiftUI transforms to exactly match Trimming View. [1]
- Final Save: a single background export that bakes rotation and trim into the file and returns a URL or data handle for persistence. [1][2]

## Single source of truth
- rotationQuarterTurns: Int in {0,1,2,3} stored in ViewModel and passed through AddMoveState; derive Angle.degrees = quarterTurns * 90 for SwiftUI previews. [1]
- trimRange: CMTimeRange captured from the trimmer component and persisted alongside rotationQuarterTurns until export. [1]
- AssetHandle: enum that captures either a local AVURLAsset, a streamed AVAsset, or a file written via PHAssetResourceManager for assets that aren’t file‑backed. [1][3][6]

## Asset intake (iCloud‑safe)
- Use PHImageManager.requestAVAsset(forVideo:options:resultHandler:) with PHVideoRequestOptions.networkAccessAllowed = true and progressHandler to obtain the playable AVAsset; surface a cancellable progress UI for iCloud downloads. [1][3][7]
- Expect AVAsset to be AVURLAsset or AVComposition; if not AVURLAsset, obtain file data via PHAssetResourceManager.writeDataForAssetResource to a temp file to unify the export path. [1][6]
- When only metadata is locally available, use the progress handler to drive a clear “Downloading from iCloud…” state and allow cancellation or background continuation. [1][7][8]

## Preview rendering
- SwiftUI TrimmerView and NameMoveView both apply rotationEffect(Angle.degrees(rotationQuarterTurns * 90)) for immediate user feedback; keep this purely visual to avoid re-encoding during interaction. [1]
- Reflect rotation changes with .animation(.spring) and haptic impact feedback; announce accessibility labels like “Rotated ninety degrees.” [1]
- Keep AVPlayerLayer/VideoPlayer untransformed; let SwiftUI handle the display rotation so transport and scrubbing remain performant and simple. [1]

## Export pipeline
- Build an AVMutableComposition and insert the selected video track timeRange to implement the trim without decoding the unneeded parts. [1][2]
- Compute a CGAffineTransform that combines the source track’s preferredTransform with the user’s quarter‑turn rotation, plus a translation to keep the rotated frame in bounds. [1][2][9]
- Apply the transform with AVMutableVideoCompositionLayerInstruction.setTransform(_:at:) and set a renderSize that swaps width/height for 90°/270° rotations; attach this to an AVMutableVideoComposition. [1][2][10]
- Use AVAssetExportSession with a quality preset (e.g., Highest/HEVC if available) when any transform is present; avoid Passthrough because arbitrary transforms require a video composition stage. [1][2]
- Export asynchronously to a temp file; on completion, validate duration ≈ trimRange.duration within a tolerance and that rotation is baked by inspecting the output track’s preferredTransform. [1][2]

## Rotation math (composition)
- Let Rsrc be the source track’s preferredTransform (matrix that encodes captured orientation). [1][2]
- Let Ruser be a quarter‑turn rotation matrix $$R(\theta)$$ where $$\theta \in \{0,\frac{\pi}{2},\pi,\frac{3\pi}{2}\}$$, and T be a translation to keep the image in the visible frame after rotation. [1][9][2]
- The layer instruction transform is $$T \cdot R(\theta) \cdot R_{src}$$, and renderSize is (w,h) for 0°/180° or (h,w) for 90°/270°, where (w,h) is the track’s naturalSize after applying preferredTransform. [1][2][9]

## iCloud and Photos integration
- Retrieval: Prefer requestAVAsset(forVideo:), enable networkAccessAllowed, and show progress; PHImageManager caching can be used for thumbnails, but video export should operate on AVAsset or file URLs. [1][3][5]
- Fallback for non-file AVAsset: Use PHAssetResourceManager to write the video resource to a local temp URL before building compositions to reduce export edge cases. [1][6]
- Detect cloud‑only states by attempting requests with networkAccessAllowed off (probe mode) and interpreting nil results, then re‑requesting with networkAllowed + progress if needed; avoid relying on PHImageResultIsInCloudKey alone due to inconsistent semantics. [1][11][8]

## Performance strategy
- Avoid decoding during interaction; previews are visual-only transforms in SwiftUI over AVPlayer playback. [1]
- Compute transforms once per rotation change; cache the derived renderSize and layer instruction inputs until trim or rotation changes. [1]
- Export on a background queue with QoS.userInitiated; track progress via AVAssetExportSession.progress and support cancellation/resume semantics at the UI layer. [1]
- Prefer composition-only timeRange trimming and a single export pass, rather than intermediate files; this minimizes I/O and storage pressure. [1][2]
- Use HEVC where supported to reduce output size, falling back to H.264 for compatibility; keep bit rate targets reasonable for mobile storage. [1]

## Fault tolerance
- Graceful handling for: AVComposition assets without file URLs; iCloud download cancellations; insufficient disk; time range invalidity; unsupported formats; and exporter failures, with actionable, concise error messages. [1][6][3]
- Retry policy: limited exponential backoff for transient exporter errors; immediate fallback to re-materializing the source via PHAssetResourceManager if the input AVAsset was streaming-only. [1][6]
- Validation: after export, verify duration tolerance, playable status, and no unexpected preferredTransform on the output track when rotation was baked. [1][2]

## Data model and state
- TrimmerViewModel: rotationQuarterTurns, trimRange, assetHandle, exportState; conforms to ObservableObject and persists across navigation. [1]
- AddMoveState.naming carries rotation and trim as immutable inputs to the naming view to ensure visual and exported consistency. [1]
- Cancellation tokens for any in-flight Photos/AV export requests to avoid leaked work on navigation back or dismissal. [1][3]

## API choices
- PHImageManager.requestAVAsset(forVideo:options:resultHandler:) as primary intake; use PHVideoRequestOptions.networkAccessAllowed = true and progressHandler. [1][3]
- PHImageManager/PHCachingImageManager for thumbnails and lightweight previews while a full AVAsset is being fetched. [1][5]
- PHAssetResourceManager.writeDataForAssetResource for non‑URL assets or when a stable local file is desired before export. [1][6]
- AVMutableComposition + AVMutableVideoCompositionLayerInstruction.setTransform for rotation/translation + renderSize; export via AVAssetExportSession. [1][2][10]

## Edge cases
- Portrait sources with landscape naturalSize and non-identity preferredTransform; always include preferredTransform in the math to avoid 90° drift. [1][2]
- 90°/270° rotations must swap renderSize; compute translation to keep origin visible after rotation, as AV transforms rotate around top-left. [1][9][2]
- Slow‑motion or time‑mapped assets may come as AVComposition; insert the composition track and trim at composition time, or materialize to file first if export errors occur. [1][6]
- iCloud “optimize storage” may yield degraded thumbnails and nil final image/video until network access is granted; rely on progressHandler and retries, not PHImageResultIsInCloudKey. [1][7][11]

## Testing plan
- Matrix: device generations including older CPUs/less RAM; storage nearly full; network off/poor; iCloud enabled/disabled; portrait/landscape; HEVC/H.264; HDR/SDR; slo‑mo and time‑lapse. [1]
- Golden assets: a curated set that exercises preferredTransform variants, variable frame rates, and large durations (10–30 min). [1]
- Assertions: output has expected orientation (no residual preferredTransform when baked), expected duration within ±1 frame, and expected dimensions given rotation. [1][2]

## Performance budgets
- UI: rotation animations at 60 fps by isolating to SwiftUI layer transforms; no re-encoding on interaction. [1]
- CPU: a single export pass with transform and timeRange; no intermediate composition renders unless required by input abnormalities. [1][2]
- Memory: stream-based export; avoid loading full samples in memory; use temp files and clean up aggressively on completion/cancel. [1]
- Battery: defer heavy exports on low power mode unless explicitly requested; offer background export with notifications on completion. [1]

## Observability
- Instrument Photos request progress, iCloud download timings, export durations, and failure reasons; log rotationQuarterTurns, renderSize, and exporter preset to correlate performance. [1][3]
- Include soft-assert telemetry for when preferredTransform was identity vs non-identity to detect upstream orientation anomalies in the wild. [1][2]

## Security and privacy
- Request limited Photos library access scoped to user selection; never persist original URLs beyond the session; delete temp files after export. [1]
- Respect cellular vs Wi‑Fi for iCloud downloads if desired by product; when blocked, present an affordance to proceed on cellular. [1][7]

## Implementation checklist
- Visual parity
  - SwiftUI rotationEffect + haptics + accessibility announcements on incrementing quarter turns. [1]
  - Name view mirrors TrimmerView transforms using the same rotationQuarterTurns. [1]
- State and navigation
  - rotationQuarterTurns and trimRange propagated through AddMoveState and persisted across back/forward. [1]
- Intake
  - requestAVAsset with progress, fallback to PHAssetResourceManager for non‑URL assets. [1][3][6]
- Export
  - AVMutableComposition insertTimeRange(trimRange), compute T·Ruser·Rsrc, renderSize swap for 90/270, LayerInstruction.setTransform, AVAssetExportSession export. [1][2][10]
- Validation and cleanup
  - Verify orientation baked, duration tolerance, remove temp files, persist final URL. [1][2]

## Trade-off table

| Concern | Option A | Option B | Recommendation |
|---|---|---|---|
| iCloud-backed asset materialization | Work directly with requestAVAsset result | Write a local file via PHAssetResourceManager | A by default; B when asset is AVComposition or export errors, then retry using local file for stability. [3][6] |

All of the above keeps the interaction dead simple while making the pipeline resilient: pick a video, set **rotation**, set **trim**, and the system does the right thing across orientations, iCloud, and large files with a single consistent exporter. [1][3][2][7]
