### Engineering Spec: Resolve Invalid State Transition to Display Pre-Trim View

### **1. Objective**

Modify the `AddMoveViewModel` to transition to the correct state (`.loaded`) after the real-time video loading pipeline completes. This will ensure the `PreTrimContainerView` is displayed, allowing the user to preview the video before proceeding to the full trimming interface.

### **2. Background**

The new `VideoLoadingService` successfully provides a real-time progress stream. However, upon receiving the final `.success` event, the `AddMoveViewModel` attempts to transition the UI state directly from `.loading` to `.trimming`. This transition is explicitly disallowed by the state machine rules in `AddMoveContainer.swift`, which causes a logged `INVALID STATE TRANSITION` error and forces a UI reset.

The intended flow is `Loading` -\> `Loaded` (displaying `PreTrimContainerView`) -\> `Trimming` (displaying `TrimmerViewWrapper`).

### **3. Required Code Changes**

**File to Modify**: `AddMoveViewModel.swift`

**Precise Instructions**:

1.  Navigate to the function where you handle the `AsyncThrowingStream<VideoLoadEvent, Error>` returned by the `VideoLoadingService`. This will likely be inside a `Task` that iterates through the stream events (e.g., `for try await event in progressStream`).

2.  Locate the `case .success(let player, let asset):` block within that loop. This block executes when the video is fully downloaded, processed, and buffered.

3.  Identify the line of code that sets the view model's state. It is currently making an **incorrect** transition to the `.trimming` state. It will look similar to this:

    ```swift
    // IDENTIFY AND REMOVE THIS LINE
    self.state = .trimming(asset: asset, photosIdentifier: self.photosIdentifier, rotationQuarterTurns: 0) 
    ```

4.  **Replace** that line with the following code to transition to the `.loaded` state instead:

    ```swift
    // REPLACE WITH THIS LINE
    self.state = .loaded(asset: asset, photosIdentifier: self.photosIdentifier, rotationQuarterTurns: 0)
    ```

**Reasoning**: The `AddMoveContainer` is configured to display the `PreTrimContainerView` when the state is `.loaded`. The container's validation logic explicitly permits the `loading` -\> `loaded` transition. This change aligns the `AddMoveViewModel`'s behavior with the container's established rules.

### **4. Verification Criteria**

To confirm the fix is successful, perform the following steps:

1.  ✅ Launch the "Add Move" flow and select any video from the Photos library.
2.  ✅ Observe the new real-time progress bar complete its three stages (iCloud download, metadata load, buffering).
3.  ✅ **Confirm that upon 100% completion, the UI transitions directly to the `PreTrimContainerView`**. This view should display the video player and a "Next" or "Trim Video" button, but not the full trimming controls.
4.  ✅ Verify that the application is stable and does not reset to the initial view.
5.  ✅ Check the console logs to ensure no `❌ INVALID STATE TRANSITION DETECTED!` errors are present for this workflow.

### **5. Out of Scope**

  * **Do not modify `AddMoveContainer.swift`**. Its state machine is the source of truth and is behaving correctly by rejecting the invalid transition.
  * **Do not modify `VideoTransformBuilder.swift`**. The `Invalid frame dimension` error logged is a secondary symptom of the UI reset cycle and will be resolved once the primary state transition issue is fixed.
