RESEARCH:

Short answer: Robust iOS 18 video loading hinges on three pillars: selecting the right PHVideoRequestOptions (deliveryMode, version, network access), adding explicit timeout/cancellation and retries around PhotoKit requests, and falling back to PHAssetResourceManager streaming when iCloud downloads stall, with added attention to new spatial media subtypes in iOS 18-era PhotoKit updates. [1][2][3][4][5]

### iCloud downloads
- Detect iCloud-only assets using the info dictionary key PHImageResultIsInCloudKey and reissue the request with networkAccessAllowed when needed for reliability. [8][9]
- Use PHVideoRequestOptions.progressHandler for download progress and support cancellation via the stop pointer in the progress handler for stuck transfers. [3][10]
- Always keep the request ID and cancel stuck work with cancelImageRequest or cancelDataRequest, then fall back to PHAssetResourceManager.requestData to stream the resource to a file and rebind with AVAsset/AVPlayerItem. [4][11][12][5]
- For progressive playback while the full original downloads, request .fastFormat or .mediumQualityFormat to stream from iCloud, then upgrade quality as subsequent requests complete. [13][14]

### PHVideoRequestOptions
- Prefer deliveryMode .automatic for broad compatibility, letting Photos choose the best representation given connectivity, power, and device conditions. [2]
- Set version based on intent: .current for user-edited results and .original for untouched masters, and consider surfacing a user setting to disambiguate when both are relevant. [15][16][17]
- Enable isNetworkAccessAllowed when handling iCloud assets or when PHImageResultIsInCloudKey is true, and disable it for offline-only modes to prevent unexpected network fetches. [1][8]

### Errors and retries
- Inspect the info dictionary for PHImageErrorKey to capture underlying errors, treat PHImageCancelledKey distinctly, and ignore degraded callbacks until a full-quality completion arrives. [18][4]
- Handle Photos-domain errors via PHPhotosError.Code and branch logic for user-denied access, configuration restrictions, and resource issues; treat “invalidResource (3302)” as non-retryable and surface actionable UI. [19][20]
- Use tiered retries: immediate retry for transient network issues, backoff with cancellation for low progress plateaus, and switch to PHAssetResourceManager streaming when PhotoKit delivery fails to complete. [3][12][5]

### Cancellation and timeouts
- Wrap PhotoKit callbacks in Swift concurrency with withCheckedContinuation and withTaskCancellationHandler, capturing the request ID so cancellation cleanly maps to cancelImageRequest on timeout. [21][4]
- Prefer structured timeouts (Task.sleep + cooperative cancel) over ad hoc timers, and cancel in both the task and PhotoKit layers to avoid orphaned downloads. [22][4]

### Memory and performance
- Stream large assets to disk with PHAssetResourceManager.requestData/writeData instead of materializing entire videos in memory, and cancel promptly when views disappear. [5][23][12]
- Keep concurrent video requests bounded and always hold on to request IDs for deterministic cleanup, especially when loading multiple thumbnails plus a primary player item. [4][11]
- For faster first frame while originals download, request a streaming-capable representation (fast/medium format) and upgrade to highQualityFormat once local or full-res data is available. [13][14]

### Video formats and HDR/SDR
- Account for spatial photo/video as a first-class subtype in the iOS 18 era; fetch with a predicate on mediaSubtypes and use AVAssetPlaybackAssistant to identify spatial playback needs. [7][6]
- For HDR scenarios, validate the device/display HDR capabilities and plan tone mapping behavior in the playback stack, referencing recent HDR guidance for dynamic media experiences. [24]
- Gracefully degrade unsupported or uncommon codecs by falling back to on-device transcoding workflows after resource extraction, and gate advanced paths behind isNetworkAccessAllowed checks. [1][25]

### iOS 18–specific notes
- PhotoKit updates around iOS 18 emphasize spatial media and PhotosPicker matching, which can affect fetch predicates, picker configuration, and downstream playback assumptions. [6][7]
- No new deprecations are highlighted on the PhotoKit updates page for core video request APIs; continue to use PHImageManager requestAVAsset/requestPlayerItem with updated options. [6][26]
- The redesigned Photos app does not change PhotoKit’s permission flow; leverage PhotosPicker improvements for limited-library flows and change history APIs to keep UI in sync. [27][6]

### Async/await integration
- Convert PhotoKit callbacks to async with continuations, resume only on full-quality completions (ignore degraded), and map cancellation to cancelImageRequest for correctness. [21][4]
- Use progressHandler bridges to AsyncStream for UI updates, and ensure MainActor updates for progress bars and state changes to avoid UI races. [3][22]
- Expose a single “load video” async endpoint that internally fans out to PhotoKit request, timeout, and PHAssetResourceManager fallback paths for predictable behavior. [4][5]

### Testing and debugging
- To simulate iCloud-only behavior, enable iCloud Photos with Optimize Storage so PHImageResultIsInCloudKey can be observed during requests. [28]
- Validate progress and cancellation paths by watching the progressHandler and confirming cancellation via PHImageCancelledKey in the info dictionary. [3][18]

### Concrete patterns to adopt
- Stuck-download recovery: detect low or stalled progress for N seconds, cancelImageRequest, switch to PHAssetResourceManager.requestData to a temp file, and create AVURLAsset/AVPlayerItem from disk. [3][4][5]
- Compatibility-first configuration: deliveryMode .automatic, version .current for edited output, networkAccessAllowed true when iCloud keys appear, and opportunistic streaming via fast/medium quality. [2][15][8][13][14]
- Defensive error handling: branch on PHPhotosError.Code, treat invalidResource as a hard failure, and surface actionable recovery like “Download Original in Photos” or “Try Again on Wi‑Fi.” [19][20]

### Minimal async wrapper (pattern)
- Wrap PhotoKit requests with withCheckedThrowingContinuation, store the PHImageRequestID, and cancel it inside withTaskCancellationHandler to guarantee cleanup on timeout or navigation. [21][4]

Example outline (omit in prod if not needed; shown for structure): [21]
```swift
func requestAVAssetAsync(
  for asset: PHAsset,
  options: PHVideoRequestOptions
) async throws -> AVAsset {
  var requestID: PHImageRequestID?
  return try await withTaskCancellationHandler(handler: {
    if let id = requestID { PHImageManager.default().cancelImageRequest(id) }
  }, operation: {
    try await withCheckedThrowingContinuation { cont in
      requestID = PHImageManager.default().requestAVAsset(forVideo: asset, options: options) { avAsset, _, info in
        if let error = info?[PHImageErrorKey] as? Error { cont.resume(throwing: error); return }
        if (info?[PHImageCancelledKey] as? Bool) == true { cont.resume(throwing: CancellationError()); return }
        guard let a = avAsset else { cont.resume(throwing: NSError(domain: "Video", code: -1)); return }
        cont.resume(returning: a)
      }
    }
  })
}
```

If adopting this plan, the pipeline will be resilient to iCloud stalls, edited-vs-original conflicts, and diverse formats (including spatial media), while remaining cancellable and memory-safe across concurrent loads in iOS 18. [3][15][2][4][6]
