Of course. The black screen in the Pre-Trim view is caused by a race condition where the `AVPlayer` is created and passed to the view before its underlying `AVPlayerItem` has finished loading and become ready for playback.

The logs confirm this diagnosis with the repeated warning:
`⚠️ 🎬 UNIFIED_VIDEO_PLAYER_VIEWMODEL (preview): startPlayback() called, but item is not ready (status: 0). Waiting for readiness.`

This indicates that playback is requested, but the player item's status is still `.unknown`, resulting in a black, non-playing video.

-----

## The Fix: Asynchronously Load the Player Item

The solution is to explicitly wait for the `AVPlayerItem`'s status to become `.readyToPlay` *before* creating the `UnifiedVideoPlayerViewModel` and transitioning to the `.previewing` state. This eliminates the race condition.

You'll need to modify the `loadVideo(from item: PhotosPickerItem)` function in **`AddMoveViewModel.swift`**.

### `AddMoveViewModel.swift` - Code Modification

Here is the corrected code block. You should replace the entire `// --- Completion ---` section at the end of the `loadVideo` function with this.

**Before (Problematic Code):**

```swift
// --- Completion ---
guard let asset = finalAsset else {
    throw NSError(domain: "AddMoveViewModel", code: -3, userInfo: [NSLocalizedDescriptionKey: "Failed to load video asset"])
}

// 1. Create the final player with the loaded asset
let player = AVPlayer(playerItem: AVPlayerItem(asset: asset))

// 2. Create the UnifiedVideoPlayerViewModel with the now-ready player
let playerViewModel = UnifiedVideoPlayerViewModel(
    player: player,
    mode: .preview,
    appContainer: AppContainer.shared
)

// 3. Get rotation and transition to previewing state
let rotation = await asset.rotation()
logger.info("🎬 VIEWMODEL: ✅ Video loaded and player created. Transitioning to previewing.")

state = .previewing(
    playerViewModel: playerViewModel,
    asset: asset,
    photosIdentifier: photosIdentifier,
    rotationQuarterTurns: rotation
)
```

**After (Corrected Code):**

```swift
// --- Completion ---
guard let asset = finalAsset else {
    throw NSError(domain: "AddMoveViewModel", code: -3, userInfo: [NSLocalizedDescriptionKey: "Failed to load video asset"])
}

// 1. Create the player item from the loaded asset
let playerItem = AVPlayerItem(asset: asset)

// 2. Asynchronously wait for the item's status to be ready. THIS IS THE FIX.
try await playerItem.load(.status)

// 3. Guard against loading failures
guard playerItem.status == .readyToPlay else {
    logger.error("🎬 VIEWMODEL: 🚨 PlayerItem failed to become ready. Status: \(playerItem.status.rawValue), Error: \(String(describing: playerItem.error))")
    throw playerItem.error ?? NSError(domain: "AddMoveViewModel", code: -4, userInfo: [NSLocalizedDescriptionKey: "AVPlayerItem failed to load."])
}

// 4. Now, create the player with a GUARANTEED ready-to-play item
let player = AVPlayer(playerItem: playerItem)

// 5. Create the UnifiedVideoPlayerViewModel
let playerViewModel = UnifiedVideoPlayerViewModel(
    player: player,
    mode: .preview,
    appContainer: AppContainer.shared
)

// 6. Get rotation and transition to the previewing state
let rotation = await asset.rotation()
logger.info("🎬 VIEWMODEL: ✅ Video loaded and player item is ready. Transitioning to previewing.")

state = .previewing(
    playerViewModel: playerViewModel,
    asset: asset,
    photosIdentifier: photosIdentifier,
    rotationQuarterTurns: rotation
)
```

-----

## Why This Works

By introducing `try await playerItem.load(.status)`, we explicitly pause the execution of the `loadVideo` function until the operating system has finished processing the video asset and marked the `AVPlayerItem` as ready.

This ensures that when `UnifiedVideoPlayerViewModel` is initialized and `CustomVideoPlayerView` appears, the video is already prepared for playback, completely preventing the black screen issue. ✅
