The ambiguous expression is caused by declaring a closure parameter as bare Result without generic arguments; change it to Result<Void, Error> (or Swift.Result<Void, Error>) in the withCheckedThrowingContinuation block. [1]

### What to change
- Replace the declaration of cleanupAndResume from: [1]
  - let cleanupAndResume: (Result?) -> Void = { result in [1]
- To: [1]
  - let cleanupAndResume: (Result<Void, Error>?) -> Void = { result in [1]

### Why this fixes it
- withCheckedThrowingContinuation infers a CheckedContinuation<Void, Error> in this block because success paths call continuation.resume(returning: ()) and failure paths call continuation.resume(throwing:), so resume(with:) expects a Result<Void, Error>, and leaving Result generic arguments unspecified makes the expression ambiguous. [1]

### Optional alternative
- If preferring not to pass an optional Result, use an optional Error and branch: [1]
  - let cleanupAndResume: (Error?) -> Void = { error in
      if let error { continuation.resume(throwing: error) } else { continuation.resume(returning: ()) }
    } [1]
