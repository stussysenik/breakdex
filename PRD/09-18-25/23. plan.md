You're stuck on the loading screen because the logic waiting for the video to become playable doesn't correctly handle loading failures, causing it to wait forever.

-----

### The Root Cause: Incomplete Failure Handling

The issue is in the `loadVideo(from:)` function in **`AddMoveViewModel.swift`**. The code sets up an observer to wait for the `AVPlayerItem`'s status to become `.readyToPlay`. However, if the status becomes `.failed`, the code doesn't recognize this failure and never stops waiting, leading to the infinite loading screen.

The logs confirm this: the last thing we see is the app waiting for the item to become ready, but it never does. Your own `PlayerItemStatusMonitor.swift` file actually contains a more robust implementation that correctly checks for this failure case. We need to apply that same robust logic here.

-----

### The Fix: Add Explicit Failure Checking

We need to modify the `checkReadiness` closure inside `AddMoveViewModel.swift` to properly handle the `.failed` state.

#### **File to Modify: `AddMoveViewModel.swift`**

In the `loadVideo(from:)` function, locate the `checkReadiness` closure and update it as follows.

**Before (Problematic Code):**

```swift
let checkReadiness = { [weak self] in
    guard let self = self else { return }
    
    // ...
    
    // The problem is here: It only checks for .readyToPlay
    guard playerItem.status == .readyToPlay else {
        self.logger.info("🎬 VIEWMODEL: 📊 Player item status: \(playerItem.status.rawValue), keys loaded but waiting for readyToPlay...")
        return
    }
    
    // ... Buffering checks and success resume ...
}
```

**After (Corrected Code):**

```swift
let checkReadiness = { [weak self] in
    guard let self = self else { return }

    // CRITICAL: Check for a failure state and exit early.
    if playerItem.status == .failed {
        self.logger.error("🎬 VIEWMODEL: 🚨 Player item failed during readiness check.")
        cleanupAndResume(.failure(playerItem.error ?? NSError(domain: "AddMoveViewModel", code: -4, userInfo: [NSLocalizedDescriptionKey: "AVPlayerItem failed to load."])))
        return
    }

    // Now, check for the success state.
    guard playerItem.status == .readyToPlay else {
        self.logger.info("🎬 VIEWMODEL: 📊 Player item status: \(playerItem.status.rawValue), keys loaded but waiting for readyToPlay...")
        return
    }
    
    // ... (The rest of the buffering checks and success resume logic remains the same) ...
    
    // Check buffering progress
    let requiredBufferDuration: TimeInterval = 1.0
    var bufferedDuration: TimeInterval = 0.0
    
    if let firstRange = playerItem.loadedTimeRanges.first?.timeRangeValue {
        bufferedDuration = CMTimeGetSeconds(firstRange.duration)
    }
    
    if bufferedDuration >= requiredBufferDuration || playerItem.isPlaybackBufferFull || playerItem.isPlaybackLikelyToKeepUp {
        self.logger.info("🎬 VIEWMODEL: ✅ Player item is ready and sufficiently buffered!")
        cleanupAndResume(nil)
    }
}
```

-----

### Why This Works

This change makes the video loading process resilient. It no longer assumes the video will always load successfully. Now, it will correctly:

1.  **Succeed:** If the item becomes `.readyToPlay`, it proceeds as intended.
2.  **Fail:** If the item becomes `.failed`, it immediately stops waiting and throws an error, which will correctly display an error message to the user instead of hanging indefinitely. ✅
