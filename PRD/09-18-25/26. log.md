Root cause: the call explicitly specializes withCheckedThrowingContinuation as <Void, any Error>, but this function only has a single generic parameter T and already fixes the error type to any Error, which makes the compiler mis-pick the overload with isolation:function:_ and then misinterpret the trailing closure, yielding all three errors. [1][2]

### Fix
Replace the opening line with a non-specialized call and (optionally) annotate the continuation type; no angle brackets should be provided at the call site. [1][3]

```swift
try await withCheckedThrowingContinuation { (continuation: CheckedContinuation<Void, Error>) in
    // ... your existing body unchanged ...
}
```

This matches the documented signature func withCheckedThrowingContinuation<T>(isolation: isolated (any Actor)?, function: StaticString = #function, _ body: (CheckedContinuation<T, any Error>) -> Void) async throws -> T, where only T is generic and the error is already any Error. [1]

### Why those errors
- Generic parameter 'T' could not be inferred arises because the compiler cannot reconcile the incorrect explicit specialization <Void, any Error> with a function that only exposes one generic parameter T. [1][4]
- Missing arguments for parameters 'function', #3 in call and Trailing closure passed to parameter of type 'any Actor' occur because the bad specialization steers resolution to the overload that takes isolation:function:_:, causing the trailing closure to be treated as the isolation argument of type any Actor rather than the final closure parameter. [1]

### Optional inference aid
If the enclosing async throws function returns Void and the compiler still complains about inferring T, add an explicit cast to Void after the call to help inference. [5]

```swift
try await withCheckedThrowingContinuation { continuation in
    // ...
} as Void
```

### Small usage notes
- Inside the body, resume exactly once using either continuation.resume(returning: ()) or continuation.resume(throwing: someError), which is the intended throwing-bridge behavior. [2][6]
- Do not pass explicit generic arguments to generic functions in Swift calls; let the compiler infer them from context and annotations like the continuation type. [7][3]
