### **Fix: Correcting the `CGAffineTransform` for Video Rotation**

This plan directly corresponds to **Fix 2.2** of the implementation plan in the main specification. The goal is to ensure the transformation logic is mathematically sound, resulting in a true WYSIWYG preview.

#### 1\. The Core Problem

The current implementation calculates an incorrect `CGAffineTransform`. For a 90-degree rotation, it should swap the video's width and height and then translate it back into the new frame. The logs and the image confirm this translation step is being calculated incorrectly, causing the cropping.

#### 2\. The Solution: First-Principles Matrix Transformation

The engineer must rewrite the transformation logic inside `VideoTransformBuilder` to correctly account for the video track's original orientation (`preferredTransform`) and the desired rotation.

  * **Action:** Implement the following logic to build a correct transformation matrix. This ensures that regardless of the video's original orientation, the final rotated preview is centered and scaled properly.

  * **Command to Locate Faulty Code:**
    `GrepTool(pattern="AVMutableVideoCompositionLayerInstruction", path="Video/VideoTransformBuilder.swift")`

  * **Refined Code Snippet (`VideoTransformBuilder.swift`):**

    ```swift
    // Inside a function like createPlayerItem or exportVideo

    // ... after getting the videoTrack
    let layerInstruction = AVMutableVideoCompositionLayerInstruction(assetTrack: videoTrack)

    // 1. Load the track's existing properties
    let preferredTransform = try await videoTrack.load(.preferredTransform)
    let naturalSize = try await videoTrack.load(.naturalSize)

    // 2. Determine the render size after rotation
    let isPortrait = naturalSize.height > naturalSize.width
    let isRotated90or270 = quarterTurns % 2 != 0
    let renderSize: CGSize

    if isRotated90or270 {
        renderSize = CGSize(width: naturalSize.height, height: naturalSize.width)
    } else {
        renderSize = naturalSize
    }

    // 3. Build the new transform by composing rotation and translation
    var finalTransform = CGAffineTransform.identity
    switch quarterTurns {
    case 1: // 90 degrees
        finalTransform = CGAffineTransform(translationX: renderSize.width, y: 0)
        finalTransform = finalTransform.rotated(by: .pi / 2)
    case 2: // 180 degrees
        finalTransform = CGAffineTransform(translationX: renderSize.width, y: renderSize.height)
        finalTransform = finalTransform.rotated(by: .pi)
    case 3: // 270 degrees
        finalTransform = CGAffineTransform(translationX: 0, y: renderSize.height)
        finalTransform = finalTransform.rotated(by: .pi * 1.5)
    default: // 0 degrees
        finalTransform = .identity
    }

    // 4. IMPORTANT: Pre-concat with the asset's own preferred transform
    // This handles videos that were already shot sideways or upside-down.
    finalTransform = preferredTransform.concatenating(finalTransform)

    layerInstruction.setTransform(finalTransform, at: .zero)

    // ... continue building the composition with the renderSize and layerInstruction
    let videoComposition = AVMutableVideoComposition()
    videoComposition.renderSize = renderSize
    // ... assign instructions and frame duration

    // Return the new AVPlayerItem with the videoComposition applied
    let playerItem = AVPlayerItem(asset: composition)
    playerItem.videoComposition = videoComposition
    ```

### 2. Functional Requirements

#### **FR-1: Resilient Asset Import**
The system must handle video imports from local storage or iCloud with high reliability.
* **Memory Efficiency:** Large video files must be imported via a streaming mechanism to prevent memory overload and crashes.
* **Stateful Retries:** For assets in iCloud, the import mechanism must be resilient to transient network failures, implementing a stateful retry strategy with exponential backoff and jitter. The operation must be **idempotent**.

#### **FR-2: Atomic Save Operation**
The save process must be a transactional unit of work, ensuring data is never left in an inconsistent state.
* **Strict Sequence:** The operation must follow this exact sequence:
    1.  Export the processed `AVAsset` to a temporary file.
    2.  Atomically save the temporary file to the "BreakDex" Photos album and retrieve its `localIdentifier`.
    3.  Save the move's metadata, including the `localIdentifier`, to CoreData.
    4.  Delete the temporary file.
* **Rollback on Failure:** If any step after the Photos save fails, the newly created `PHAsset` *must* be deleted from the "BreakDex" album to ensure consistency.

#### **FR-3: Single Source of Truth & Album Management**
The "BreakDex" Photos album is the absolute source of truth for all video assets.
* **Idempotent Album Handling:** On every save, the system must check for the "BreakDex" album. If it exists, the asset is added. If not, it is created. The system must **never** create a duplicate or empty album.

#### **FR-4: Data Consistency & Reconciliation**
A reconciliation process is required to handle catastrophic failures (e.g., an OS crash mid-transaction).
* **Startup Verification:** On every app launch, the system will compare `localIdentifier`s in the "BreakDex" album against those in CoreData.
* **Orphan Cleanup:** Any asset in the album but not in CoreData is an "orphan" and must be automatically deleted.

#### **FR-5: Deterministic Teardown & Memory Safety**
All components in the video pipeline must be free of memory leaks.
* **Retain Cycle Elimination:** The identified retain cycle in `TrimmerViewModel` must be resolved.
* **Resource Invalidation:** All observers and `CADisplayLink` instances must be explicitly invalidated in a `teardown()` method, which must be called during state transitions.

#### **FR-6: Correct Video Transformation (WYSIWYG)**
Visual transformations in the trimmer must exactly match the saved asset.
* **Lightweight Previews:** Rotation previews in the UI must be instantaneous and lightweight, not triggering heavyweight video processing.
* **Correct Transform Logic:** The final exported video must apply a mathematically correct `CGAffineTransform` that accounts for the video's original orientation, ensuring it is not cropped or improperly rotated.
