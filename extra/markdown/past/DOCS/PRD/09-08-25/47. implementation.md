 Short answer: Route “Change Video” through the app’s state machine and present a dedicated, full‑screen selection mode that’s driven by a single source of truth, with a Photos‑grade grid powered by PHCachingImageManager, AsyncStream‑based progress, and file‑backed asset resolution, so the experience feels native and never flickers or dismisses unexpectedly. [1][2]

## Objectives
- Present a native‑feeling, full‑screen video gallery that remains visible until pick or cancel, with predictable, state‑driven navigation and no inline conditional view swaps. [1][3]
- Fetch and display video assets efficiently with PHFetchOptions + PHCachingImageManager, prefetching, cancelation, and iCloud progress for smooth scrolling and fast thumbnails. [1][2]
- Commit to single‑owner state and model lifetimes to prevent premature onDisappear and view churn while keeping PhotosPicker or custom grid UX stable. [1][4]

## Scope
- In scope: state design, container‑driven routing, Photos grid module, asset fetching/caching/progress, selection feedback, and performance guardrails for iOS‑native feel. [1][2]
- Out of scope: server sync, non‑Photos sources, and features beyond single‑select plus basic filtering/sorting for initial release. [1][2]

## State and navigation
- Add a dedicated selectingVideo state to AddMoveState and transition via view‑model intents (beginChangeVideo, didPickVideo, cancelChangeVideo) owned by the container, not leaf views. [1][4]
- Present AddMoveSelectClipView as a fullScreenCover or a NavigationStack destination keyed off AddMoveState, never via inline if/else in the same body hierarchy to avoid immediate onDisappear. [1][3]
- Keep model ownership in the container with @StateObject, pass into children as @ObservedObject, and never construct selection view models inside the selection view body. [1][4]

## Photos integration
- Use PHPhotoLibrary authorization flow before fetching, then PHFetchOptions with a creationDate sort descriptor and a predicate for video mediaType. [1][2]
- Fetch assets via PHAsset.fetchAssets(with:.video, options:) and enumerate lazily for pagination, deferring thumbnail requests until the grid needs them. [1][2]
- For embedded picker variants or future parity, validate against PhotosPicker behaviors but prefer custom grid for full control and a native look. [1][5]

## Grid layout and visuals
- Use LazyVGrid with three adaptive columns on compact width and four to six on regular width, using minimal inter‑item spacing and .aspectFill crop to emulate Photos rows. [1][6]
- Compute thumbnail targetSize from cell size times UIScreen.scale to ensure crisp rendering without oversizing, and clip to rounded rect with a small corner radius consistent with modern Photos visuals. [1][2]
- Overlay duration labels at bottom‑right for videos and show a subtle gradient scrim for readability without deviating from native feel. [1][2]

## Selection feedback
- Single‑select by default: tap applies a light haptic and overlays a checkmark.circle.fill with a brief spring scale + fade, then calls didPickVideo to return to preview. [1][2]
- Use a semi‑transparent highlight that does not obscure thumbnail content, and ensure VoiceOver labels announce selection with asset duration for accessibility. [1][2]
- Keep selection gestures fast by deferring any heavy PHAsset resolution to the view model after the UI acknowledges the tap. [1][2]

## Performance and caching
- Use PHCachingImageManager for thumbnail requests with startCachingImages and stopCachingImages driven by onAppear/onDisappear of rows and on scroll prefetch windows. [1][2]
- Request thumbnails with contentMode .aspectFill and a targetSize matching cell pixel size, marking options.deliveryMode as .opportunistic to allow quick, degraded images followed by high‑quality updates. [1][2]
- Batch prefetch the next N rows based on scroll velocity and cancel requests for cells that scrolled offscreen to reduce wasted work. [1][2]

## Async, progress, and iCloud
- PhotosClient returns an AsyncThrowingStream for progress and a typed async result for the final asset/URL, handling PHVideoRequestOptions.networkAccessAllowed and cancelImageRequest on Task cancellation. [1][2]
- Show progress for iCloud‑backed videos inline in the selected cell and relay completion back to the container to close the selection screen only after the asset is ready or a placeholder is acceptable. [1][2]
- Prefer file‑backed materialization for downstream AVFoundation pipelines that require AVPlayerItem.videoComposition, falling back to preview‑only playback if export is not imminent. [1][2]

## Error handling
- Permission denied: present an inline state with a “Grant Access” CTA to Settings and a compact explanation, and allow cancel to return to preview without state loss. [1][2]
- iCloud offline: surface a banner in the selection UI and allow selecting locally available videos while queuing downloads if the user insists, with clear progress feedback. [1][2]
- Timeouts/cancel: ensure all PhotoKit requests are canceled when dismissing the selection screen and no orphaned callbacks can mutate state post‑dismiss. [1][3]

## Accessibility and interaction
- Ensure cells are large enough for touch targets, with VoiceOver labels describing “Video, duration mm:ss, creation date,” and add an accessibility action “Select video.” [1][2]
- Support Smart Invert and Dynamic Type for labels in headers and any metadata overlays, while keeping the grid density consistent. [1][2]
- Respect swipe‑to‑dismiss if implemented via fullScreenCover by providing a visible cancel button and preventing accidental dismissal during download. [1][3]

## Telemetry
- Log time to first grid paint, scroll hitch count, average thumbnail latency, iCloud download completion rate, and cancel rate from selection screen. [1][4]
- Record state transitions into and out of selectingVideo to ensure no immediate onDisappear loops or flickers regress. [1][3]

## Testing plan
- Navigation: rapid taps on “Change Video,” cancel, and pick across devices and orientations to verify the selection screen remains visible until explicit dismissal. [1][3]
- Performance: large libraries and iCloud‑only albums, measuring scroll smoothness and thumbnail load timing with and without caching. [1][2]
- Edge cases: permission denied, limited library selection, offline mode, and device with low memory while rapidly scrolling the grid. [1][2]

## Acceptance criteria
- Tapping “Change Video” reliably presents the full‑screen gallery, which stays visible until a pick or cancel, with zero immediate onDisappear dismissals. [1][3]
- Thumbnails load quickly with visible progressive updates and smooth scrolling, and selecting a clip feels instantaneous with native haptics and overlay feedback. [1][2]
- After selection, navigation returns to previewing with the correct asset, and no orphaned PhotoKit requests continue running after dismissal. [1][4]

## Rollout
- Ship behind a “NativeGallery” feature flag and collect telemetry on presentation stability, scroll performance, and selection latencies, then roll to 100% after validation. [1][4]
- Keep a fallback to system PhotosPicker inline sheet if the custom gallery detects unavailable authorization or severe performance regressions during beta. [1][2]
