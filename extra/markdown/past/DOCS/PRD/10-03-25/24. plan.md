The root cause is a classic SwiftUI state synchronization issue. The view's local state for rotation (`@State private var previewRotationDegrees`) is falling out of sync with the authoritative state in the `TrimmerViewModel`.

Here's the chain of failure according to the logs:

1.  **Correct Initialization**: When the 90° video loads, the view is initialized, and `previewRotationDegrees` is correctly set to `90.0`. The log confirms this: `initial_rotation_degrees="90.0"`. The video preview looks correct.
2.  **State Desynchronization**: For reasons related to SwiftUI's view lifecycle, the `previewRotationDegrees` state incorrectly reverts to `0.0` before you press the button.
3.  **The Flip**: When you press the rotate button, the action code reads the now-incorrect state (`0.0`) as its starting point. It correctly calculates that the *new total rotation* should be 180° (`90° intrinsic + 90° user-applied`). It then sets the state directly from `0.0` to `180.0`.
4.  **The Result**: The view jumps 180°, which you perceive as a flip, instead of making a smooth 90° turn from its previous state.
