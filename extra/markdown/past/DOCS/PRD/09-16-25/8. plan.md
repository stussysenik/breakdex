### **Engineering Spec: Refactor Pre-Trim Flow to Unify State and Implement Video Loading**

### **1. Objective**

Fully resolve the empty video player issue by undertaking a two-part fix:

1.  **Implement** the missing video loading functionality in the `UnifiedVideoPlayerViewModel.loadVideo()` method.
2.  **Refactor** the `PreTrimContainerView` and `PreTrimView` to share a single, unified instance of the `UnifiedVideoPlayerViewModel`, eliminating the current architectural disconnect and establishing a proper unidirectional data flow.

### **2. Background**

The current implementation fails to display a video for two reasons. First, the `UnifiedVideoPlayerViewModel.loadVideo()` method is a non-functional stub that only logs a warning. Second, a critical architectural flaw exists where `PreTrimContainerView` and its child, `PreTrimView`, each create their own separate instances of `UnifiedVideoPlayerViewModel`, breaking the state flow. The user sees the empty player from the child view's instance, which is never loaded. This spec corrects both issues.

### **Part 1: Implement Video Loading in `UnifiedVideoPlayerViewModel`**

This change gives the ViewModel the ability to load a video asset into its player, fulfilling the new responsibility given to it in the `PreTrimContainerView`.

**File to Modify**: `UnifiedVideoPlayerViewModel.swift`

**Precise Instructions**:

1.  Navigate to the `loadVideo(from source: VideoSource, quarterTurns: Int)` method.

2.  Remove the existing `logger.warning` and the "not supported" comment.

3.  Replace the method body with the following implementation, which uses the `VideoLoadingService` to asynchronously load the asset and configure the existing player:

    ```swift
    // REPLACE the existing loadVideo method with this implementation
    public func loadVideo(from source: VideoSource, quarterTurns: Int) async throws {
        guard case .photos(let identifier) = source else {
            let errorMessage = "Unsupported video source type."
            self.state = .error(message: errorMessage)
            throw NSError(domain: "UnifiedVideoPlayerViewModel", code: -1, userInfo: [NSLocalizedDescriptionKey: errorMessage])
        }

        guard let phAsset = PHAsset.fetchAssets(withLocalIdentifiers: [identifier], options: nil).firstObject else {
            let errorMessage = "Could not find PHAsset with identifier: \(identifier)."
            self.state = .error(message: errorMessage)
            throw NSError(domain: "UnifiedVideoPlayerViewModel", code: -2, userInfo: [NSLocalizedDescriptionKey: errorMessage])
        }

        let loadingService = LiveVideoLoadingService() // As per 2. plan.md, this is the main loading service
        let progressStream = loadingService.loadPHAssetWithProgress(phAsset)

        do {
            for try await event in progressStream {
                await MainActor.run {
                    switch event {
                    case .progress(let fraction, let status):
                        self.state = .loading(progress: fraction, etaSeconds: nil, status: status)
                    case .success(let player, let asset):
                        // We have a new, fully prepared player. Replace the old one.
                        if let existingPlayer = self.avPlayer {
                            existingPlayer.replaceCurrentItem(with: player.currentItem)
                            self.playerItem = player.currentItem
                            self.state = .ready(player: existingPlayer)
                            videoHealthMonitor.startMonitoring(asset: asset)
                        }
                    }
                }
            }
        } catch {
            let errorMessage = "Failed to load video asset: \(error.localizedDescription)"
            self.state = .error(message: errorMessage)
            throw error
        }
    }
    ```

### **Part 2: Refactor View Hierarchy for a Single Source of Truth**

This architectural change ensures that `PreTrimContainerView` owns the player state and passes it down to `PreTrimView`, eliminating the "Two ViewModels" problem.

**File 1 to Modify**: `PreTrimView.swift`

**Precise Instructions**:

1.  Change the `playerViewModel` property declaration from a state-creating `@StateObject` to a state-receiving `@ObservedObject`.

    ```swift
    // FROM:
    @StateObject private var playerViewModel: UnifiedVideoPlayerViewModel

    // TO:
    @ObservedObject private var playerViewModel: UnifiedVideoPlayerViewModel
    ```

2.  Update the `init` method to accept the `UnifiedVideoPlayerViewModel` from its parent. Remove all logic that creates a new player or view model.

    ```swift
    // REPLACE the entire existing init method with this
    init(viewModel: AddMoveViewModel, playerViewModel: UnifiedVideoPlayerViewModel, asset: AVAsset, photosIdentifier: String?, rotationQuarterTurns: Int, selectedTab: Binding<TabSelection>) {
        self.viewModel = viewModel
        self.playerViewModel = playerViewModel // Assign the received ViewModel
        self.asset = asset
        self.photosIdentifier = photosIdentifier
        self.rotationQuarterTurns = rotationQuarterTurns
        self._selectedTab = selectedTab
    }
    ```

**File 2 to Modify**: `PreTrimContainerView.swift`

**Precise Instructions**:

1.  Navigate to the `body` property where `PreTrimView` is rendered.

2.  Modify the call to the `PreTrimView` initializer to pass the container's `playerViewModel` instance directly.

    ```swift
    // REPLACE the existing PreTrimView instantiation with this
    PreTrimView(
        viewModel: AddMoveViewModel.create(viewContext: PersistenceController.shared.container.viewContext),
        playerViewModel: self.playerViewModel, // Pass the container's ViewModel down
        asset: playerViewModel.playerItem?.asset ?? AVURLAsset(url: URL(fileURLWithPath: "")), // Fallback remains for safety
        photosIdentifier: phAsset.localIdentifier,
        rotationQuarterTurns: rotationQuarterTurns,
        selectedTab: .constant(.add)
    )
    ```
