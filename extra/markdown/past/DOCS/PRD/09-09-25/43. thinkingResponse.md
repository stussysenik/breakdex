Short answer: Make handle movement UI-local and transient, then coalesce changes to the ViewModel and AVPlayer into a single “chasing seek” loop at display rate, with implicit animations disabled during drag and a consistent gesture coordinateSpace, which eliminates double-render jitter while keeping the preview precise and responsive [1][2][3][4].

## Why jitter happens
- Continuous drag updates that write into observable ViewModel state cause full view re-renders while the same drag simultaneously drives AVPlayer seeks, so frames get canceled and redrawn, creating stutter and “double” rendering artifacts [1][5].  
- Apple recommends not issuing seeks in rapid succession because each new seek cancels the prior, producing lots of seeking and little showing; instead use a single “chasing” seek with a completion handler to serialize updates during scrubbing [2][6].  
- Gesture coordinate spaces and animation interplay can also add jitter; conflicting animation/gesture updates and mismatched coordinateSpace can manifest as jumps or stutter during drag [4][7].  

## Fix the drag pipeline
- Keep handle position in a transient @GestureState inside HybridPreciseTrimmerView and render directly from it, only proposing changes to the ViewModel at a controlled rate rather than on every onChanged tick [1][8].  
- Use a consistent gesture coordinateSpace (.local or .global) to avoid geometry recomputation loops; explicitly setting one resolved similar stutter/looping issues for others [4][8].  
- Disable implicit animations for per-frame drag moves and only animate onEnded (e.g., via Transaction or withAnimation(nil) during drag), preventing animation engines from fighting gesture updates [7][5].  

## Smooth, linked preview
- Implement Apple’s “chasing seek” pattern: pause during scrubbing, track a chaseTime, issue at most one seek at a time with a completion handler, and if the desired time changed during the seek, immediately chase the latest time in the handler [2][3].  
- Coalesce preview seeks to display rate using a CADisplayLink or similar scheduler that reads the latest proposed time and triggers the serialized seek logic, avoiding a flood of seeks from high-frequency drag events [9][2].  
- Use zero or very small tolerances for scrubbing frame-accuracy, but keep to the serialized pattern so seeks are smooth and not canceled mid-flight [3][2].

```swift
// HybridPreciseTrimmerView: keep drag local and transient
struct HandleView: View {
  @GestureState private var dragX: CGFloat = 0
  @ObservedObject var vm: TrimmerViewModel

  var body: some View {
    Circle()
      .offset(x: dragX) // UI reads transient state
      .gesture(
        DragGesture(minimumDistance: 0, coordinateSpace: .local) // pick one space and stick to it
          .updating($dragX) { value, state, _ in
            // Disable implicit animation during drag in a transaction, or ensure none is applied to this offset
            state = value.translation.width
          }
          .onChanged { value in
            let proposed = vm.xToTime(value.location.x) // map to time
            vm.proposeTimeForActiveHandle(proposed) // coalesced path, not direct seek
          }
          .onEnded { value in
            let final = vm.xToTime(value.location.x)
            vm.commitHandle(final) // optional finalize/animate
            vm.requestSeek(final)  // single final seek if needed
          }
      )
  }
}
```
- The .updating @GestureState keeps handle motion smooth without publishing view-wide changes, while .onChanged proposes changes to the VM at a controlled cadence rather than every event [8][10].  

```swift
// ViewModel: coalesce proposals and serialize seeks (Apple QA1820 pattern)
final class TrimmerViewModel: ObservableObject {
  @Published var startTime: CMTime = .zero
  @Published var endTime: CMTime = .zero

  // Scrub state
  private var displayLink: CADisplayLink?
  private var pendingPreviewTime: CMTime?
  private var isSeekInProgress = false
  private var chaseTime: CMTime = .zero
  private let player: AVPlayer

  func startCoalescing() {
    guard displayLink == nil else { return }
    displayLink = CADisplayLink(target: self, selector: #selector(tick))
    displayLink?.add(to: .main, forMode: .common)
  }

  func stopCoalescing() {
    displayLink?.invalidate()
    displayLink = nil
  }

  func proposeTimeForActiveHandle(_ t: CMTime) {
    pendingPreviewTime = t  // latest wins
  }

  @objc private func tick() {
    guard let t = pendingPreviewTime else { return }
    pendingPreviewTime = nil
    stopPlayingAndSeekSmoothly(to: t) // serialized “chasing” seek
  }

  private func stopPlayingAndSeekSmoothly(to newTime: CMTime) {
    player.pause()
    if newTime != chaseTime {
      chaseTime = newTime
      if !isSeekInProgress {
        trySeekToChaseTime()
      }
    }
  }

  private func trySeekToChaseTime() {
    // ensure playerItem status is ready; otherwise wait
    actuallySeekToTime()
  }

  private func actuallySeekToTime() {
    isSeekInProgress = true
    let seekTimeInProgress = chaseTime
    player.seek(to: seekTimeInProgress,
                toleranceBefore: .zero,
                toleranceAfter: .zero) { [weak self] _ in
      guard let self else { return }
      if seekTimeInProgress == self.chaseTime {
        self.isSeekInProgress = false
      } else {
        self.trySeekToChaseTime()
      }
    }
  }

  func requestSeek(_ t: CMTime) {
    pendingPreviewTime = t
  }
}
```
- The pattern above is a direct application of Apple’s “chasing” seek guidance for smooth scrubbing, with zero tolerances and a single in-flight seek at a time, driven by a display-link coalescer so drag noise never floods the player [2][3].
