1.  **The Trigger:** The user taps "Continue" in `FeatureRichTrimmerView`, which calls `unifiedState.proceedToNextState()`.

2.  **The Flawed Order:**

#### ✅ **Task 1: Correct the Order of Operations (The Main Bottleneck)**

This is the single most important change. We must ensure cleanup completes **before** the state transition is announced to SwiftUI.

  * **File:** `AddMoveUnifiedState.swift`
  * **Action 1.1:** Modify `proceedToNextState()`. Move the `cleanupTrimmerViewModel()` call here so it executes *before* transitioning.
      * **From**:
        ```swift
        case .trimming:
            await transitionTo(.naming)
        ```
      * **To:**
        ```swift
        case .trimming:
            // 🧠 FIRST: Fully clean up the resources from the state we are LEAVING.
            diagnosticLogger.logInfo("🔄 Starting trimmer cleanup before state transition", metadata: [
                "current_flow_state": "\(flowState)",
                "trimmer_vm_exists": "\(trimmerViewModel != nil)",
                "transition_target": "naming"
            ])
            await cleanupTrimmerViewModel()
            diagnosticLogger.logInfo("✅ Trimmer cleanup completed, proceeding to state transition", metadata: [
                "cleanup_successful": "true",
                "trimmer_vm_after_cleanup": "\(trimmerViewModel == nil)"
            ])
            
            // 🚀 THEN: Transition to the new state on a clean slate.
            await transitionTo(.naming)
        ```
  * **Action 1.2:** Modify `transitionTo(_:)`. Remove the now-redundant and incorrectly placed cleanup call from the `.naming` case.
      * **From**:
        ```swift
        case .naming:
            playerState = .paused
            isTrimmingActive = false
            currentPlayerViewModel?.pauseForTrimming()
            await cleanupTrimmerViewModel() // This is the race condition
            // ...
        ```
      * **To:**
        ```swift
        case .naming:
            playerState = .paused
            isTrimmingActive = false
            currentPlayerViewModel?.pauseForTrimming()
            // Trimmer cleanup has now been completed BEFORE this transition began.
            diagnosticLogger.logInfo("🔄 Transitioned to naming state with sequential cleanup", metadata: [
                "move_name_length": "\(moveName.count)",
                "trimmer_vm_cleaned": "true",
                "player_state": "\(playerState)",
                "race_condition_prevention": "sequential_cleanup_applied"
            ])
        ```
  * **Rationale:** This enforces a strict, robust order. Cleanup of the `.trimming` state finishes completely. Then, and only then, does `flowState` change to `.naming`. SwiftUI now has a clean, predictable state change to handle, which will resolve the UI freeze.
