## **Spec-Kit: Correcting Video Transform Logic**

### **1. Objective**

To implement the definitive fix for the `NameMoveView` preview by correcting a fundamental error in the video transformation logic. This will ensure that trimmed and rotated videos become ready for playback quickly and reliably, resolving the indefinite hang.

### **2. Diagnosis & Root Cause**

The application hangs at `NAME_MOVE_VIEW: Waiting for composed player item to become ready...` because the `VideoTransformBuilder` is producing an invalid video composition. While our previous fix for `renderSize` was correct, the final transformation matrix is being assembled in the wrong order.

The current implementation calculates the final transform as `Translation * UserRotation * SourceRotation`. In matrix math, this means the source rotation is applied last. The correct sequence is to first orient the video with its source transform, then apply the user's rotation, and finally translate it into the new, correctly-sized frame.

**Analogy**: The current code is like moving a painting one foot to the right on a table, then rotating it 90 degrees around the corner of the table. The painting ends up off the table entirely. The correct way is to rotate the painting first, then move it into its final position on the wall.

Because the video content is effectively rendered outside the visible frame, `AVFoundation` creates a composition that isn't technically invalid (it doesn't throw an error), but it contains no playable media, so it never reaches the `.readyToPlay` state.

### **3. The Solution: Simple, Reliable, and Performant**

The solution is to correct the order of matrix concatenation. This is a simple, one-line fix that addresses the root mathematical error. It is highly performant as it doesn't change the amount of computation, only its correctness. No complex fallbacks or increased timeouts are necessary because the generated video will now be valid.

### **4. Implementation Details**

**File to Modify**: `VideoTransformBuilder.swift`

**Target Method**: `build(asset:trimRange:quarterTurns:)`

**Specific Line to Change**: Locate the line where `finalTransform` is calculated.

#### **Before (Incorrect):**

```swift
// VideoTransformBuilder.swift, line 90
let finalTransform = translation.concatenating(Ruser).concatenating(Rsrc)
```

#### **After (Correct):**

```swift
// VideoTransformBuilder.swift, line 90
// The correct order: apply source transform, then user rotation, then translation.
let finalTransform = Rsrc.concatenating(Ruser).concatenating(translation)
```
