  logger.info("🎬 NAME_MOVE_VIEW: Checking composed player item readiness...")
  try await Task.sleep(nanoseconds: 200_000_000) // 0.2 second wait for composition

  if composedPlayerItem.status != .readyToPlay {
      logger.warning("🎬 NAME_MOVE_VIEW: Composed player item not ready (status: 
  \(composedPlayerItem.status.rawValue)), continuing anyway...")
  }

  doesn't actually wait for readiness:
  public func waitForReady() async throws {
      // For simplicity, we'll just return immediately since the player should be 
  ready
      // In a more complex implementation, you might want to verify player status 
  here
      return
  }

  The Fix:

  NameMoveView needs to properly wait for the composed player item to be ready
  before creating the UnifiedVideoPlayerViewModel. The current approach of:
  1. Creating composed player item
  2. Waiting 0.2 seconds
  3. Continuing even if not ready
  4. Creating UnifiedVideoPlayerViewModel
  5. Calling waitForReady() (which is a no-op)

  Should be:
  1. Creating composed player item
  2. Actually waiting for it to be ready with proper timeout handling
  3. Only then creating UnifiedVideoPlayerViewModel
