## Diagnosis: The Root Cause is a Coordinate Space Conflict

The logs show the builder is correctly calculating a new `renderSize` and applying transforms in the right order. However, the app still hangs.

The root cause is a conflict between **two different coordinate systems**:

1.  The video track's own `preferredTransform` (`Rsrc`), which correctly orients the video from its raw state.
2.  Our manually calculated `rotation` (`Ruser`) and `translation` (`T`) matrices.

Our code manually calculates a rotation and translation based on the video's `naturalSize`. This logic is fundamentally flawed because it **ignores the video's pre-existing orientation**. We are fighting the framework by re-implementing logic that `AVFoundation` is designed to handle for us. This conflict results in a mathematically incoherent final transform, producing a composition that never becomes ready.

## The Solution: Work *with* the Framework, Not Against It

The solution is to stop manually calculating complex transforms and instead leverage `AVFoundation`'s powerful composition tools. This will result in code that is simpler, more reliable, and far more maintainable.

The new strategy is:

1.  Let `AVFoundation` create a baseline valid composition that respects the video's original orientation.
2.  Create a *simple* rotation transform for only the user's desired rotation.
3.  Apply this simple rotation on top of the transforms that `AVFoundation` has already prepared.

## Spec-Kit: Final Video Composition Fix

### **1. Objective**

To refactor `VideoTransformBuilder` to use a framework-native approach for video composition. This will resolve the hanging issue by producing a valid `AVPlayerItem` that correctly combines the video's source orientation with the user's desired rotation and trim settings.

### **2. Implementation Details**

**File to Modify**: `VideoTransformBuilder.swift`

**Target Method**: `build(asset:trimRange:quarterTurns:)`

**Instructions**: Replace the entire body of the `build` method with the following simpler, more correct implementation. This new version delegates the complex calculations to `AVFoundation`.

```swift
// In VideoTransformBuilder.swift

static func build(asset: AVAsset, trimRange: CMTimeRange? = nil, quarterTurns: Int) async throws -> (composition: AVMutableComposition, videoComposition: AVMutableVideoComposition) {
    let composition = AVMutableComposition()

    // 1. Set the time range for the composition.
    let timeRange: CMTimeRange
    if let trimRange = trimRange {
        timeRange = trimRange
    } else {
        let duration = try await asset.load(.duration)
        timeRange = CMTimeRange(start: .zero, duration: duration)
    }
    try await composition.insertTimeRange(timeRange, of: asset, at: .zero)

    // 2. --- THE CORE FIX ---
    // Let AVFoundation create a video composition that correctly handles the asset's
    // initial orientation, render size, and instructions. This is the key.
    let videoComposition = AVMutableVideoComposition(propertiesOf: composition)
    
    // 3. Create a SIMPLE transform for only the user's desired rotation.
    let userRotation = CGAffineTransform(rotationAngle: .pi / 2 * CGFloat(quarterTurns))

    // 4. Modify the instructions generated by AVFoundation.
    for instruction in videoComposition.instructions {
        guard let layerInstruction = instruction as? AVMutableVideoCompositionInstruction,
              let assetTrack = composition.tracks(withMediaType: .video).first else { continue }
        
        let originalTransform = layerInstruction.transform(for: assetTrack, at: .zero)
        
        // 5. Apply our user rotation ON TOP of the original, correct transform.
        layerInstruction.setTransform(originalTransform.concatenating(userRotation), for: assetTrack)
    }

    print("✅ VideoTransformBuilder completed with framework-native composition.")
    return (composition, videoComposition)
}
```

This implementation is superior because:

  - **It's Simpler**: It removes all manual `renderSize`, `rotation`, and `translation` calculations.
  - **It's Correct**: It leverages `AVMutableVideoComposition(propertiesOf:)`, the official `AVFoundation` way to build a valid composition that respects all source metadata.
  - **It's Robust**: It will correctly handle any source video, regardless of its `preferredTransform`, because we are no longer making incorrect assumptions about its coordinate space.
