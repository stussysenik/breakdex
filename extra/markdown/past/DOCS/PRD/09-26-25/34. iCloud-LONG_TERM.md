### **Chain-of-Thought Analysis (First Principles)**

1.  [cite\_start]**The Problem (A Broken Morphism):** The current system uses `PHAsset.localIdentifier` to link a `CoreDataMoveState` object to a `PHAssetState` object. [cite: 49, 61] [cite\_start]As documented, `localIdentifier` is not stable across devices or iCloud restores, making this link fragile. [cite: 244, 247] [cite\_start]This is a "broken morphism" because it fails to reliably preserve the relationship between the two data stores. [cite: 248]

2.  **The Goal (A Stable, Composed Morphism):** The objective is to create a new, reliable persistence morphism. This isn't a single function but a *composition* of several smaller, well-defined operations:

      * First, an asset is created in the Photos library (`FinalAsset` → `PHAssetState`).
      * [cite\_start]Next, its local identifier is mapped to a stable cloud identifier (`PHAssetState` → `CloudIdentifier`). [cite: 257]
      * [cite\_start]Finally, the string representation of this cloud identifier is persisted alongside the move's name (`CloudIdentifier` x `String` → `CoreDataMoveState`). [cite: 258]

3.  **Implementation Strategy:** This composed morphism will be implemented within the `AddMoveSaveCoordinator`, which is correctly decoupled from the `AddMoveUnifiedState` view state. The `saveMove()` function in `AddMoveUnifiedState` will remain the trigger, but the complex persistence logic will reside in the coordinator, ensuring a clean separation of concerns.

#### **1. Saving the Move with `PHCloudIdentifier`**

The logic belongs in your `AddMoveSaveCoordinator`. The `saveMove` function in `AddMoveUnifiedState.swift` correctly calls this coordinator, so we will implement the coordinator's method.

**`GrepTool(pattern="func saveMove", path="AddMoveUnifiedState.swift")`**

The existing `saveMove` function in `AddMoveUnifiedState` is the correct entry point. It delegates the work, and no changes are needed there. The implementation below is for the `AddMoveSaveCoordinator`.

```swift
// In: AddMoveSaveCoordinator.swift (or equivalent service layer file)

import Foundation
import CoreData
import Photos
import OSLog

// A potential structure for your save coordinator
class AddMoveSaveCoordinator {
    private let context: NSManagedObjectContext
    private let diagnosticLogger = DiagnosticLoggingHelper(category: "AddMoveSaveCoordinator")

    init(context: NSManagedObjectContext) {
        self.context = context
    }

    /// Saves a new move, creating the video asset in Photos and the metadata in CoreData.
    /// This implementation uses PHCloudIdentifier for a stable, cross-device link.
    func saveMove(
        name: String,
        asset: AVAsset,
        photosIdentifier: String, // This is the localIdentifier from the initial PHAsset
        trimStartTime: Double,
        trimEndTime: Double,
        rotationQuarterTurns: Int
    ) async throws -> (move: Move, photosIdentifier: String) {
        
        diagnosticLogger.startTiming("full_save_operation")
        
        // --- Step 1: Export the trimmed and rotated video to a temporary file ---
        let timeRange = CMTimeRange(
            start: CMTime(seconds: trimStartTime, preferredTimescale: 600),
            end: CMTime(seconds: trimEndTime, preferredTimescale: 600)
        )
        let outputURL = try await exportVideo(asset: asset, trimRange: timeRange, rotation: rotationQuarterTurns)
        diagnosticLogger.logInfo("✅ Video successfully exported to temporary URL", metadata: ["url": outputURL.path])
        
        // --- Step 2: Save the temporary video file to the Photos library ---
        let assetPlaceholder = try await saveVideoToPhotos(from: outputURL)
        let newLocalIdentifier = assetPlaceholder.localIdentifier
        diagnosticLogger.logInfo("✅ Video saved to Photos, received new local identifier", metadata: ["localIdentifier": newLocalIdentifier])
        
        // --- Step 3: Add the new asset to the "BreakDex" album ---
        try await addAssetToBreakDexAlbum(placeholder: assetPlaceholder)
        diagnosticLogger.logInfo("✅ Asset added to 'BreakDex' album successfully.")
        
        // --- Step 4: Convert the new local identifier to a stable PHCloudIdentifier ---
        diagnosticLogger.logInfo("🔄 Converting local identifier to stable cloud identifier...")
        let cloudIdentifier = try await getCloudIdentifier(for: newLocalIdentifier)
        diagnosticLogger.logInfo("✅ Successfully retrieved stable cloud identifier", metadata: ["cloudIdentifier": cloudIdentifier.stringValue])

        // --- Step 5: Persist the Move entity to CoreData with the cloud identifier ---
        // This is an @MainActor function to ensure it runs on the correct context thread.
        let savedMove = try await saveMoveToCoreData(name: name, cloudIdentifier: cloudIdentifier.stringValue)
        diagnosticLogger.logInfo("✅ Move entity persisted to CoreData successfully", metadata: [
            "moveName": savedMove.name ?? "N/A",
            "cloudIdentifier": savedMove.videoCloudIdentifier ?? "N/A"
        ])

        // Clean up the temporary file
        try? FileManager.default.removeItem(at: outputURL)

        diagnosticLogger.stopTiming("full_save_operation")
        return (move: savedMove, photosIdentifier: newLocalIdentifier)
    }

    // MARK: - Private Helper Methods

    private func getCloudIdentifier(for localIdentifier: String) async throws -> PHCloudIdentifier {
        [cite_start]// This morphism converts a local identifier to a stable cloud identifier. [cite: 257]
        let mappings = try await PHPhotoLibrary.shared().cloudIdentifierMappings(forLocalIdentifiers: [localIdentifier])
        
        // Safely unwrap the result.
        guard let cloudIdentifierResult = mappings[localIdentifier] else {
            diagnosticLogger.logError("Cloud identifier mapping not found for local identifier.", metadata: ["localIdentifier": localIdentifier])
            throw AddMoveError.cloudIdentifierMappingFailed
        }
        
        // The result is a Result<PHCloudIdentifier, Error>, so we must try to get the value.
        return try cloudIdentifierResult.get()
    }
    
    @MainActor
    private func saveMoveToCoreData(name: String, cloudIdentifier: String) throws -> Move {
        [cite_start]// This morphism persists the final state to the local cache. [cite: 238, 473]
        let newMove = Move(context: context)
        newMove.name = name
        [cite_start]// REFINED: Store the stable cloud identifier string. [cite: 475]
        newMove.videoCloudIdentifier = cloudIdentifier
        
        try context.save()
        return newMove
    }

    // Other private helpers for exportVideo, saveVideoToPhotos, addAssetToBreakDexAlbum...
    // These would contain the logic using VideoTransformBuilder and AlbumManager.
}
```

#### **2. Retrieving the Move using `PHCloudIdentifier`**

After saving, you need to retrieve the `PHAsset` on any device using the stored `videoCloudIdentifier`. This logic should be placed in the repository or view model that fetches a `Move` for display.

```swift
// In: MoveRepository.swift or MoveDetailViewModel.swift

import Foundation
import Photos
import CoreData

class MoveRepository {
    private let diagnosticLogger = DiagnosticLoggingHelper(category: "MoveRepository")

    /// Fetches a PHAsset corresponding to a CoreData Move entity using the stable cloud identifier.
    [cite_start]/// This function implements the reverse morphism: from CoreData cache back to the PhotoKit source of truth. [cite: 259]
    func fetchAsset(for move: Move) async throws -> PHAsset? {
        diagnosticLogger.startTiming("fetch_asset_from_cloud_id")
        
        // --- Step 1: Get the stored cloud identifier string from the Move entity ---
        guard let cloudIdentifierString = move.videoCloudIdentifier else {
            diagnosticLogger.logError("Move entity is missing a cloud identifier.", metadata: ["moveName": move.name ?? "N/A"])
            throw FetchError.missingCloudIdentifier
        }
        diagnosticLogger.logInfo("🔍 Starting fetch for asset with cloud identifier string", metadata: ["cloudIdentifierString": cloudIdentifierString])

        // --- Step 2: Initialize a PHCloudIdentifier object from the string ---
        let cloudIdentifier = PHCloudIdentifier(stringValue: cloudIdentifierString)
        diagnosticLogger.logInfo("✅ Created PHCloudIdentifier object from string.")

        // --- Step 3: Convert the cloud identifier back to the *current device's* local identifier ---
        [cite_start]// This is the critical step for cross-device compatibility. [cite: 262]
        let localIdentifierMappings = try await PHPhotoLibrary.shared().localIdentifierMappings(for: [cloudIdentifier])
        
        guard let localIdentifierResult = localIdentifierMappings[cloudIdentifier] else {
            diagnosticLogger.logError("Local identifier mapping not found for cloud identifier.", metadata: ["cloudIdentifierString": cloudIdentifierString])
            throw FetchError.localIdentifierMappingFailed
        }
        
        // The result is a Result<String, Error>, so we must try to get the value.
        let localIdentifier = try localIdentifierResult.get()
        diagnosticLogger.logInfo("✅ Converted cloud ID to current device's local ID", metadata: ["localIdentifier": localIdentifier])

        // --- Step 4: Fetch the PHAsset using the retrieved local identifier ---
        let fetchOptions = PHFetchOptions()
        let assets = PHAsset.fetchAssets(withLocalIdentifiers: [localIdentifier], options: fetchOptions)
        
        guard let finalAsset = assets.firstObject else {
            // This could happen if the user deleted the video from their Photos library externally.
            diagnosticLogger.logWarning("⚠️ Asset not found for local identifier. It may have been deleted externally.", metadata: ["localIdentifier": localIdentifier])
            return nil
        }

        diagnosticLogger.logInfo("✅ Successfully fetched PHAsset using stable identifier.", metadata: ["assetIdentifier": finalAsset.localIdentifier])
        diagnosticLogger.stopTiming("fetch_asset_from_cloud_id")
        return finalAsset
    }
    
    enum FetchError: Error, LocalizedError {
        case missingCloudIdentifier
        case localIdentifierMappingFailed
        
        var errorDescription: String? {
            switch self {
            case .missingCloudIdentifier: return "The saved move has no cloud identifier."
            case .localIdentifierMappingFailed: return "Could not find the video on this device. It may not be synced yet."
            }
        }
    }
}
```

### **Verification Plan**

To ensure the implementation is correct and robust, follow this verification checklist:

1.  **✅ Single-Device Test (Baseline):**

      * Save a new move. Verify the `videoCloudIdentifier` in CoreData is populated.
      * Restart the app and navigate to the move's detail view. Verify the video loads and plays correctly.

2.  **✅ Multi-Device Test (iCloud Sync):**

      * **Prerequisite:** Use two devices logged into the same iCloud account with iCloud Photo Library enabled.
      * On **Device A**, save a new move.
      * Wait for iCloud to sync. On **Device B**, open the app.
      * Verify the new move appears in the arsenal.
      * Navigate to its detail view. **The video must load and play correctly.** This confirms the `PHCloudIdentifier` link is working across devices.

3.  **✅ Edge Case: External Deletion:**

      * Save a new move.
      * Close the app. Open the **Photos app** and delete the newly saved video from the "BreakDex" album.
      * Re-open the BreakDex app and navigate to the move's detail view.
      * **Expected Behavior:** The app should not crash. The `fetchAsset` function should return `nil`, and the UI should gracefully handle this by showing a "Video Not Found" placeholder. (This verifies the error handling added in the repository).

4.  **✅ Edge Case: iCloud Photos Disabled:**

      * On a device with iCloud Photos disabled, save a move.
      * Verify it saves and retrieves correctly on that same device. The `cloudIdentifier` API should still provide a stable identifier for local use.
